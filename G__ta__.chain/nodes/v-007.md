# 代码核实结果（2026-08-17 全量读码 D:\unity\unityProjectLocation\windy）

## 文档声称 vs 代码 — 验证通过的

- 双 HG（前 0.6 后 0.2 带 -g 符号）✓；Perlin-Worley 四通道权重 (0.625,0.25,0.125,0) ✓；边缘侵蚀 (1-baseD)² ✓
- 64 步视线 march + 蓝噪声抖动 + T<0.01 早退 ✓；8 步向日光 ✓
- CPU 镜像透射调制 Directional Light ✓（64 步、中点法、km⁻¹ 单位换算有注释）
- 桥接层宏级可移除 ✓；云光照取大气 LUT ✓；fallback 生成链 ✓（蓝噪声诚实标注低差异序列）
- 无多散射 ✓（无 MultiScatterLUTGen）——water 移植版已超越原版，代码实锤

## 代码里发现的问题（文档未提/与文档不符）

1. **debugMode 是死参数**：C# 设 `_debugMode` 但 shader 无此变量无分支——"调试三板斧"在代码中不存在；`_densityPow` 同样声明未用
2. **向日光积分缺步长因子**：`t+=max(0,D(p))` 缺 `*st`，光学深度量纲错误——云层厚度变化不影响暗部，靠 _lightAbsorptionTowardSun 人为补偿
3. **CPU 太阳透射无地面遮蔽**：太阳低于地平线时 `h<0 break` → T≈1 → 日落后地面仍亮，与 GPU 天空地面阴影项不一致
4. **左右镜像同款根因潜伏**（t-023）：cloud/fog shader 均为手写全屏三角 vert 无 _BlitScaleBias，仅 target scale=1 时恰好正确——water 已修，windy 未修
5. 死代码：`_phaseParams.w` 未用；`CloudSkyAmbient` 定义但云 shader 从未调用
6. `DisableTempPreviewCameras` 每帧禁用所有 depth>Main 的相机——粗暴方案，未来加反射/水下相机会被误杀；Camera.main 为 null 时 NRE
7. 文档失真：InteractiveEditor 实为 295 行"包围盒摆放 Handle"非"调参"；性能表"每步最多 2 次 3D 采样"不实（D() 每步 4 纹理采样，向日光再 ×8）
8. LUT 仅 Start/SetConfig 生成，运行中改 config 不重生成（新旧参数混用）

## 代码级确认的优点

- 参数全部在场景组件上（非 renderer asset），ApplyParameters 单一出口全量 push——面板管线本身是通的（water 的"面板无效"是移植问题非原版问题）
- 生命周期规范：OnEnable/OnDisable/Cleanup/RegenerateAll、RT 释放、光源颜色还原
- 依赖倒置 + atmosphereEnabled 开关有 fallback；"Scene 视图 Blit 翻转 URP 方向标记"注释说明作者真踩过并理解了机制

## 关键反转叙事（最大资产，目前没用起来）

water 工程的大气 = windy 移植 + 持续演进（多散射 LUT、天空 cubemap 128²×6、空气透视雾、水下桥接）——**移植版已超越原版**。case 03 的叙事应从"我复现了什么"改为"它孵化出了什么"：windy 是起点，water 是进化终点。面试里这比单独讲 windy 有说服力得多。

## 短板（诚实清单）

1. 无多次散射：云内暗、天空差 10-20% 亮度（文档已诚实标注）
2. 无时序重投影/上采样：生产级体积云标配，64 步 + 全分辨率 = 学习版性能画像
3. 蓝噪声 fallback 是低差异序列：条带抑制能力弱于真蓝噪声
4. 参数面板有效性存疑：移植到 water 后出现"面板调节无效"根因分析（backup 报告），windy 原版面板是否端到端可用需按代码验证（遵循"信代码不信注释"）
5. 太阳光 CPU 镜像的维护成本：双实现一致性靠纪律不靠机制（无自动测试对齐）

## 提升建议（性价比排序）

1. **回植** water 的多散射 LUT + cubemap → 把"未实现"变成"自己后续演进"（代码现成，成本最低，叙事收益最大）
2. 补参数面板中文化（与水下面板同风格）→ TA-美术工具链故事三连（大气/水面/水下）
3. 时序重投影：做不动就准备好"为什么不做"的量化回答（帧率-鬼影权衡，用数据说话）
4. 面试防御：所有"为什么选 X"用选型对比表回答，禁止"业界标准所以我也用"（那是复现声明，不是决策论证）

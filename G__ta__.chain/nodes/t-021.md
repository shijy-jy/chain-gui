# 深度逻辑审查结论（3 处错误，全部代码级证据）

## 翻转 #1: 深度约定混用（致命）

- `sceneDepth = Linear01Depth(rawDepth)` → **[1=近, 0=远]**（reversed-Z 约定）
- `viewDepth = 眼距/far`（顶点传）→ **[0=近, 1=远]**（相反约定）
- 二者相减：`depthDiff = 1 - (D_scene + D_water)/far` ≈ 0.9 **恒大于 0**
- 后果：`clip(depthDiff)` 永不丢弃（"障碍物遮挡"分支是死代码）；水面永远盖住水前物体

## 翻转 #2: 岸边交叉泡沫恒为 0

- `smoothstep(0, _ProjectionParams.w(=1/far≈0.001), depthDiff≈0.9)` 恒输出 1 → `intersect = 1-1 = 0`
- 后果：深度交叉岸边泡沫从未生效（看到的岸沫全部来自 FFT 泡沫通道）

## 翻转 #3: 屏幕 UV 手工 y 翻转 + 深度采样

- 顶点 `screenUV.y = 1.0 - screenUV.y` 手工翻转，与 URP 深度纹理约定无保证
- 修复：片元内用 `pos.xy / _ScaledScreenParams.xy`（URP 规范屏幕 UV）

# 已实施（FFTOcean_Render.shader）

1. **深度块重写为米制**：`depthDiff = LinearEyeDepth(scene) - length(worldPos-cam)`；`clip` 在水上真正生效；`intersect` 用水深 < `_ShoreFoamRange`(3m) 判定——岸边泡沫首次真实生效
2. **水下视角**（几何判定，不依赖面朝向/法线翻转）：
   - `Cull Off` 双面渲染（水上背面被深度测试自然淘汰）
   - Snell 窗口：`cos(视线, +Y)` vs 临界角 48.6°
   - 窗口内：`refract(toSurface, (0,-1,0), 1.33)` 折射方向采样真实大气天空（虚拟观察点，规避水下观察点被地面截断积分的问题）
   - 窗口外：深水色
   - 水柱吸收：就地 Beer-Lambert（不依赖额外 renderer feature/pass）
3. 参数默认值：`_ShoreFoamRange=3m`、`_UnderwaterAbsorption=(0.30,0.08,0.03)/m`、`_UnderwaterFogColor=(0.02,0.15,0.20)`
4. 诊断：天空采样失败 → 窗口显示品红色

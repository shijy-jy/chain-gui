> 触发：UI 缺字；渲追字形；kSpp 显示

# 用户反馈（瑾瑜）

1. "渲/追" 在所有位置显示 "?"（染 正常）；用户已自行加 `rb.AddText("渲追")`
2. 面板 kSpp 显示 16000（实际 16），其余参数正常

# 问题 1 根因：图集容量在打包阶段耗尽，非范围声明缺失

- `GetGlyphRangesChineseSimplifiedCommon()` **实为全量 CJK 块 0x4E00-0x9FAF ≈ 2.1 万字**（非注释所称 2500）
- 22.5px 字号 + 2x 过采样下，字体图集在 2048×2048 打满后，**0x6E00 之后的字形被静默丢弃**
- 实测吻合：渲(0x6E32)/追(0x8FFD) 缺字，染(0x67D3) 正常
- **用户的 `AddText("渲追")` 是无效修复**：二字本就在全量块范围声明内，缺字发生在图集打包（packing）阶段而非范围声明阶段——AddText 不会改变打包结果
- 修复：字形范围改为 `Default(ASCII) + AddText(本 UI 实际用字显式清单)` → 约 60 字形 → 图集极小，全部字形必有
- 约定：新增/修改任何中文标签必须同步 `AddText("渲染控制启动停止回预览模式中光栅路径追踪参数统计")` 清单（代码注释已写明）

# 问题 2 根因：格式化而非数值错误

- kSpp 数值链路正确（tuneValue=16.0，范围 [1,32] 步长 1）
- 滑条格式统一 `%.3f` → 16 显示为 "16.000" → 窄滑条中小数点几乎不可见 → 被误读为 16000
- 修复：按步长选格式——step≥1 → `%.0f`；step≥0.1 → `%.1f`；否则 `%.3f`（diSamples/mcap/atrousPasses 等整数参数一并受益）

# 教训

1. ImGui 的 glyph-range 常量名有误导性：ChineseSimplifiedCommon 实际是全量块；"常用字集"的缩减要靠**显式 AddText 清单**，不是靠这个 API
2. 缺字分两个阶段排查：范围声明（build ranges）→ 图集打包（atlas packing）；AddText 只解决前者，图集满了后者仍会静默丢字形（无任何警告）
3. 整数参数永远不要用 %.3f——窄 UI 里 "16.000" 与 "16000" 视觉无法区分

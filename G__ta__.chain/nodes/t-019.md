> 触发：水面水下优化；天空反射微高光；水下透射雾

# 状态更新 3（水下看水上"被挡住"修复，两处确定性 bug）

- ✅ 双面渲染确认存在（Cull Off，用户版本），"被挡住"实为水下分支显示写死蓝色
- 🐛 bug1：`refract(toSurface, upN, 1.0/1.33)` — HLSL refract 的 eta = n入射/n透射；水→空气应为 **1.33**（写反导致折射方向朝下采样天空 → 黑 → 兜底蓝）
- 🐛 bug2：相机在水下时 `_WorldSpaceCameraPos.y < 0` → 观察点在地表之下 → 单散射积分被地面截断 ≈ 0 → 天空色黑 → 兜底蓝；改为水面附近虚拟观察点 `WorldToAtmosphere((cam.x, 0.5, cam.z))` 计算
- 修复：Snell 窗口内 = 折射方向真实大气天空；窗口外 = 深水色

# 状态更新 2（画面颠倒修复，2026-08-16 晚）

- 🔑 **根因**：全屏雾 shader 用手动 SV_VertexID 三角形顶点，未应用 Blitter 的 `_BlitScaleBias`（相机目标↔临时 RT 的 Y 朝向相反）→ 整幅画面上下颠倒（天空在下）。用户加的 `UNITY_UV_STARTS_AT_TOP` 翻转在 D3D11 恒为 0，不生效
- ✅ **修复**（对照 URP 14.0.12 包内源码 `core/Runtime/Utilities/Blit.hlsl` + 官方 `Shaders/Utils/Blit.shader` 模板）：改用 `#pragma vertex Vert`（Blit.hlsl 内置顶点，自动应用翻转校正）+ 正确 include 路径 + `input.texcoord`
- ✅ 同源潜在 bug 一并修复：AtmosphereFog.shader（同样手动三角形，挂到活跃管线时会同样颠倒）
- ⚠️ 用户自改的 FFTOcean_Render.shader（Cull Off + isUnderwater 分支 + SV_IsFrontFace 水下视角支持）**未触碰**，保留用户版本

# 水下优化（用户定义：相机下水时的水下效果）

- 水面透射（俯视水下物体）：水面后存在实际几何（sceneDepth < 0.9999）时，采样场景色做斜率折射 + Beer-Lambert 吸收（RGB 分通道），透射层 = 水下背景 + 水内散射
- 相机水下全屏雾（新文件）：
  - `FFTVerify/UnderwaterFog.shader`：向上看 = 水柱距离吸收（(水面Y-相机Y)/viewDir.y）+ 朝太阳辉光；向下看 = 实际距离雾
  - `FFTVerify/UnderwaterFogRendererFeature.cs`：camera.y < waterSurfaceY 才注入（Scene/Game 均生效）；材质留空自动创建；注入点 BeforeRenderingTransparents

# 用户操作

# 风险点（如实）

- 水面切 Transparent 队列：深度/岸边交叉逻辑依赖 ZWrite On（已保留）；水面对相机透明排序变化——需场景回归验证
- 水下雾在 BeforeRenderingTransparents：水面（透明）不受水下雾影响（从下往上看水面被背面剔除，无冲突）

> 触发：术语替换事故；40 节点 updated 被毁；正则事故

# 事故现象

用户反馈 chain-gui（挂载 G:\deepseek\alive_data）"节点数据全没了，只剩四个节点"。

# 根因（自我引入，替换脚本的正则陷阱）

术语替换脚本 bump frontmatter 时的 `updated` 行替换：

```powershell
$t = [regex]::Replace($t, '(updated:\s*)[^\r\n]+', "`$1$now")
```

替换串 = "$1" + 时间戳（以数字 2 开头）→ .NET 把 `$12` 解析为"组 12"（不存在）→ 输出**字面量 `$1`** → 40 个文件的 `updated:` 行变成：

```
$12026-08-19T14:35:25+08:00
```

→ 前端 YAML 解析失败 → 后端跳过这些节点 → 图谱只剩 4 个未包含"主人"（未被动过）的文件 = 用户看到的"四个节点"。数据从未删除。

# 修复

- 正则回调修复 40 个文件：`(?m)^\$1(\d{4}...)$` → `updated: <时间戳>`（用 MatchEvaluator 回调，彻底避开 $-替换串解析）
- 中途发现环境怪癖：`RegexOptions::Multiline` 参数重载在此 pwsh 环境失效（IsMatch 恒 False），改用内联 `(?m)` 标志
- 修复后 44/44 frontmatter 解析通过；revision 值（+1）与 主人→开发者 替换均无异常

# 教训（写入规范）

1. **.NET 正则替换串中 `$n` 后紧跟数字会被解析为两位组号**——替换串一律用 MatchEvaluator 回调，禁止拼接 `$1`+动态内容
2. **批量编辑后必须做 schema 校验**，不能只验证"搜索词已消失"（上次只查了 主人 残留，没查 frontmatter 完整性）
3. 该环境 RegexOptions 枚举重载不可靠 → 正则一律内联标志 `(?m)` 等
4. "节点消失"类问题先查数据再查渲染：文件在 = 解析/显示层问题

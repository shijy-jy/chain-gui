> 触发：waterrenderer 案例拆解；海洋渲染技术全景；面试案例

# 案例定位

把 waterrenderer.test（URP 14.0.12 海洋渲染系统）拆解成面试可讲的技术案例：重建"为什么这么做 → 难点 → 怎么解 → 结果"的完整决策链。

## 已确认的技术全景（来自工程文档）

- 方案 B：混合 Mesh + 体积 Ray Marching 水体系统（双路径：水上 Mesh 表面 + 水下体积）
- 波浪：JONSWAP 频谱（γ=3.3）→ Mitsuyasu cos-2s 方向扩展 → 3 组涌浪频域叠加 → IFFT（Cooley-Tukey + Stockham）→ 频域 Gerstner（Tessendorf 2001）
- 5 个八度（128²×4 + 256² 谱尾法线），Octave4 只生成法线
- 4 级 LOD（129²/65²/33²/17²），环形切割 + Morph + innerFade 接缝修复
- 水面 Shader：Schlick Fresnel、Cubemap 反射、透射 SSS、12 分量解析毛细波、事件涟漪、Jacobian 白沫、Beer-Lambert 吸收
- 水下 Shader：Newton-Raphson 修正水面求交 + Ray Marching、Snell/TIR、God Rays、焦散投影
- 天空：大气散射（Transmittance LUT + Sky Cubemap Compute）
- 版本线：V2.0 → V2.1 → V2.6 → V2.9 → V3.0 → V3.1 → V4 → V4.1 → R9

## 讲解叙事线设计（草稿）

1. 一句话定位 + 为什么要做
2. 方案选型：为什么是 FFT（对比 Gerstner 解析叠加、Voronoi 噪声），为什么是方案 B 双路径
3. 核心算法逐个拆：频谱 → IFFT → 位移/法线 → LOD → 水面着色 → 水下 Ray Marching
4. 迭代叙事：V2.9 内圈暗色根因、V3.1 法线五维优化、V4 光谱连续性重构（删 Voronoi/解析 Gerstner 转纯 FFT）、R9 JONSWAP 升级——每个版本讲一个"发现问题 → 定位根因 → 修复"闭环
5. 性能工程：性能预算表 + 优化措施（法线降频、自适应步长、LOD 八度裁剪）
6. 工程能力证据：文档体系、验证脚本（SkyComputeVerifier）、git 规范

# DCC 与工具链

**管什么**：数字内容创作工具（Blender / Maya / Substance / Houdini 等）的脚本化、批处理、导入导出约定，以及把 DCC 接进自动化与 AI 工作流的桥接层。

**边界**：引擎里的运行时逻辑与资源加载 → 「引擎与管线」；着色器本身的写法 → 「渲染与着色器」；与具体 DCC 无关的排错经验 → 「工程实践」。

## 已有子节点

- **工具 · Blender 自动化与材质节点**（`Blender自动化与材质节点`）——类型化工具 vs `run_code` 逃生舱的能力边界、三个真陷阱（RNA 身份不稳定 / workbench 预览不读节点树 / 替换 `obj.data` 静默丢材质）、以及"工具产出与手工等价"的验证（位图级 0.000）

- **方法 · 动画与骨骼管线（IK / 动力学 / MMD 重定向）**（`动画与骨骼管线`）——IK 约束挂哪根骨、pole 角实测扫描、脚掌锁定的静止朝向、头发弹簧的解析反解与两遍法、MMD 重定向的四条硬规则，以及"用测量而不是猜"的诊断法（IK 伸展比 / 与体型无关的对比量 / A-B 基准法）

- **工具 · 资产校验与模型体检**（`资产校验与模型体检`）——一键体检的六个部分（建模/材质/骨骼/比例/对称性/多视角渲染）、两个已修缺陷（参照系选错、工具有副作用）、以及"用四道检验否决一个看似合理的需求"的典范用法

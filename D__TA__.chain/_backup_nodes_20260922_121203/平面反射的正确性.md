# 平面反射：镜像相机的正确构造

## 做法

把场景对着反射平面再渲染一遍到一张 RT，然后在着色器里按屏幕坐标采样。核心是**镜像相机**：

$$M_{\text{reflect}}=\text{Scale}(1,-1,1) \text{ （在该平面的局部空间里）},\qquad V_{\text{mirror}}=V_{\text{main}}\cdot M_{\text{reflect}}$$

等价说法：把主相机的视图矩阵乘上一个"反射平面空间里的镜像矩阵"，再用它渲染一次。

## 陷阱一：用 LookRotation 拼镜像相机 → 手性翻转

一个自然的错法：取主相机的前向量与上向量，各自对平面做镜像，然后 `LookRotation(mirroredFwd, mirroredUp)` 重建旋转。**这会翻转坐标系手性**——镜像后的基向量构成左手系，导致：
- 三角形环绕方向（winding）反了 → 背面剔除把该看到的剔掉、把不该看到的留下；
- 表现是"倒影随视角错位旋转"这类看起来像数学算错、实际是拓扑性质错的现象。

**正解**：用严格的反射矩阵（保留镜像性质，不要重新正交化），并显式翻转剔除方向：`GL.invertCulling = true` 渲染镜像相机，或设置 `camera.cullingMask`/`CommandBuffer` 的相应状态。

## 陷阱二：镜像渲染期间的额外几何被一起采进 RT

镜像 pass 会把**场景里所有可见物**再画一遍，包括那些"只该出现在主视角"的辅助几何。真实事故：接地网格线被画进 RT，二次采样后水面出现**"错位假网格 + 地平线硬分界带"**。
**修法**：镜像渲染期间临时禁用该层（或把 LOD/材质通道做区分）。诊断方法：逐层关闭渲染（A/B）看症状何时消失。

## 陷阱三：近平面与精度

- 水面在反射相机里会挡住大部分场景 → 常用**斜切近平面**（oblique near-plane clipping，把近平面压到水面上）避免渲染水面以下的几何。
- 反射 RT 分辨率与主相机不一致时，屏幕空间采样要做正确的 UV 变换，否则倒影会整体错位。
- 精度：反射矩阵是"非刚体"变换，法线要用**逆转置**（见「图形数学基础」变形：反射时法线变换为 $M^{-T}$ 的特例），直接乘同一矩阵会得到错误的法线朝向。

## 代价与替代方案（面试必答的取舍）

| 方案 | 能反射什么 | 代价 |
|---|---|---|
| 平面反射（本项目） | 该平面上的一切（屏外、背后都行） | 场景渲染两遍（或按需 + 隔帧 + 降分辨率） |
| SSR 屏幕空间反射 | 只在屏幕内可见的东西 | 便宜，但出屏即丢、边缘拉伸 |
| Reflection Probe | 环境级别近似 | 最便宜，但位置/形状近似、动态物不准 |

工程手段：RT 分辨率档位 **512/1024/2048 + 隔帧更新**（`TA_show` 就是这么做的），远处/静态时降档。

## 可能被追问的三层

1. **原理层**：为什么镜像会翻转手性？为什么反射矩阵不能正交化（一旦正交化就丢了镜像语义）？法线为什么必须用逆转置？
2. **实现层**：`GL.invertCulling` 到底改了哪个状态（front-face winding 还是 cull mode）？斜切近平面矩阵怎么构造？RT 分辨率与主相机不一致时 UV 怎么算？
3. **边界层**：水面波动（不是平面）时平面反射还成立吗（近似：法线扰动 + 屏幕空间偏移）？反射里再出现反射怎么办（递归层数）？VR/双眼相机下这套怎么改？

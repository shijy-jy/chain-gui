# 自研边界与证据强度

**为什么单独建这个节点**：六个项目侦察下来，**每一个都有"自研 vs 参考/复刻/协作"的边界问题**。TA 面试的追问几乎必然落在"这块是你做的吗、为什么这么做"上——**主动划清边界是加分，被问穿是致命**。

## 证据强度三级（自定口径，面试时可以直接讲）

| 级别 | 标准 | 例子 |
|---|---|---|
| **强** | 可当场打开的可运行产物 / 源码行 / 实测数字 | 白炉 ±1%、`PSNR ≥ 50 dB` 判定链、`max_abs_diff = 0`、41 万顶点砍 36% |
| **中** | 有产物但缺独立验证（自述日志、单方数据） | SDF 的 `v-*` 静态核对、Engram 的 CHANGELOG 单测数 |
| **弱** | 只有说法、设想的产物、或未被引用的文件 | AI 生成天空盒（未在场景中引用）、Engram 的检索"效果好"（仅 1 条 recall 审计） |

## 三条硬规则

1. **不说"我写的"，只说"我做了什么 + 参考了什么 + 我改了什么"**——三段式表述在任何追问下都站得住。
2. **主动交代未完成与未量化**：windtest 云/大气未合成、SDF 9 个 task 待实机裁决、render_unified_oss 无性能数据、PT CPU 位级复现根因未闭环。面试官更信"知道自己边界的人"。
3. **每个主张都能指到证据**：讲稿里出现的每个数字与机制，必须能在「项目深挖」节点里找到 `文件:行` 或节点 id；指不到的就删掉或降级为"我记得是"。

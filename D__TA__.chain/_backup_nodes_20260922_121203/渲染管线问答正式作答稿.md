## 第一题　裁剪空间、透视除法与深度测试

### 问 1.1　图元裁剪为何在齐次裁剪空间中执行，而不在规范化设备坐标（NDC）中执行？

**答**：视锥体在齐次裁剪空间中由**六个线性半空间（即六个平面）**界定，因此判断顶点是否位于视锥之内，可归结为顶点与平面方程的**点积符号判断**；多边形边与平面的交点可由**线性插值**直接求得。跨近平面的三角形在该空间中能够被正确分割并生成新顶点，此即"补顶点"的机制所在。

反之，若先执行透视除法 $\div w$，当 $w \le 0$（顶点位于相机后方）时坐标将发生翻转或趋于无穷，跨近平面的三角形会被错误裁剪。故裁剪必须先于透视除法执行。

需注意：透视投影下 $w_{clip} = -z_{view}$，**各顶点的 $w$ 值并不相同**；仅正交投影满足 $w \equiv 1$。

### 问 1.2　深度在管线各阶段的线性性质如何？与深度精度问题有何关联？

**答**：观察空间的深度为线性；经透视投影后，**NDC 中的深度与 $z$ 呈非线性关系**（与 $1/z$ 线性相关），故近处精度高、远处精度低。**反向 Z**（reversed-Z，`UNITY_REVERSED_Z`）将近平面映射至 1、远平面映射至 0，使近处落在浮点数分布更密的区间，从而提升深度精度。若该约定写反，会出现深度判定或雾效在天空像素上的错误。

### 问 1.3　提前深度测试（early-Z）与延后深度测试（late-Z）有何差异？early-Z 成立的前提是什么？

**答**：**early-Z** 指硬件将深度测试提前至片元着色器执行之前，被判定为遮挡的片元不进入着色计算，因而节省的是**整个片元着色阶段的开销**（在前向渲染中即包含光照计算）。**late-Z** 发生于片元着色器执行之后，被遮挡片元已完成为着色，仅避免了写回。

early-Z 的成立前提为：片元着色器**不写入深度**、**不执行 `discard`**、且**未修改深度测试状态**。任一前提被破坏时，硬件将退回 late-Z 或禁用深度预测试。

补充工程手段：**depth pre-pass**（先以最小着色仅写入深度，再带深度测试重绘一遍）相当于手工实现 early-Z，常用于复杂场景。

### 问 1.4　延迟渲染管线为何与多重采样抗锯齿（MSAA）配合不佳？

**答**：延迟渲染需将几何与材质属性写入 G-Buffer，其属性数量显著多于普通颜色缓冲。MSAA 对每个像素维护多个采样点；若逐采样点存储全部 G-Buffer 属性，显存占用与带宽开销将成倍增长，并随场景复杂度上升而急剧恶化。

需明确：**G-Buffer 存储的是几何与材质属性**（基础色、法线、粗糙度、金属度、深度、运动矢量等）；光照、环境光遮蔽与阴影是在后续 pass 中**依据这些属性计算得出**，并非预先渲染进 G-Buffer。

因此延迟管线通常以 TAA 或自定义抗锯齿替代 MSAA，且透明物体需以前向方式补绘。

> **易错点提示**：本次演练出现的偏差为——误述"齐次裁剪空间中 $w$ 值保持一致"（该结论仅对正交投影成立）；误述 early-Z"主要用于延迟渲染"；以及对 G-Buffer 存储内容的表述倒置。

## 第二题　绘制调用开销、顶点着色器能力与 discard

### 问 2.1　一次绘制调用（draw call）在 CPU 侧的开销由哪些部分构成？

**答**：其开销主要来自**渲染状态的变化**与命令提交，而非顶点数据本身。具体构成包括：

1. 状态切换：着色器程序、渲染目标、混合、深度与模板状态；
2. 常量缓冲（UBO）的绑定与上传；
3. 资源绑定及必要的同步与屏障；
4. 命令写入命令缓冲；
5. 驱动侧的参数校验与批处理。

该结论解释了合批、实例化与 GPU 驱动式绘制（GPU-driven）之所以有效。同时需注意：在**软件光栅化**（无图形 API 管线，例如以 CUDA 逐像素光栅）中，"减少绘制调用"这一命题并不适用。

### 问 2.2　顶点着色器在能力上有哪些限制？

**答**：其限制包括：不能创建或销毁图元；不能访问同一图元内的其他顶点（无邻接信息）；不能获取片元阶段的插值结果；不能执行依赖邻域的操作。图元的创建与销毁属于**几何着色器**的能力范围，但几何着色器在移动端通常不被推荐（性能代价高，且与分块架构不契合）。

### 问 2.3　`discard`（片元丢弃）对渲染性能机制有何影响？

**答**：`discard` 使该片元的可见性无法在着色之前确定，因此造成两项后果：

1. **破坏 early-Z 的前提**，硬件退回 late-Z；
2. 在**分块延迟渲染（TBDR）**架构下**破坏隐藏面消除（HSR）**，强制进入"先着色、后测试"的流程，其代价可能超过其所节省的工作量。

**辨析**：背面剔除由**剔除模式（cull mode）**控制，与 `discard` 并非同一机制。`discard` 是片元着色器主动放弃该片元，典型用途为透明度测试（alpha test）。

> **易错点提示**：本次演练中，问 2.1 的作答停留在"提交了哪些数据"，未涉及状态切换等主要开销；问 2.3 的作答阐述了 `discard` 的用途，未回答其破坏的性能机制，并将背面剔除与 `discard` 混同。

## 第三题　延迟渲染的适用性、TBDR 与光栅化的前景

### 问 3.1　何时应选用延迟渲染？其代价是什么？

**答**：当场景**光源数量多且光照模型复杂**时，延迟渲染可将光照计算次数与物体数量解耦，因而具有优势。其代价包括：G-Buffer 带来的带宽与显存压力；透明物体需前向补绘；与 MSAA 配合不佳；材质模型受固定 G-Buffer 布局限制。

需注意：光源数量多并非选用延迟渲染的充分条件——前向渲染的增强方案（如 Forward+ 借助分块灯光列表）已显著缓解前向管线的多光源问题；工程实践中亦常见**混合方案**，即不透明物体走延迟、透明物体走前向。

### 问 3.2　请说明 TBDR 的基本原理与工程约束。

**答**：

**（1）基本原理**　TBDR（Tile-Based Deferred Rendering，分块延迟渲染）将屏幕划分为若干小块（tile，常见 16×16 或 32×32 像素）；同一 tile 的几何先被收集，随后在**片上高速内存（tile memory）**中完成着色与合并，最后统一写回主存。相较立即模式渲染（IMR）反复读写系统内存中的帧缓冲，该方式将多次主存往返压缩为一次写入，**显著降低带宽与功耗**——这是移动 GPU 采用分块架构的主要原因。

**（2）关键机制**　由于几何在着色之前已收集完毕，GPU 可在 tile 范围内先行确定每个像素的可见片元（**隐藏面消除，HSR**），被遮挡的片元不执行片元着色器。因此分块架构下的"提前深度测试"具有**结构性、近乎免费**的特性；但其成立依赖于"先收集、后着色"的次序。

**（3）主要约束**　`discard` 与在片元着色器中写深度会破坏 HSR；频繁切换渲染目标或反复 Blit 将触发 tile 的 **resolve（flush）**，是分块架构中代价最高的操作；多层透明混合与过多 MRT 会超出 tile 内存预算；依赖读回帧缓冲的实现会中断分块流程。相应地，移动端优化的重心在于**减少 pass 数与渲染目标切换**，而不仅是降低 overdraw。

**（4）概念辨析**　TBDR 与桌面端所称的延迟渲染（G-Buffer 延迟光照）**并非同一概念**：前者指先收集几何、将着色推迟至可见性确定之后，用以节省带宽；后者指先写入几何属性、再统一计算光照，用以解耦光照与物体数量。

### 问 3.3　光栅化是否会被光线追踪取代？

**答**：短期内不会。光栅化的优势不仅在于性能开销较低，更在于其**高度并行、局部性良好且行为可预测**。光线追踪的瓶颈在于加速结构遍历的相干性问题、降噪开销，以及功耗与芯片面积成本。当前工程实践为**混合渲染**：以光栅化负责主可见性判断，以光线追踪处理其难以精确表达的效应（精确阴影、反射与全局光照），并配合 ReSTIR、SVGF 等降噪方法。

> **易错点提示**：本次演练中，问 3.2 未作答；问 3.3 的作答方向正确，但未给出"短期不可取代"的具体依据，亦未提及混合渲染这一现实路径。

## 附录二　作答要点速记（复述用）

1. 裁剪在齐次空间：视锥是**六个线性半空间**；交点靠线性插值；先除 $w$ 会毁掉 $w\le0$ 的顶点。
2. $w$ 不恒定（透视下 $w=-z_{view}$）；深度在 NDC 非线性，故用反向 Z 提精度。
3. early-Z 省整段片元着色，前提是不写深度／不 discard／不改深度状态；否则退回 late-Z。
4. G-Buffer 存**属性**，光照/阴影是**后续 pass 算出来的**。
5. draw call 贵在**状态变化**，不在顶点数据。
6. `discard` 破坏的是 **early-Z 前提与 HSR**；背面剔除是 **cull mode**。
7. TBDR ＝ **分块＋tile 内存＋HSR**，怕 discard 与切 RT；与桌面延迟渲染**不是一回事**。
8. 光栅化短期不会被取代，现实路径是**混合渲染**。

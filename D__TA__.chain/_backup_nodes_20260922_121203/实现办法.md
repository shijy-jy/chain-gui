# 实现办法

**管什么**：跨项目复用的解题套路——面对"要更快 / 更真 / 更省事"时你实际用过的手段，以及每种手段的代价与适用边界。

**边界**：单个项目里一次性用到的细节 → 「项目深挖」的对应节点；原理本身 → 各基础 hub。本 hub 只收**在两个以上项目里复现过**、或明确知道"什么情况下该用"的办法。

**怎么来的**：从各项目「关键难题 → 实现办法」里提炼重复出现的部分——同一个套路在不同项目反复出现，就是你的方法论；只出现一次的，老实留在项目节点里。

## 已有子节点

- **实现办法 · 确定性验证优先**（`确定性验证优先`）——先用数字回答、肉眼只做定性；判据先于实现；口径要写清（位级 vs 统计级）；验证不得与被验证同源
- **实现办法 · 把重复劳动脚本化**（`脚本化重复劳动`）——一次性批处理 / 编辑器扩展 / 流水线三种形态，以及"工具要落在使用者动线上""生成器必须确定性"
- **实现办法 · 先量化再优化**（`先量化再优化`）——量化现象 → 量级估算定位 → 改一处用同一把尺子复验；含五个项目的真实归因案例
- **实现办法 · 用程序化生成代替手工资产**（`程序化生成`）——几何 / 表面 / 统计 / 采样四个层次的证据，以及代价与边界（可控性、确定性、成本转移、观感上限）

## 待建（等素材，不造空节点）

- **数据驱动**：把参数从代码搬进资产/配置，让美术与策划可调（`TA_show` 的美术调参面板是雏形）
- **跨会话与协作**：把结论写进图谱/文档而不是留在对话里（可复用「方案 · Engram 多工作区 MCP 接入」；`SDF` 的 Director + 模块拆分是为降低双会话冲突）
- **降级与平台差异**：移动端精度、特性开关、预算控制（目前六个项目都缺移动端素材，属短板）

## 每条怎么写

**问题类型 → 手段 → 代价与边界 → 在哪些项目用过（链接项目节点）→ 证据**。
只写"用了 X"没有价值，必须写清"X 换来什么、付出什么、什么时候不该用"。

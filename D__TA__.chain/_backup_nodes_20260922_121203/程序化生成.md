# 实现办法 · 用程序化生成代替手工资产

## 套路

**能用数学、噪声或频谱描述的东西，就不要手工做资产。** 判断标准不是"技术上能不能生成"，而是三条业务问题：
1. 这东西**会被改多少次**（改得越多，程序化越赚）；
2. 需要**几个变体**（一个 vs 一百个）；
3. 是否需要**确定性复现**（做基线、做回归就必须）。

## 四个层次（每层都有项目证据）

| 层次 | 做法 | 项目证据 |
|---|---|---|
| **几何** | 用参数生成网格与布局，而不是手摆 | `TA_show`：能量网格地面是**41 万顶点的程序化网格**；**40 根光柱共用单个 38,280 顶点 Mesh**，CPU 只推参数、世界位置由顶点着色器反算（6 组全局数组协议手工对齐）；`render_unified_oss`：`gen_bench_scenes.py` 纯标准库**确定性**生成 4 个基准场景，重生成为**字节一致** |
| **表面** | 用噪声 + 色带 + 坡度拼材质，不画贴图 | `SDF`：溶解用**对象空间 3D Perlin**（不建噪声贴图，跨棱不断裂）；Blender 工具链：一次调用建出 **13 节点 / 14 连线**的程序化石材（Noise→ColorRamp 分档 + Voronoi `DISTANCE_TO_EDGE` 做裂缝 + 双 Bump 串联） |
| **统计** | 用**频谱/分布**描述整体，而不是逐个体摆放 | `water`：FFT 统计波谱海面——真实海面是"无数随机正弦波的叠加"，用 JONSWAP 谱 + 方向扩散描述它，**一次 IFFT 出整片海**。这一层最值钱：程序化在这里不只是"省事"，而是**用统计描述换来了物理可信度**（手摆波形永远做不出正确的波数分布） |
| **采样** | 程序化生成采样序列/噪声纹理，去掉外部依赖 | `render_unified_oss`：自研 FFT 频谱整形生成 64×64 双通道**蓝噪声**（固定种子），消除外部贴图依赖；Blender 侧噪声虽有离线资产，但材质图本身是程序化的 |

## 代价与边界（必须主动说，否则听起来像在卖）

1. **可控性下降**：美术很难说"把这一块改一下"（对比：贴图可以直接画）。→ 应对是**暴露语义参数**（噪声尺度、阈值、色带偏移、方向权重）并做面板，而不是让美术改噪声实现。
2. **随机必须可复现**：固定种子、确定性生成；否则**基线不可比、回归没法做**（`gen_bench_scenes.py` 的"字节一致"就是为此）。
3. **成本转移而不是消失**：省掉了包体与手工时间，但**运行时 ALU/顶点量照付**（噪声八度数、41 万顶点的光栅化）。→ 必须配套 LOD/剔除（见「LOD 与剔除手段」）。
4. **观感的上限**：程序化擅长"自然、重复、大尺度"（海面、云雾、石材、格线），不擅长"设计过的具体形状"（角色、道具、logo）——**该手工的还是要手工**。

## 判断清单（面试可当场用）

- 会被改 >3 次？→ 程序化；
- 需要几十个变体？→ 程序化 + 参数化；
- 要做回归/基线？→ **必须**确定性程序化；
- 需要精确设计意图？→ 手工，程序化只做辅助（遮罩、过渡、分布）。

## 可能被追问的三层

1. **原理层**：Perlin/Worley/Simplex 的差别与适用？fbm 的 $1/f$ 衰减为什么自然？程序化噪声与频谱方法（FFT）在"合成分形"上的等价性？
2. **实现层**：怎么保证确定性（浮点、并行归约顺序、随机种子）？噪声 ALU 成本怎么估？程序化网格的顶点量怎么控（LOD/退化）？从"程序化"到"美术可调"的参数映射怎么设计？
3. **边界层**：程序化与手工混合的方案（程序化生成 + 手工雕刻叠加）？程序化资产怎么做版本兼容（参数改了旧资产怎么办）？什么信号说明"该退回手工了"（美术反复要求特例时）？

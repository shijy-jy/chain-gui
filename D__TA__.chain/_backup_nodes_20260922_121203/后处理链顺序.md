# 后处理链顺序：顺序即语义

## 核心命题

后处理**不是一串互不相干的效果，而是一条有顺序的链**——同一组算子换个顺序，结果不同，而且常常**物理上就是错的**。判断每一步该放哪，只问三个问题：

1. 这一步需要**线性 HDR 空间**吗？（需要 → 必须在色调映射之前）
2. 需要**深度/法线/运动矢量**吗？（需要 → 必须在这些缓冲还有效、且未被覆盖时）
3. 它是**显示域的观感修饰**吗？（是 → 放在色调映射之后）

## 推荐的链（自上而下是执行顺序）

| 阶段 | 内容 | 为什么在这 |
|---|---|---|
| 1. 几何 + 光照 | 输出 **HDR 线性**颜色 + 深度/法线 | 一切物理量都在线性空间 |
| 2. 依赖深度的屏幕空间效果 | SSAO、SSR、体积光/雾、屏幕空间阴影 | 需要深度且需要线性空间 |
| 3. **Bloom / 泛光** | 阈值提取 + 多级模糊 + 合成 | **必须能在色调映射前拿到 >1 的高光能量**——压过之后就提不出来了 |
| 4. **色调映射 + 曝光** | HDR → 显示域 | 之后进入"感知域"，不再做物理运算 |
| 5. 显示域修饰 | 锐化（CAS）、色差、颗粒、暗角、色彩分级 | 这些是"画在一张已成像的图上"的算子 |
| 6. UI / HUD | 界面合成 | UI 不该被前面的效果波及（除非刻意） |

## 顺序错的典型症状（面试可直接用）

| 错误 | 症状 | 根因 |
|---|---|---|
| Bloom 放在色调映射**之后** | 高光几乎不发光，Bloom 像"糊了一层灰" | 高光已被压到 1.0 附近，**阈值提不出能量** |
| 锐化放在色调映射**之前** | 过曝区出现振铃/黑边 | 在线性空间里 9.3 与 1.0 都是"白"，锐化会在压缩前放大差异 |
| 雾放在色调映射**之后** | 雾色不随曝光变化、与天空对不上 | 雾是**线性空间的光学量**（散射/吸收），不是显示域调色 |
| 屏幕空间效果在**覆盖了深度**之后做 | 效果消失或出现错位边缘 | 深度缓冲已被后续 pass 重写 |
| UI 被 Bloom/色调映射波及 | 文字发光、颜色不对 | UI 通常应在**最终显示域**合成 |

## 在你项目里的落点

- **`TA_show`**：全屏雾是 `AfterRenderingOpaques` 的 RendererFeature，且**雾色逐像素采样反射 RT** 来保持天地缝合——**它必须在线性空间、且在反射 RT 还有效时执行**。删掉 pass 内的行星积分后换成"烘焙 cubemap + 仰角驱动解析雾"，属于"用更便宜的近似替换链中一环"，但**位置没变**（这很关键：换实现 ≠ 换位置）。
- **`SDF`**：后处理件是 CAS 锐化（显示域）、热扭曲、地面光斑、烟（线性域）——**它们的类别不同，位置就该不同**。元素球那次事故（四层叠加峰值 ≈9.3 而 Bloom 阈值 1.0 → 全白过曝）本质是**"线性域能量"与"显示域阈值"没对齐**：修法是分层归因（贴图定形 / 色带定色 / HDR 只提最热处），而不是整体压曝光。
- **`render_unified_oss`**：显示链是一个**独立且会污染所有后端**的层——`packColor` 的硬钳制把 HDR 高光抹平（CPU 球内峰值 153 vs GPU 5.6），改成软拐点色调映射后，**所有模式的观感基线都得重建**。→ 教训：**改显示链 = 改全项目观感**，要当架构变更对待（`d-013`/`t-028`/`t-029`）。
- **`water`**：水下效果是独立 RendererFeature（`renderPassEvent = 450`，透明之后），用 Snell 窗做折射——**它需要场景颜色已合成**，位置天然在后段。

## 工程上怎么保证顺序不出错

1. **把顺序写进配置可视的地方**（URP 的 Renderer 资产里 Feature 列表顺序就是执行顺序）——顺序是**设计**，不是偶然。
2. **每个 Feature 显式声明输入**（`ConfigureInput(Depth|Color|...)`），不依赖"恰好有别的效果产生了深度"（见「URP RenderFeature 的插入点与依赖」）。
3. **给链做开关矩阵**：每个效果能单独开关（solo），才能验证"顺序改动带来的差异"——这也是「工程结构与协作」里 5 模块支持 solo 的同类思路。
4. **量化验证**：改顺序前后用同一相机位对比图（A/B），避免"感觉更通透了"。

## 可能被追问的三层

1. **原理层**：为什么 Bloom 必须在色调映射前（能量域 vs 感知域）？曝光应该在哪一步算（自动曝光需要统计整帧亮度，通常与色调映射同阶段）？线性空间混合与显示域混合的差别？
2. **实现层**：Bloom 的阈值与 knee 怎么定（HDR 阈值 vs 显示域阈值）？CAS 锐化为什么放在显示域（它是感知锐化，不是物理对比度）？怎么实现"效果 solo/开关矩阵"？深度缓冲在哪个 pass 之后就不能用了？
3. **边界层**：TAA/时域降噪插在链的哪里（为什么通常在色调映射前、且需要运动矢量）？HDR 显示（PQ/HLG）下这条链怎么改？移动端 TBDR 上"多一次全屏 pass"的真实代价是什么（tile 内存 flush）？

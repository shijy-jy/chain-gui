# 知识库索引

本库是 **Technical Artist（TA）** 方向的个人知识库：工作区 `D:\TA`，模式 `dev`（自由知识图谱，不套分析模式的目标/设计/任务/验证层级）。一个节点讲清一个知识点，靠 `parent` 表达归属，每个大主题一个 hub 根节点。

## 一级主题（hub）

| hub | 管什么 | 边界（不放这里） |
|---|---|---|
| 渲染与着色器 | 光照/材质模型、GPU 侧效果实现与调试 | 资产怎么生产 → DCC 与工具链；资源怎么加载 → 引擎与管线 |
| DCC 与工具链 | Blender/Maya/Substance 的脚本、导出、批处理，以及 DCC↔自动化/AI 的桥 | 引擎内运行时逻辑 → 引擎与管线 |
| 引擎与管线 | Unity（含团结）、Unreal 的渲染管线、资源与构建流程、性能预算与平台差异 | 逐行 shader 实现 → 渲染与着色器 |
| 图形数学基础 | 线代/几何/采样积分/色彩与光度学等复用型理论 | 只服务单一效果的推导 → 放那个效果自己的节点 |
| 工程实践 | 工具链排错、环境与版本陷阱、跨工程复用的流程与约定 | 有明确技术主题的内容 → 放各自 hub |
| 项目深挖 | 六个项目各自「做了什么 / 难在哪 / 怎么解决 / 证据」 | 通用原理 → 各基础 hub；跨项目套路 → 实现办法 |
| 实现办法 | 跨项目复用的解题套路及其代价与边界 | 一次性细节 → 项目深挖；原理 → 各基础 hub |
| 面试准备 | 自我介绍、项目讲述稿、追问应对、复习路线 | 知识本身 → 各主题 hub |

## 怎么用这个库

- **建节点**：`title` 写主题名（库内唯一可辨），正文**自包含**——脱离本库上下文也能读懂。数学用 LaTeX（行内 `$...$`、独立行 `$$...$$`）。
- **建链接**：`parent` 指向上层主题；跨主题引用在正文里写节点标题即可（本模式只有 `parent` 一种边）。
- **递进链**（可选，缺陷驱动时用）：`问题：` → `方案 ·` → `局限 ·` → 新 `方案 ·` 交替挂；子节点 frontmatter 写 `rel: solves` 表示"解决父的局限"（递进主线），备选方案写 `rel: alternative`。
- **找回**：正文开头写「`> 触发：`未来想起它时会说的话术」；`tags` 填同义词（≤5 个）。检索用 `recall`（语义召回，退化时会显式声明 `degraded`）。
- **维护**：长期不用的节点用 `archive_node` 归档（保留全文、默认不进检索）；库长到维护吃力时用 `consolidate` 先看 `dry_run` 计划再执行。
- **有代码的工程**（v8 M-Code）：代码骨架挂在**理论/概念节点**的「代码」栏（`code_map`），不为代码模块另建骨架节点；模块名/函数名会进入检索。

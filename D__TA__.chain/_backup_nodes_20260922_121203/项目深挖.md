# 项目深挖

**管什么**：每个做过/在做的项目一个节点，写清「这是什么 → 我负责什么 → 难在哪 → 怎么解决 → 证据在哪」。面试时能被追问三层而不崩，靠的就是这里的证据链。

**边界**：通用原理 → 各基础 hub；从多个项目反复出现的解题套路 → 「实现办法」；怎么口头讲出来 → 「面试准备」。

## 每个项目节点写什么（模板）

1. **一句话定位** + 技术栈（引擎版本 / 语言 / 规模数字）
2. **我负责的部分**：把"我做的"与"现成资产/教程照抄的"分清（面试被追问时这是诚信底线）
3. **关键难题 → 实现办法**：每条写 问题症状 / 根因 / 办法 / 代价 / 证据（`文件:行`、测量数据、截图）
4. **可量化结果**：帧率、draw call、内存、构建时间、制作效率——有数字写数字，没数字写"没测"
5. **当时的取舍与现在会怎么改**：能说清"为什么当时这么做"是加分项
6. **可能被追问的三层**：原理层 / 实现层 / 极限与替代方案

## 证据约定

- 证据路径**相对项目根**书写（如 `Assets/Shaders/Ocean.shader:120`），方便复现。
- 截图放 `artifacts/<节点id>/`，正文引用文件名。
- 已有 `.chain` 图谱的项目：**先复用其节点**，本库只留对面试有用的提炼版，并注明"详见原工程图谱"；不重复造内容。

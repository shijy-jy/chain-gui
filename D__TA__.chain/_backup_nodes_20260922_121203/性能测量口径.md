# 性能测量口径：怎么测、测什么、怎么复现

**为什么单独立一条**：方法论（「实现办法 · 先量化再优化」）解决"往哪看"，这条解决"**怎么量才算数**"。**没有口径的优化结果不算结果**——面试里"我优化了 36%"和"我在窗口内、同参数、同分辨率下测到 X ms → Y ms"是完全不同的可信度。

## 一、先分类：你在量什么

| 层次 | 工具 | 量到的是 | 注意 |
|---|---|---|---|
| **CPU 侧** | Unity Profiler（Timeline）、引擎自身的 cpu profiler | 脚本更新/物理/提交/GC | 编辑器开销 ≠ 发布版本；务必在**发布构建**上复测 |
| **GPU 侧** | Frame Debugger（逐 pass 看 RT 切换与 draw call）、GPU timestamp query | 真正的 GPU 时间与 pass 分布 | Frame Debugger 会**改变**渲染行为（可能禁用批处理），只用来看结构不用来计时 |
| **端到端** | 帧率采样、Frame Timing | 用户实际体验 | 帧率是离散的（16.7/33.3 ms 台阶），**看帧时间分布而不是平均帧率** |
| **CUDA / OpenGL 自有渲染器** | CUDA events、GL timer query | kernel 与 pass 各自的耗时 | 需要显式同步才准；异步提交会让 naive 计时偏小 |

**统计量要用中位数与 P95/P99，不要用平均**：渲染的卡顿来自长尾，平均值会把 1% 的 100 ms 卡顿稀释掉。

## 二、口径必须写进报告（模板）

```
机器：<CPU / GPU / 内存 / 驱动版本>
构建：<发布 / 编辑器>  <commit hash>
场景：<场景名 / 分辨率 / 画质档 / vsync 关>
负载：<passes / 采样数 / 粒子数 / 视点数>
测量：<工具>  <采样时长或帧数>  统计量=<中位 / P95>
结论：<改前 X ms → 改后 Y ms>
```

**四条硬规矩**：
1. **同一把尺子**：改前改后同机、同驱动、同参数、同分辨率；换机器就必须重新测基线。
2. **终止条件唯一**：要么按墙钟、要么按 passes/采样数，**不能两个并存**（见下面的真实事故）。
3. **热机后再测**：GPU 会降频（笔记本尤其），前 30 秒的数据不可信。
4. **测量代码本身要被验证**：测量脚本也会写错（下面两例都是真的）。

## 四、两个真实事故：测量代码自己错了

1. **终止条件冲突**：`render_unified_oss` 的 `--passes` 与默认的 **10 秒墙钟**并发——慢机器上 pass 数会漂移（实测同一配置出现 **15 与 9** 两种结果）。**修法：`--passes` 独占终止条件。**
2. **off-by-one 让"冒烟测试"全是假的**：`--autotest` 解析 `found+9` 差一，导致此前所有"四模式冒烟通过"**其实全在跑 mode 4**（`PROCESS_LOG:26`）。**这是个极好的面试故事：连自动化的测量/验证代码都必须被独立验证过。**

## 五、给你项目的补测计划（可执行）

- **TA_show**：发布构建 + 关 vsync，用 Profiler 抓 60 秒，记录：帧时间中位/P95、GPU pass 分布（Frame Debugger 看 AtmosphereSky / SSAO / AtmosphereFog 各自的 RT 切换）；再关掉雾 pass 对比一次 → 得到"删 ray-march 换来的收益"这个数。
- **windtest**：把云与大气合成后测一次，记录云 pass 的 GPU 时间与步长/步数的关系（步数减半 → 时间与观感各变化多少）。
- **render_unified_oss**：加一个 `--bench` 计时模式（CUDA events + 固定分辨率 + 固定 passes），把"~95 ms/frame"升级成可复现的基线；光栅与路径追踪分别记。
- **SDF**：粒子数 × 分辨率 × GPU 时间的三角关系（65536 粒的上限到底卡在哪：带宽/填充率/原子竞争）。

## 六、可能被追问的三层

1. **原理层**：为什么帧率是离散的台阶（vsync/呈现节奏）？CPU bound 与 GPU bound 怎么区分（交叉法：降分辨率看帧时间是否变）？为什么 GPU 计时需要同步与 timestamp query？
2. **实现层**：Unity Profiler 的 `ProfilerMarker` 怎么埋点？Frame Debugger 为什么会改变行为？CUDA events 怎么用才准（start/record/sync）？热节流怎么检测（同一测试跑三遍看是否漂移）？
3. **边界层**：移动端的测量与 PC 有什么不同（TBDR、温控、电池策略）？怎么测"内存带宽瓶颈"而不是帧时间？跨平台结论能不能互相推广？

## 七、手写/白板题（自测）

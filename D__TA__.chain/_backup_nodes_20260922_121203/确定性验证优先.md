# 实现办法 · 确定性验证优先（先取证据再下判断）

## 套路

**能用数字回答的问题，不要用眼睛回答。** 顺序永远是：
1. **先构造可判定的问题**（"能量应该是 1"、"同参数两次跑应该逐像素一致"、"密度积分不该饱和"）；
2. **取确定性证据**（数值/日志/结构化采样/分块矩阵），肉眼与视觉模型只做**定性**兜底；
3. **结论必须能被别人复现**（同一命令、同一参数、同一输出）。

## 视觉模型的正确定位（实测证据，2026-09）

用本地视觉模型（Qwen 系）读渲染图很有诱惑力——但它**不能做定量判断**，这不是参数量问题：同一个会话里 3B 模型连续三次给出与几何测量**完全相反**的答案（说"头占 30%、腿 40%"，实测 48%/24%；说"没有手臂抬起"，实测手腕 z 从 0.040 → **0.321**；说"画面没有变化"，实测 **28% 像素变了**）。换成 8B 后**定性描述明显变好**（自己发现"左侧角色手臂被头发遮挡"，与射线遮挡测试结论一致），**但定量依然不可靠**。

**所以正确架构是两层**：
1. **确定性测量层（主力）**：射线检测、骨骼夹角、IK 可达性、像素级 A/B、相机投影包围盒、镜像最近点距离——**凡能用几何算出来的，绝不问视觉模型**。
2. **视觉模型层（辅助）**：只做它擅长的——读 UI/报错文字、OCR、粗判"这是不是个人形""画面里有没有明显穿帮"。

→ 一句话版本（面试可直接说）：**"我把视觉模型当'能看懂图的实习生'用，而不是当测量仪器用。"**
（部署侧的两个附带教训：本地跑 VLM 时 `-fa on` 让生成速度从 2.6 → **36.4 tok/s（14×）**，显存"差不多够"和"够"差一个数量级；PowerShell 发中文 body 默认不按 UTF-8 编码，会伪装成"模型变傻"。）

## 三条可复述的原则（面试直接用）

1. **判定标准要先于实现存在**：先写"什么叫做对了"（能量 1.0、PSNR ≥ 50 dB、逐像素 diff = 0），再动手。事后补标准 = 给自己找台阶。
2. **口径要写清**：光栅可以要求**位级一致**，路径追踪只能要求**统计级**（浮点非结合性）；把不可位级复现包装成"通过"是自欺（`render_unified_oss` 的 PT CPU 根因至今未闭环，如实标注）。
3. **别让验证与被验证同源**：Kulla-Conty 的 LUT 与采样器若共用一个实现，自洽测试测不出共享偏差——**必须用独立方法仲裁**（白炉 + 解析解）。

## 可能被追问的三层

1. **原理层**：PSNR 的峰值为什么要钉死成参考图最大值？为什么浮点渲染难以位级复现（非结合性、FMA、驱动差异）？
2. **实现层**：`max_abs_diff = 0` 与 `PSNR ≥ 50 dB` 分别在什么情况下用？基线更新为什么要有 `-Force` 与交互确认？报告里为什么要注入 git hash？
3. **边界层**：视觉类效果（观感、构图）怎么验证？截图比对的上限在哪（无 SSIM/FLIP 时的替代）？自动化验收怎么避免"把 bug 固化成基线"？

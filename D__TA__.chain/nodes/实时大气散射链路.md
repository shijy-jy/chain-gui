# 方案 · 实时大气散射链路（LUT → 多散射迭代）

**这条是本库目前**跨项目复用度最高**的一条技术线：同一套思路在 water、windtest、TA_show 三个工程里各落地一次，每次都在前一次的基础上改。面试讲"我理解一个系统的演进"时，这是最好的例子。**

## 递进链（缺陷驱动，完整链在 `G:\water\.chain` 的「方案 · 透射率 LUT 预计算」一线）

```
问题：天空要有物理可信的散射，且要实时
 └─ 方案 · 单次散射体积积分
     └─ 局限 · 嵌套步进 32×64 ≈ 2000 次/像素            ← 性能不可接受
         └─ 方案 · 透射率 LUT 预计算（256×128）        ← solves
             └─ 局限 · 缺多次散射：地平线与日落失真
                 └─ 方案 · 多散射 LUT 不动点迭代（32×32，2 轮）  ← solves
                     └─ 局限 · 各向同性源 + 未计地面反射
```

## 三次落地对照（这就是"实现办法"的证据）

| | water | windtest | TA_show（当前主力） |
|---|---|---|---|
| 透射率 LUT | 256×128 | 256×128 | 256×128 |
| 多散射 | 32×32、2 轮不动点迭代 | Bruneton 多散射 LUT 迭代 | 32×32 迭代 |
| 天空 | 128³ cubemap 按需更新（太阳 >0.5° 或高度 >0.2 km） | 天空 cubemap（Tex2DArray 6 面 + mip）+ 天空盒 | cubemap 128²×6 面 ray-march |
| 雾/空中 | 自带指数雾，海-气桥 `OceanAtmosphereBridge.hlsl` **已写未接** | 太阳大气衰减 + 地面遮蔽（`sunDir.y<=0` 归零） | **全屏雾后处理**：删 ray-march，烘焙 cubemap + 仰角驱动解析雾，雾色逐像素采样反射 RT 保持天地缝合 |
| 性能手段 | 128³ cubemap 按需更新 | 早退 + 解析式 Beer×powder | 参数 hash 脏检查 + cubemap 100 ms 节流；反射 RT 512/1024/2048 + 隔帧 |

**云 × 大气耦合**（windtest 的一步）：云的环境光不再用固定色，改为采样大气生成的天空 cubemap → 日落时云自动联动，这是"两个系统真正接起来"的证据。

## 踩过的坑（可直接当面试故事讲）

1. **单位 m⁻¹ ↔ km⁻¹ 漏乘，无任何报错**——画面"看着还行"，靠数值验证才发现。→ 经验：静默错误只能靠数值验证抓，不能靠肉眼。
2. **自写全屏 pass 的 Vert 导致画面左右镜像** → 改用 core `Blit.hlsl` 的 `Vert`。
3. **`RWTexture2D` 不能 `SampleLevel`** → 另建只读孪生纹理。
4. **CPU 侧太阳衰减与 GPU 天空不一致**（日落后面仍亮）→ CPU 补地面遮蔽 `sunDir.y <= 0` 返回 0。
5. **LUT 只在 `Start()` 生成** → 参数 hash 脏检查 + 节流重算（否则改参数没反应）。

## 可能被追问的三层

1. **原理层**：Rayleigh 与 Mie 的区别与相函数？透射率 LUT 为什么是 2D（高度 × 视角天顶角）？多散射为什么用不动点迭代且 2 轮就够？为什么日落时地平线偏红、天顶偏蓝？
2. **实现层**：LUT 的分辨率怎么选（256×128 / 32×32 的依据）？cubemap 什么时候重建？脏检查用什么做 key？`ConfigureInput(Depth)` 为什么关掉 Depth Texture 还能拿到深度？
3. **边界层**：这套近似在什么场景会崩（高空视角？外星球大气？强地面反射？）？换到移动端先砍哪一步？不做多散射的损失能不能接受？

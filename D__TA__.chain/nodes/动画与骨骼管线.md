# 方法 · 动画与骨骼管线（IK / 动力学 / MMD 重定向）

**来源**：我的 Blender 工具链工作区 `D:\unity\unityProjectLocation\jianmo\.chain` → `node-24` / `node-25`。**这是工具向 TA 最有说服力的一块**：从"提取的游戏模型"走到"能和原生 MMD 模型吃同一份 VMD 动作"。全程用测量说话。

## 一、搭 IK：位置与朝向都得算对

- **约束挂在小腿骨上，不是脚骨**。因为 IK 到达的是**受约束骨骼的 tail**；这套游戏骨架的 `Ankle_L` 骨头**朝上**（head z=−0.2149 → tail z=−0.1349），挂上去会反向求解。**先看骨骼朝向，再决定挂哪根。**
- **`pole_angle` 必须实测扫描**：静止姿势膝盖几乎伸直（预弯仅约 4°），直接扫判别不出来 → 先把 IK 目标挪到**强制弯曲**的位置，再从 −180° 到 180° 每 5° 扫，取膝盖最靠前（$y$ 最小）的角度。实测两侧都收敛到 **−90°**，曲线有唯一极小值。
- **验证判据（很关键）**：胯部下压 0.06，两只脚的踝关节世界坐标应当**一个数字都不变**（实测 `(0.0559, 0.0063, −0.2149)` 完全不变，膝盖前弯到 $y=-0.066$）。→ **"脚没动"是可以用数字判定的**，不用看画面。

## 二、脚掌水平锁定

胯部下沉 0.012 时膝盖弯 37°（腿长 0.189，余弦定理算得），脚会跟着翘 37°。解法：给踝骨加**世界空间**的 `COPY_ROTATION`，target 是空物体。
**关键细节：空物体的朝向必须等于该骨骼的静止朝向**，否则第一帧脚就翻 90°（本例 `Ankle_L` 静止轴等价于绕世界 X 转 +90°）。
**与外部动作的冲突**：套 VMD 时必须把该约束 influence 设为 0，否则它**完全覆盖** MMD 的「足首」轨道；**不能用 `mix_mode='ADD'` 代替**（ADD 会把小腿旋转也加进去，脚就不水平了）。

## 三、头发动力学：位置弹簧 + 解析反解

源文件 0 刚体（MMD 物理不存在），要自己写。**核心是把"由世界空间目标位置反解骨骼局部旋转"写成解析式**，而不是每帧给 `pose_bone.matrix` 赋值——后者需要每根骨、每帧刷新 depsgraph，**47 骨 × 120 帧跑不动**：

$$L_k = \text{parent\_rest\_local}^{-1}\cdot \text{bone\_rest\_local}\ (\text{常量，预计算}),\qquad W_{\text{rigid}} = W_{\text{parent}} L_k$$

在世界空间模拟发梢：$v \leftarrow (v + (\text{rigid\_tip} - \text{tip})\cdot \text{STIFF} + G)\cdot \text{DAMP}$，然后限角（把方向朝刚体方向旋回，最多 `MAXANG`），最后

$$\text{basis} = L_k^{-1} W_{\text{parent}}^{-1} W_k,\qquad \text{rotation\_quaternion} = \text{basis.to\_quaternion()}$$

**两遍法**：第一遍只记录每帧父骨世界矩阵（每帧一次 depsgraph 更新），第二遍纯数学模拟并插帧。**实测**：`DAMP=0.72 / STIFF=0.30 / MAXANG=55° / G=(0,0,−0.0012)/帧²`，24 条链、5640 关键帧、发梢摆幅约 0.127（1.6 倍骨长），首尾帧精确回位可循环。
**链识别规则**：按名字含 Hair/Ribbon/Tail/Ear 筛选 → 排除 `_Handle`/`_Ha` 等空壳骨 → 沿"只有一个动态子节点"向下延伸 → **分叉支路单独成链**（否则漏掉）。

## 四、MMD 重定向：让别人的动作能套上

**起点**：MMD Tools 有骨骼名**字典系统**，导入 VMD 时用**按串长降序的子串替换**（不是整名映射）：`左腕` → `腕_L` → 把 `腕` 替换成 `Arm` → `Arm_L`。**这恰好是 UmaViewer 给这套模型的命名方式**，所以 26 条标准轨道里 **15 条开箱即用**。

### 三个必须知道的规则
1. **字典不能一对多**：两个 VMD 名映射到同一根骨 → `importer.py:470` 的 `assert` 直接崩溃（所以 `腰` 与 `下半身` 只能留一个）。
2. **替换顺序**：`足ＩＫ_L` 必须排在 `足_L` 前、`足首_L`/`手首_L` 必须排在 `首` 前（CSV 按串长降序排好即可）。
3. **自定义字典会整体替换内建字典**，必须写全。

### 最关键的一步：骨骼静止朝向必须符合 MMD 约定
`convert_rotation` 是 $q\,r\,q^{*}$，而 $q$ 由**目标骨骼自己的 `matrix_local`** 导出 → **朝向不对，同一个 VMD 旋转就会落到错的轴上**。实测偏差：`Head` 原朝下（应朝上）、`Ankle_L/R` 原朝上（应朝脚尖）、`Hip` 朝后上（应朝下）。
改朝向**不影响绑定姿势**（静止时形变恒等），但会改变局部轴 → **已有手工 K 帧与头发烘焙都要重做**。

### 另一条结构陷阱：兄弟 vs 父子
MMD 里 `上半身` 与 `下半身` **是兄弟**（局部坐标系上下相反，同一个四元数产生"上半身倾 + 骨盆反向"的铰链效果）。本模型原本把 `Hip` 当 `Waist` 的父级 → **同一旋转被叠两层**。修法：`Waist` 改挂到 `Center` 下与 `Hip` 平级。

### 极向目标必须跟随骨盆
`IK_Pole_L/R` 是世界空间空物体 → 角色一移动/转身，极向点落到身体侧后方，**膝盖弯曲平面被整个拽歪**（实测膝偏移 X 从 0.074 变成 **0.875**，明显侧扭）。
修法：给极向空物体加 `Child Of` 约束 → target 骨盆骨，`inverse_matrix` 用**静止姿势**的骨盆矩阵；**挂 `Hip` 而不是 `Center`**（膝盖弯曲平面由骨盆决定）。修复后膝偏移回到 $(-0.205, -0.734)$，基本朝前。

## 五、诊断方法（这套方法比结论更值钱）

| 问题 | 指标 | 实测 |
|---|---|---|
| 动作"看起来不对" | **IK 目标伸展比** $=\dfrac{|\text{IK 目标} - \text{大腿根}|}{\text{腿全长}}$，$>1$ 就是够不着 | 修正前 **64.5%** 的帧够不着（伸展比中位 1.23、最大 **4.28**，膝角中位 **0.3°**＝腿一直伸直）；把位移轨道整体缩放 $k=0.20$ 后降到 **8.1%**，膝角中位回到 39.9°，IK 误差中位归 0 |
| 跨模型对比 | **只能用与体型无关的量**：关节夹角、骨骼朝向轴相对竖直的倾角、方位角 | 用"头到骨盆向量"会得到"幅度差一倍"的错误结论（该模型头占身高 48%、腿占 16%） |
| 判断"丢了轨道有没有损失" | **先量内容再下结论** | `腰`/`グルーブ` 的旋转**全部是 0.0°**，纯恒等占位轨道，丢弃零损失 |
| 角度大是不是姿态错 | 分解成**倾角 vs 绕竖轴扭转** | 上半身世界转角曾测到 172.7°，其实是扭转，倾角中位只有 20° |

**A/B 基准法**：拿一个**原生 MMD 模型**当 ground truth，同一份 VMD 分别套上，逐帧比与缩放无关的量——躯干/手臂相关度 **0.98~1.00**，膝 0.845（余差来自 8% 的帧仍够不着）。**有 ground truth 之后，靠推理没法定论的问题全都一次定论。**

## 六、两个"别急着动手"的教训

1. **补骨骼前先验证网格里有没有对应几何**：这个模型**没有四指几何**（手部包围盒 0.077×0.096×0.080，宽 > 长 = 拳套形状；薄带扫描最多 3 簇从未到 4；指尖区直方图连续无间隙；"指尖跨度"比参照模型四指跨度还宽）。**硬加手指骨只会把整块网格揉软，比保持刚性更糟** → 四指 24 条轨道故意不映射。
2. **骨头名字对得上 ≠ 动作就对**；**关节的物理可达性才是硬约束**。这个模型腿长只占身高 16%，而动作是按腿占 ~50% 的模型设计的——**腿相对动作短了约 4 倍**，这不是映射能修的，只能缩放位移（代价：身体行程从 2.00 缩到 0.40，舞蹈变偏原地）。

## 七、工具与验证链

- `pmx_probe.py` 先探清源文件到底有什么（IK / morph / 物理）→ `vmd_tool.py`（VMD 读写 + 合成测试动作）→ `import_vmd.py` 一键导入（关脚掌锁定 → 按字典导入 → 报命中/丢弃清单）→ `mmd_dict/shikageki.csv`（实测 25/26 命中）。
- **快速验证渲染**：`engine='BLENDER_WORKBENCH'` + `bpy.ops.render.opengl(animation=True)` + **`color_type='TEXTURE'`** → **0.019 秒/帧**（739 帧 13.7 秒），EEVEE 3.4 秒/帧要 42 分钟，**快 180 倍**。
  **注意**：`color_type='MATERIAL'` 对 MMD 材质毫无用处（`diffuse_color` 全是默认白 → 一片灰白），**必须用 `TEXTURE`**。

## 八、可能被追问的三层

1. **原理层**：IK 解算的两类方法（解析 vs 迭代）与本例（Blender IK 约束）属于哪类？四元数为什么适合做旋转插值？弹簧-阻尼的稳定性条件（步长与刚度）？
2. **实现层**：为什么 `pose_bone.matrix` 赋值代价高（depsgraph 依赖图重算）？`Child Of` 的 `inverse_matrix` 为什么必须用静止姿势矩阵？`COPY_ROTATION` 世界空间与局部空间的差别？
3. **边界层**：这套重定向流程换成 Unity/UE 的 Humanoid/Retarget 会怎么做（同样的"朝向约定"问题会不会出现）？如果按比例缩放位移解决不了（比如动作是跑动），还有什么办法？如何自动检测"骨骼朝向不符合约定"？

# 色彩与光度学：线性空间、HDR 与色调映射

## 两个物理量先分清

- **辐照度 $E$**（irradiance）：单位面积收到的功率，单位 $\mathrm{W/m^2}$。
- **辐射亮度 $L$**（radiance）：单位面积、单位立体角、单位投影面积上的功率，单位 $\mathrm{W/(m^2\cdot sr)}$。

渲染里追踪的是 $L$（沿光线不变），光照积分出来的是 $E$。**量纲不统一是静默 bug 的温床**——真实事故：大气散射里 $\mathrm{m^{-1}}$ 与 $\mathrm{km^{-1}}$ 漏乘，画面"看着还行"，**没有任何报错**（`G:\water\.chain` 的 `大气模块工程踩坑`）。

## 线性空间：**只在显示器那一刻才做非线性**

- 美术给的颜色（贴图）大多在 **sRGB**（近似 $V \approx V_{\text{lin}}^{1/2.2}$）编码下——它是为了在 8 位精度里合理分配暗部码值，**不是物理量**。
- 正确流程：**贴图 sRGB 解码 → 线性空间做所有光照/混合运算 → 输出时再编码**。
- 混合（alpha blend）、模糊、加法**必须在线性空间做**，否则暗部会明显发灰/发暗（"为什么我的模糊看起来脏"的常见根因）。
- 反过来：如果是"数据贴图"（法线、粗糙度、遮罩），**不能**做 sRGB 解码。这个区分是 TA 岗位的高频考点。

## HDR 与色调映射：**不能简单 clamp**

场景里的亮度范围远超显示器（太阳可达 $10^3\sim10^5$）。直接 `saturate` / `clamp(0,1)` 会把所有高光压成同一片白斑——真实事故：`render_unified_oss` 里金属球"看起来像玻璃球"，球内峰值 RGB **CPU 153 vs GPU 5.6**，根因不是材质算错，而是 `packColor` **硬钳制**把能量抹平了；改成软拐点色调映射后观感正常，代价是**整条显示链的所有模式观感基线都得重建**（`t-028`/`t-029`）。

色调映射算子：
| 算子 | 特点 |
|---|---|
| Reinhard $L/(1+L)$ | 简单，压得"软"，高光无细节 |
| 软拐点（knee）/ filmic | 保持中段线性、只压高光，工程上最常用 |
| ACES | 电影感、饱和度高，工业标准 |

**自动曝光**：用对数平均亮度 $\log\bar L$ 驱动曝光（`render_unified_oss` 的 `logLumReduceKernel` + `halfTonemapKernel`），避免手调；要注意**时域平滑**，否则转视角时画面"呼吸"。

## 在你项目里的落点（三类，覆盖"该做/不该做"）

- **物理正确的一侧**：`render_unified_oss` 的 HDR + 自动曝光 + 软拐点 tone map；白炉测试本质上也要求线性空间能量守恒。
- **风格化的一侧**：`SDF` 元素球四层叠加 ≈9.3 而 Bloom 阈值 1.0 → 全白过曝；修法是分层归因（贴图定形 / 色带定色 / **HDR 只提最热处**）而不是继续调曝光（`t-037`）。
- **量纲一致性**：`water` 的大气散射单位换算坑（上面那条），以及 `TA_show` 的 HDR 开启 + Bloom 阈值设定。

## 可能被追问的三层

1. **原理层**：sRGB 曲线与 gamma 2.2 的关系（近似而非等同）？为什么人眼/显示器需要非线性编码（韦伯定律 / 每比特的感知均匀性）？辐射亮度与辐照度在渲染方程里各自出现的位置？
2. **实现层**：法线贴图为什么不能 sRGB？Bloom 阈值应该设在哪（HDR 前还是后）？色调映射后做 Bloom 与之前做有什么差别？自动曝光的 $\log$ 平均为什么要排除极亮像素？
3. **边界层**：HDR 显示（PQ/HLG）管线要怎么改？移动端半精度下 HDR 范围够不够（$2^{16}$ 的半精度只有 5 位指数）？tonemap 放在 UI 之前还是之后？

# Engram 模块详细设计 · 初版方案

> **版本**：v1.0 · **日期**：2026-09-03 · **基线**：Engram v2.7.0（MCP 阶段一 M1–M4 完成）
> **配套文档**：《未来规划·阶段整理 v1.0》给出模块全景与本文件的行文框架；本文件逐模块给出**功能清单、问题分析、初版方案**。仍为规划文档，不执行修改。

---

## M-A · MCP 接入收尾

### 功能清单
1. Claude Desktop 实机验收（规划书七项标准）；
2. watcher 端到端固化为自动化测试；
3. `engram-mcp.exe` 随 NSIS 安装包交付；
4. 三份客户端接入文档（Claude Desktop / Cursor / dsh）+ 故障排查清单；
5. dsh profile 多工作区挂载确认（water/restri/story/learning，配置已就位待重启验证）。

### 需解决的问题
| # | 问题 | 分析 |
|---|---|---|
| A1 | exe 路径随安装位置漂移，客户端配置里的 `command` 会失效 | 绿色安装 vs 固定目录的取舍；dsh 补丁已写死 `D:\AIworkspace\Engram\engram-mcp.exe`，正式分发必须有稳定路径 |
| A2 | 升级安装时 exe 被占用（Windows 文件锁） | NSIS 覆盖写失败是最常见的安装事故 |
| A3 | watcher 验收目前靠人工观察 GUI（"2 秒内刷新"） | 需要可回归的自动化判据 |
| A4 | 工具即契约：工具清单任何变更必须可追溯 | 目前没有 CHANGELOG，客户端升级后工具签名漂移无法排查 |

### 初版方案
- **A1**：安装器固定安装目录 `C:\Program Files\Engram\`（NSIS 写注册表 `HKLM\Software\Engram\InstallDir`）；文档给出两套 `command` 写法：安装版绝对路径、开发版相对仓库路径。
- **A2**：NSIS 升级段先执行 `taskkill /IM engram-mcp.exe /F`（静默忽略不存在）；server 侧加单实例互斥（Windows mutex），避免旧进程占锁。
- **A3**：新增 Rust ignored 集成测试 `watcher_e2e`（沿用 `real_dir_verify` 先例）：临时 dev 工作区 → 启动真实 notify watcher → 以子进程调 `engram-mcp --workspace <tmp>` 执行 `create_node` → 断言 2s 内收到文件事件。
- **A4**：仓库根新增 `CHANGELOG.md`，从 M-A 起记录工具契约变更（版本号 = 工具集哈希来源）。

### 与其它模块的联系
- 输出：稳定的工具契约 → M-B（词汇表）、M-D（recall 工具）都建立在其上；
- watcher 是 GUI 与 server 之间**唯一**的连接点（M-E 分发依赖此验收）；
- dsh 挂载完成即 M-E 的"深度集成"初版。

## M-B · 理解与检索增强

### 功能清单
1. AI_GUIDE 升级 v8（读写双修：何时新建/补充旧节点/连边；rel 词汇表收敛定稿）；
2. `rel_desc` 字段全链路（扫描/侧栏编辑/hover 显示/server 已支持 desc 参数，补 GUI 侧）；
3. 可选向量检索（同义词问题，先克制）。

### 需解决的问题
| # | 问题 | 分析 |
|---|---|---|
| B1 | rel 词汇表如何"收敛定稿"（D2） | 目前三值 `contains/solves/alternative` 与 GUI 线型一一对应；扩展词表（如 depends/precedes/illustrates）必须映射到现有线型，否则渲染不出来 |
| B2 | rel_desc 的显示与编辑入口 | server 已能写，但 GUI 侧栏没有编辑框、图谱 hover 不显示——"人机共治"要求两边都能改、都能看 |
| B3 | 向量检索的启动条件 | 何时判定"关键词+BFS 不够用"？需要有客观信号而非拍脑袋 |
| B4 | 避免两套嵌入设施 | 若 M-B 先做向量、M-D 再做图嵌入，会出现两个索引两套存储 |

### 初版方案
- **B1**：词汇表 v8 = 三值不变 + 新增三个候选（`depends`、`precedes`、`illustrates`），全部映射到现有线型（depends→虚线、precedes→实线、illustrates→点线）；`get_guide` 返回的词汇表为唯一权威，server 放行列表同步更新。
- **B2**：侧栏链接编辑器增加 `rel_desc` 文本框（≤ 60 字）；图谱边 hover 浮层显示 rel_desc；`read_node` 邻域名片已含 `rel_desc?` 字段（server 侧完成）。
- **B3**：启动信号 = 连续出现"search 零命中但语义相关"的真实反馈，或图谱超 500 节点；在此之前保持关键词+BFS。
- **B4**：**向量检索若做，直接按 M-D 4.1 的索引方案实施**（同一 `.engram/embeddings`、同一个 `recall` 工具），M-B 只负责指南与 rel_desc，不单独建索引。

### 与其它模块的联系
- B1/B2 的产物（词汇表、rel_desc 语料）是 **M-D 边注意力权重的数据基础**；
- B4 保证 M-B 与 M-D 共用一套索引，杜绝双索引漂移；
- 指南 v8 同时服务 GUI 的"复制 AI 指南"与 server 的 `get_guide`（D4 单源）。

## M-C · 记忆生命周期

### 功能清单
1. C1 访问统计（触达次数/最后触达时间，server 侧，落 `.engram/meta`）；
2. C2 消退归档（长期未触达 → 建议归档，归档≠删除，人可恢复）；
3. C3 巩固建议（高频共现节点建议连边；弱关联定期体检）；
4. C4 多进程并发写协议（文件锁 + append-only 审计日志）；
5. C5 对话自动提取（远期，人审后入库）。

### 需解决的问题
| # | 问题 | 分析 |
|---|---|---|
| C1a | 统计口径 | GUI 的读节点操作也算"触达"吗？GUI 零改动约束 vs 统计完整性冲突 |
| C2a | 消退判定与安全 | 阈值设定（时间/次数）；归档后图谱如何显示；恢复路径 |
| C3a | 建议的噪音 | 高频共现 ≠ 该连边（两个节点可能只是常被同一查询命中）——自动连边会污染图谱 |
| C4a | 跨进程锁 | Windows 上 GUI（Tauri/Rust）与 server 两个进程写同一文件；只靠乐观锁不够（乐观锁只覆盖 server 自己的读改写） |
| C4b | 审计的可追溯 | 谁（哪个客户端）、何时、改了什么、结果如何——日志必须 append-only 且不可被写入工具修改 |

### 初版方案
- **C1a**：分两期——一期只统计 **MCP 侧触达**（read/search/expand/recall 命中即计数），满足"遗忘即检索"的最小闭环；二期（C5 同期）在 GUI 侧加近零改动埋点（复用 watcher 之外的 Tauri 事件通道，`focusNodeId`/`selectedNode` 变化时上报一行）。
- **C2a**：阈值初版 = 90 天未触达；动作 = `get_overview` 返回"消退候选清单"，新增工具 `archive_node(id)` 移到 `.chain/archive/`，节点文件保留原样；GUI 增加"归档视图"开关（近零改动：侧栏列表过滤）。
- **C3a**：只建议不执行——共现计数 = 同一次 `expand`/`recall` 结果中同时出现的频次；建议条目带原因（"过去 30 天同现 12 次"），人工确认后走 `link_nodes`。
- **C4a**：写入路径统一为"文件锁（`LockFileEx`，超时 5s）→ 重读 → 校验 updated → 写 tmp → rename → 解锁"；GUI 的 update_node 命令同样接入（这正是"近零改动"范围内允许的改动）。
- **C4b**：`.engram/audit.jsonl` 每写一行 `{ts, client, tool, node, expected_updated, result}`；audit 只由 server 追加，不提供任何工具读写它。

### 与其它模块的联系
- C1 统计 → **M-D 4.2 注意力生命期先验**（"遗忘即检索"闭环的枢纽）；
- C2 归档 → M-D 检索的排除规则（归档节点不参与 recall，可手动包含）；
- C4 审计 → M-E 可观测性/故障排查的素材；
- C3 建议 → M-B 指南 v8 的"何时连边"章节的实证来源。

## M-D · 记忆图网络（L3 核心）

### 功能清单
1. 4.1 向量索引：全图元 K 嵌入入 `.engram/`；新增 `recall(query, k)` 工具；
2. 4.2 图注意力检索：沿边消息传递；`expand` 输出注意力权重；GUI 涟漪亮度可由权重驱动（可选开关）；
3. 4.3 自适应：访问统计反馈进权重；可选本地微调（远期）。

### 需解决的问题
| # | 问题 | 分析 |
|---|---|---|
| D1 | 嵌入模型选型 | 内容以中文为主 + LaTeX 公式 + 代码片段；必须本地（零云依赖）；千级节点实时性 |
| D2 | 存储与检索规模 | 千级节点 brute-force Q·K 即可；但索引文件要支持增量更新与全库重嵌 |
| D3 | 图注意力传播的稳定性 | 稀疏图 2–3 跳足够；度偏置（hub 节点天然权重高）；权重需可解释 |
| D4 | GUI 联动渲染 | 涟漪亮度目前只由拓扑层深决定；接入权重后要保持"一眼可读" |
| D5 | 索引一致性 | 文件是唯一事实源，索引是派生——编辑后如何保证不腐化 |
| D6 | 可解释性输出 | 用户要能回答"为什么这些节点被召回" |

### 初版方案
- **D1**：一期用 `fastembed`（ONNX）+ **BGE-small-zh-v1.5**（512 维，中英混合够用）；选型时实测三组中文同义词检索样例（"布局/力导向/物理模拟"、"采样/重采样/蓄水池"、"局限/缺陷/问题"）达标才定稿。
- **D2**：`.engram/embeddings.bin`（连续 f32，节点顺序与 index.json 对应）+ `index.json`（id → offset/hash）；千级节点全库重嵌 < 1 分钟（实测阈值）。
- **D3**：传播算法 = 个性化 PageRank 变体：从种子节点出发，边转移概率 = `sim(child, query) × rel_weight × life_prior`（度归一化消除 hub 偏置）；rel_weight 初值 `contains=1.0 / solves=1.2 / alternative=0.8`（B1 词汇表扩展后补全）；2 跳截断 + 权重软最大归一。
- **D4**：GUI 涟漪亮度 = 拓扑层深衰减 × 注意力权重（默认关闭权重通道，保持现观感；开关放波纹参数面板）。
- **D5**：索引每项记录内容哈希；`read_node`/写入时校验，不一致即单点重嵌；全库重嵌命令随安装包提供。
- **D6**：`recall`/`expand` 返回每项 `weight` 及其分解 `{sim, rel, life}`；GUI hover 浮层显示分解值。

### 与其它模块的联系
- **输入**：M-B（rel_desc 语料、词汇表→rel_weight）、M-C（C1 统计→life_prior、C2 归档→排除规则）；
- **输出**：M-A 的工具面（recall 加入工具清单并进 CHANGELOG）、GUI（涟漪权重通道）；
- **自依赖**：4.1 的索引是 4.2/4.3 的基础；4.3 的微调仅在 4.2 可解释权重实测不足时启动（有明确门槛）。

## M-E · 分发与生态

### 功能清单
1. 安装包集成（exe 随 NSIS、注册表安装路径、升级杀进程——承接 M-A）；
2. 客户端接入文档三份 + 故障排查清单四类；
3. dsh 深度集成（短期 profile 补丁多工作区——已就位；远期原生插件）；
4. 多工作区注册表与 HTTP 远程（远期）。

### 需解决的问题
| # | 问题 | 分析 |
|---|---|---|
| E1 | 客户端配置漂移 | 三种客户端配置模板 + exe 路径两套写法，容易过时 |
| E2 | 工具契约跨版本 | 客户端缓存工具列表，server 升级后旧客户端行为不可预期 |
| E3 | dsh 原生插件时机 | 官方插件 API 尚在 v0.1 预览，破坏性变更风险 |

### 初版方案
- **E1**：文档集中到 `docs/clients/`，各客户端一节；exe 路径用安装版/开发版两栏对照；每次发版在 CHANGELOG 同步更新。
- **E2**：server 启动时把 `serverInfo.version` 与工具清单哈希写入握手 instructions；客户端启动日志记录；文档写明"升级后重启客户端"。
- **E3**：维持现状（profile 补丁挂载），dsh 插件 API 稳定前不投入；投入信号 = 官方发布稳定 API 或补丁方式出现明显短板。

### 与其它模块的联系
- M-E 是 M-A~M-D 的**交付层**：每个里程碑的产物都以"用户零额外安装"为验收；
- 可观测性（server 日志 + C4 审计）是故障排查清单的数据源。

## M-G · 开源运营

### 功能清单
1. README.en.md（英文版）；
2. "为什么做 Engram"故事文 + 波纹 GIF 演示（V2EX/掘金/X）；
3. 发布节奏与版本号规范。

### 需解决的问题
- G1：英文版与中文版内容漂移 → 初版方案：README.en 只翻译价值主张/快速开始/截图，详细设计指向中文文档；
- G2：宣传素材缺动图 → 用现有 demo 工作区录屏转 GIF（dev 模式波纹交互 10 秒）。

### 与其它模块的联系
- M-G 的发布节奏跟随 M-A/M-B/M-C 里程碑；故事文素材取自已完成的真实功能（涟漪、聚焦、MCP 接入）。

## 模块间联系总图

```
                    ┌────────────────────────────────────────────┐
                    │           唯一事实源：.chain/nodes/*.md      │
                    └───────▲───────────────────────▲────────────┘
                    读/写(server)                读(watcher)
        ┌───────────────┴──────┐          ┌────────┴─────────┐
        │  M-A engram-mcp      │          │  Engram GUI       │
        │  9 工具 + D2/D3/D4   │          │  涟漪/聚焦/侧栏    │
        └───┬───────────┬──────┘          └────────▲─────────┘
            │           │                          │ D4 权重通道(可选)
   ┌────────▼───┐  ┌────▼──────────┐               │
   │ M-B 指南v8 │  │ M-D 记忆图网络 │◄── M-C 统计    │
   │ 词汇表     │──│ K嵌入/注意力   │    (C1 life)   │
   │ rel_desc   │  │ recall/expand  │               │
   └────────────┘  └────┬───────────┘               │
                        │ D5 派生索引                │
                 ┌──────▼──────┐                     │
                 │ .engram/    │                     │
                 │ embeddings  │                     │
                 │ meta/audit  │                     │
                 └─────────────┘                     │
   ──────────────────────────────────────────────────┘
   M-E 分发（打包/文档/多客户端）包裹以上全部；
   M-G 运营按 M-A→M-B→M-C 里程碑发布。
```

**关键数据流**：
1. **写**：AI → M-A 工具 → （M-C C4 锁+审计）→ `.md` → GUI watcher 自动刷新（唯一连接点）；
2. **读**：AI → M-A 工具 → M-D 索引（如启用）→ 叙述拼装（邻域/路径/权重分解）；
3. **派生**：`.engram/` 全部可重建（嵌入、统计、审计之外无任何状态）；
4. **反馈**：M-C 统计 → M-D 权重 → M-A 返回 → 下一次对话——记忆越用越准。

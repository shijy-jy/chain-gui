### 1.2 已核实的技术债（代码核实，非推断）

1. **写路径未统一**：GUI 的 update_node 与 MCP 核心层是两条并行实现，D3 保护只活在 MCP 侧——GUI 写入无乐观锁、无原子写；
2. **watcher 边界**：只监听 `nodes/` 顶层 `.md`；事件循环零自动化测试（测试只覆盖纯函数）；未来归档写 `archive/` 不会触发刷新；
3. **双代码库漂移**：安装版目录无 git，与开发版（G:\test1.x）的版本漂移无验证手段；
4. **测试盲区**：无并发双写、无故障注入、无大图分级、无编码边界用例。

### 1.3 已拍板决策清单（✅ = 已定，两模式通用）

**软件层（五项）**：
- ✅ S-3 治理权：冲突即冻结——CONFLICT 后节点进入 `[待裁决]` 前缀，人处理；
- ✅ S-4 多工作区：单实例多工作区——工具加 `workspace` 参数，跨区记忆可关联；
- ✅ S-5 版本矩阵：GUI / 工具契约 / 指南 / 索引格式四版本独立管理，`--version` 输出 git 短哈希；
- ✅ S-6 红线：GUI「零破坏」（加性改动允许，破坏性改动禁止）；
- ✅ 接入矩阵：人（GUI）/ 本地 AI（stdio）/ 云端 AI（HTTP+token 经本机转发）。

**记忆层（八点）**：
- ✅ 1 粒度裁决：正文 >60 行或含两个可独立检索主题 → 拆；标题近似+正文重叠 → 建议合并（提示不自动做）；
- ✅ 2 编码规范：frontmatter 加 `trigger: [词1..5]` 数组（结构化，可作检索 K 的一部分）；
- ✅ 3 强度公式：ACT-R 基础激活 `S = ln(Σ (now-t_j)^(-0.5))`，指数由命中/未命中反馈校准——**零人工权重**，度数因子被访问历史自然吸收；
- ✅ 4 双时钟：墙钟（指数半衰期遗忘）+ 记忆时钟（每次工具调用 +1，event gap 作排序二级因子与冷启动指标）；
- ✅ 5 线索衰减回路：recall 失败查询入 stats，consolidate 同期产出「线索缺口清单」，人/AI 择机补 trigger（不自动写）；
- ✅ 6 检索阶梯 L1–L5（查询表示 × 记忆表示逐级放宽）：L1 精简线索↔trigger → L2 多线索↔trigger → L3 大意↔线索 → L4 三内容↔关键线索 → L5 三内容↔大意；**归档节点自 L4 起可见**——遗忘=检索成本升高而非不可见；
- ✅ 7 冲突检测两阶段：先标题相似度（零依赖），向量索引上线后升级嵌入相似度（同一套设施）；
- ✅ 8 蒸馏 consolidate：社区摘要式——BFS/共现聚类 → 骨架节点只陈述共识事实且**逐条附源节点引用** → `derived: true` + `[蒸馏]` 前缀 + L4 阶梯可见 + `dry_run` 默认 + 人审摘帽。

⏳ **待决**：M-Code 试点语言（Rust 优先，见 §3.3）。

## 2 · 开发模式规划（自由知识库）

### 2.1 定位

自由知识图谱：笔记、卡片、任意拓扑；AI 辅助整理；递进关系建模（rel 三类型 + rel_desc）。**生态位：人机共治的个人/项目知识库，有检索阶梯、有遗忘。**

### 2.2 记忆层设计（§1.3 八点的落地）

- **写入**：指南 v8 含粒度双条件与 trigger 规范；写入守门（同名拦截/词表/乐观锁）沿用 MCP 侧并随"唯一写路径重构"覆盖 GUI；
- **读取**：检索阶梯 L1–L5 + `recall` 工具（向量索引可插拔、默认本地、降级链永不失效）+ 失败日志回路；
- **维护**：强度（ACT-R）+ 双时钟统计（stats.json 派生文件）+ 归档（`archived` 前缀）+ 蒸馏（严格引用）+ 断边（unlink_nodes）。

### 2.3 记忆图网络终态

QKV 图元（Q 现算 / K 派生索引 / V 即文件 / 图结构与生命周期作先验）；注意力权重 = `sim × rel_weight × life_prior`（度归一化）；子阶段 4.1 向量索引 → 4.2 图注意力检索 → 4.3 自适应（微调有明确门槛）。**「遗忘即检索」闭环**：强度信号即注意力先验。

### 2.4 落地顺序

```
第 0 步（已部分完成）：拍板
第 1 步：唯一写路径重构（core/writer）+ 单实例多工作区
第 2 步：M-B'：指南 v8（粒度+trigger）+ recall（L2 阶梯起步 + 降级链 + 失败日志）
第 3 步：M-C'：stats 双时钟 + 归档/断边 + watcher 事件循环自动化
第 4 步：M-D'：冲突检测升级 + 蒸馏（严格引用）+ HTTP spike
第 5 步：记忆图网络 4.1 → 4.2
```

## 3 · 分析模式规划（工程链协议）

### 3.1 定位

严格链协议（goal→design→task→verification + 状态机 + 失败派生链）：工程推进的记忆。**目标升级：从"结论记忆"进化为"工程代码的内化"——在工程图谱上长出代码契约层。**

### 3.2 现状

链协议 v7 已覆盖：单根树校验、九字段、状态光晕、失败定格与派生、折叠/快照/过程日志、AI_GUIDE 单源。缺口：**设计与代码之间没有中间层**——design 节点写的是文字设计，代码在仓库里，两者靠人脑关联。

### 3.3 新模块 M-Code · 代码骨架内化（本规划核心增量）

**目标**：对应节点内容中显示"解决当前问题设计的代码框架"——函数封装级（功能、封装、接口输入输出清晰，不细到实现）；通过所有有效节点的框架即可理清工程逻辑，实现模块化、避免推到重来、避免每次推进全量读码的推理延迟。

**核心原则：骨架必须从代码自动派生、可随时再生成，绝不能是 AI 手写的静态快照**（漂移的骨架比没有骨架更危险）。

三层设计：

1. **自动提取**：tree-sitter（Rust/Python/JS/TS 通用）提取模块结构、公开接口优先的函数签名、调用边 → 生成每节点骨架 + 流程图（Mermaid 文本）；
2. **变更联动**：watcher 监听代码目录 → 对应节点骨架标 `stale` → AI 进场主动 `refresh_code_map`（安静优先）+ stale 标记兜底；
3. **AI 只做加法**：职责描述与设计意图由 AI 补写；结构事实（签名/调用边）永远来自代码。

**挂载方式**：frontmatter `code_map: <派生区文件>` 引用 `.chain/code_map/<node-id>.md`，正文只放一句概述（I1/I2 红线：派生物不进事实源）。

**流程图渲染**：GUI 加 Mermaid 渲染（markdown 代码块，零破坏加性改动）。

### 3.4 四层信息模型

分析模式节点由此承载四层信息：

```
事实层（结论：现状/失败/验收） ← 已有
设计层（骨架契约：模块/接口/调用） ← M-Code 新增
代码层（实现：仓库文件） ← 骨架按索引指回
验证层（测试契约） ← 已有（v 节点）
```

AI 进场路径变为：读链 → 读骨架 → 按骨架索引读具体代码 → 写回事实与骨架更新——**推理延迟从 O(全量代码) 降为 O(骨架)+O(改动面)**。

### 3.5 与记忆层共享

代码骨架直接进入 §1.3 的检索阶梯：模块名/函数名成为 trigger（说"登录接口"即命中骨架）；骨架大意进 L4/L5；强度与双时钟同机制；蒸馏的严格引用同样适用（骨架蒸馏 = 模块簇摘要）。

⏳ **待决**：试点语言（建议 Rust——自己的项目、tree-sitter-rust 成熟、可立即在 Engram 自身上验证"用骨架理解 Engram"）。

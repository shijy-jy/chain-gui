### 模块 3：遗忘方案（设计定型）

**问题：** 三个月后 500 个节点，AI 凭什么 3 次调用内找到此刻最该想起的 3 条？

**核心立场：遗忘是特性，不是 bug；归档优于删除**（人类遗忘多为提取失败而非存储丢失）。

四组件：

1. **记忆强度信号**（P1）：`access_count` / `last_accessed` 统计写入 `.chain/stats.json` 派生文件（**不进 YAML**，防 git 噪音 + watcher 风暴）；强度公式 `f(访问次数, 最近访问, 图谱度数)`，预留 `importance` 第四因子（见模块五）。
2. **归档而非删除**（P1）：`archive_node`（frontmatter `archived: true` + 标题 `[归档]` 前缀，GUI 零改动）+ `unlink_nodes` 断边（修复只能连不能拆的不对称）。
3. **语义冲突检测**（P1）：create 时高相似 hint，复用 D2 已有 `alternative` 边表达竞争，零新增概念。
4. **巩固蒸馏**（P2，最有特色）：`consolidate` 反刍——节点簇蒸馏为语义节点 + `contains` 回指，闲置节点建议归档；默认 `dry_run=true` 延续 D3 写入保护哲学。

**理论校准：** 记忆权重=突触强度×平行通道数 ⇒ 访问次数↔强度、图谱度数↔平行通道，公式有神经解剖学依据；海马体=索引不存内容 ⇒ 「索引与内容分离」与 D 系红线同构；细节遗忘=主动精简留骨架 ⇒ consolidate 产物应是**骨架**而非全文摘要。

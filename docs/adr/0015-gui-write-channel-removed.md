# ADR 0015 · GUI 人治写通道移除（三层重构 P2）

- **日期**：2026-10-03
- **状态**：已接受

## 背景

三层重构（设计稿 `docs/Engram_三层重构_设计整理_v1.md`）把 Engram 的治理模型从"人机共治"改为"**AI 自治，验证在痕迹**"：

1. 用户决定**放弃人治通道**——记忆的写入不再由 GUI 承担；
2. 记忆的**唯一入口是对话**，AI 使用记忆系统的唯一通道是 **MCP**（remember / dialogue_status / resolve_conflict，契约 v6→v8）；
3. GUI 保留"**只读观察面 + 维护通道**"（渲染、检索、快照、代码骨架挂载、过程日志）。

遗留的 GUI 写通道包括：信息栏编辑面（update/create/delete/set_parent/fold）、文件树模式三态操作面（create_node_human/delete_node_human/set_parent_human）。它们与"入口唯一"冲突——其中 GUI 编辑面还绕过了冻结门禁/审计/索引 stale（实测确认的不一致）。

## 决定

**移除全部 GUI 人治写通道**：

| 通道 | 处置 |
|---|---|
| Tauri 命令 update_node / create_node / delete_node / set_parent / fold_chain | 删除（含注册） |
| Tauri 命令 create_node_human / delete_node_human / set_parent_human | 删除（含注册） |
| core `node_edit` 三个 `*_human` 函数与"人用护栏"分支 | 删除 |
| 信息栏编辑表单（标题/状态/标签/正文/保存/删除/折叠/改挂载） | 删除 |
| 文件树模式三态操作面（＋/✎/🗑） | 降为只读阅读面 |
| GUI 保留 | 只读：扫描/渲染/搜索/阅读/定位；维护通道：reindex、code_map 挂载/刷新、快照、过程日志追加、工作区管理 |

**冲突裁决出口转移**：`resolve_conflict`（MCP）成为冻结节点的唯一自愈通道；`ensure_not_frozen` 的恢复说明同步改写。

**与此前 ADR 的关系**：

- **ADR 0003（冲突即冻结）**：治理权从"人"转移为"AI 经 resolve_conflict 裁决"，冻结语义不变（并发保护信号 + 拒绝一切 AI 写入）；
- **ADR 0012（GUI 零破坏）**：本条是**对它的显式豁免**——删除 GUI 写工具属破坏性改动，但经用户拍板（2026-10-03，"放弃人治通道"），以本 ADR 记录豁免；
- **ADR 0014（唯一写路径）**：核心层唯一写路径原则保持不变——只是写路径的**入口**从"GUI/MCP 双通道"收窄为"MCP 单通道"。

## 后果

**正面**：

- 入口唯一（设计稿 §I2）由"物理上只剩一个写工具"保证，不再是文档承诺；
- GUI 绕过冻结门禁/审计/索引 stale 的三处不一致**随通道删除一并消失**（不是打补丁）；
- 人用 GUI 变成纯粹观察面：任何新节点都可回答"从哪次对话来"（origin 溯源）。

**负面/风险**：

- 人无法直接在 GUI 修改节点——记忆修正只能通过 AI 会话完成；离线/无 AI 场景下维护能力下降；
- 文件树模式的"编辑"体验不复存在，用户 2.18.0 拍板的"人用编辑面"被撤回（同样以用户本轮拍板为准）；
- CDP 自动化脚本（`_verify_edit*.cjs` 等）依赖的写路径与 `__engramDebug` 交互面需要随删（另立任务）；
- 若未来接"云端 AI"通道，须先解决"AI 身份"问题——否则任何 AI 都持有裁决权（设计稿 §9 已预告）。

**未来影响**：

- 人若要恢复编辑权，应重新走 ADR（例如"裁决通道给谁"的重设计），不得静默加回。

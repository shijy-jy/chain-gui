# Engram 未来规划 · 阶段性整理（模块化设计）

> **版本**：v1.0 · **日期**：2026-09-03 · **基线**：Engram v2.7.0（commit `ca737fa`，MCP 阶段一 M1–M4 完成、31/31 验收全绿）
> **性质**：以最终目的为导向的模块化规划整理——只做设计梳理，不执行具体修改。实现以各模块的「启动条件」为准。

---

## 0 · 最终目的（北极星）

**让任意 AI 客户端把 Engram 工作区当作自己的外接记忆——记忆独立于模型、透明可读、可携带、会巩固也会遗忘。**

由它反推，Engram 需要三层能力，缺一不可：

| 层 | 能力 | 现状 |
|---|---|---|
| L1 人机交互层 | 人用 GUI 看见并治理记忆（可视化、涟漪、聚焦、侧栏） | **成熟**（v2.6） |
| L2 机器交互层 | AI 用 MCP 读写同一份记忆（工具 = GUI 交互的翻译） | **主体完成**（阶段一 M1–M4） |
| L3 记忆智能层 | 记忆自组织：图注意力检索、巩固与遗忘、生命周期 | **未开始**（本规划的核心） |

一句话概括路线：**先把「人怎么用」翻译给机器（L2），再让记忆自己会组织（L3）。**

---

## 1 · 模块全景与依赖

```
P1 收尾 ──► P2 理解与检索 ──► P4.1 向量索引 ──► P4.2 图注意力检索 ──► P4.3 自适应
                │
                └──► P3 生命周期 ◄── 与 P4.2 合流（访问统计 = 注意力先验）
E 分发与生态：贯穿全程（每阶段随包交付、多客户端接入）
G 开源运营：并行低优先级
```

模块编号：**M-A 接入收尾 → M-B 理解检索 → M-C 生命周期 → M-D 记忆图网络 → M-E 分发生态 → M-G 开源运营**。

## 2 · 模块化设计

### M-A · MCP 接入收尾（阶段一剩余）

**目标**：P1 全链路验收闭环 + 随包交付。

| 项 | 现状 | 剩余设计 |
|---|---|---|
| 工具集 | ✅ 9 工具 + D2/D3/D4 全过 | 无 |
| Claude Desktop 实机 | ⏳ 未验收 | 按规划书 §06 配置片段实机走 7 项验收 |
| watcher 端到端 | ⏳ 手动验证过（G:\water） | 固化为 Rust ignored 集成测试 |
| 分发 | ⏳ exe 已在 resources/ | NSIS 打包附带 engram-mcp.exe；安装路径写入客户端配置文档 |
| dsh 接入 | ✅ profile 补丁挂 4 工作区（water/restri/story/learning） | 重启后生效确认；文档化"一句话切换工作区"用法 |

**验收**：规划书 v1.1 七项全绿 + 安装包内 exe 可用 + 新对话自动带工具。
**启动条件**：无（可立即执行）。

---

### M-B · 理解与检索增强（原阶段二）

**目标**：让 AI「读得懂联系，写得出好记忆」。

1. **AI_GUIDE v8 读写双修**：何时新建/补充旧节点/连边；rel 词汇表收敛定稿（D2 扩展词表由此诞生）；写入规范补 D3/D4 说明。
2. **rel_desc 字段**：子节点 frontmatter 可选一句话说明"为什么连着"——它是**边嵌入的语料**（M-D 的前置积累），向后兼容。
3. **向量检索（可选，先克制）**：解决同义词检索（"布局"找不到"力导向"）。图结构本身是强语义索引（GraphRAG 研究结论），关键词+BFS 不够用再启动。

**验收**：指南 v8 发布；rel_desc 全链路（扫描/侧栏/server）解析；可选向量检索达 `search` 同义词命中。
**启动条件**：M-A 完成。
**与 M-D 的关系**：本模块的 rel_desc 与词汇表是 M-D 边注意力的数据基础；向量检索若在此启动，直接复用 M-D 4.1 的索引设施，**避免做两套嵌入**。

---

### M-C · 记忆生命周期（原阶段三）

**目标**：记忆库具备"巩固/遗忘"——被反复访问的巩固，长期不用的消退归档（竞品无人做遗忘，这是生态位）。

| 子模块 | 设计 |
|---|---|
| C1 访问统计 | server 侧记录每个图元的触达次数与最后触达时间，落 `.engram/meta`（派生数据，不碰 .md） |
| C2 消退 | 长期未触达节点降权 → 建议归档（归档≠删除，人可恢复）；GUI 增加"归档视图" |
| C3 巩固 | 高频共现节点建议连边；弱关联定期体检（体检报告走 `get_overview` 的 health 区） |
| C4 并发协议 | 多 AI 并发写：文件锁 + append-only 审计日志（P1 乐观锁为第一道防线） |
| C5 对话提取（远期） | 会话沉淀候选节点，人审后入库 |

**验收**：连续使用两周后，`get_overview` 给出可信的巩固建议与消退清单；GUI 归档视图可用。
**启动条件**：M-A 稳定运行、写入量足以产生统计。
**与 M-D 的关系**：C1 的统计直接成为 M-D 4.2 注意力的**生命周期先验**——"遗忘即检索"闭环在此合流。

---

### M-D · 记忆图网络（新，L3 核心）

**目标**：每个图元携带 QKV 信息，图结构 + 注意力组织成可检索的"记忆图网络"——把 GUI 的涟漪升级为**内容感知的加权涟漪**。

**角色映射**（对应现有交互）：

| 概念 | 记忆图里的实体 | 载体 |
|---|---|---|
| Q 查询 | 当前对话意图编码 | recall 时现算，不落盘 |
| K 检索签名 | 图元"讲的是什么"（标题+正文+rel_desc 嵌入） | `.engram/` 派生索引 |
| V 内容 | 正文 + 邻域/路径叙述 | 仍是 `.md` 文件本身 |
| 图结构 | 注意力传播的先验（沿边、按 rel 类型加权） | 现有图谱 |
| 生命周期先验 | 访问频率/最后触达（来自 M-C） | `.engram/meta` |

**子阶段**：

- **4.1 向量索引（3–5 人天）**：全图元 K/V 嵌入入 `.engram/`；新增 `recall(query, k)` 工具（Q·K 排序 + 邻域叙述拼装）。本地嵌入模型（fastembed/ONNX），零云依赖。
- **4.2 图注意力检索（5–8 人天）**：`recall` 升级为沿边消息传递（GAT 式，不训练，权重 = 内容相似度 × rel 类型权重 × 生命周期先验）；`expand` 输出带注意力权重；GUI 涟漪亮度可选由权重驱动。
- **4.3 自适应（远期）**：访问统计反馈进权重（与 M-C 完全合流）；如需更强语义，本地 LoRA 级微调小型注意力头（只作用于检索打分，不碰数据、不碰透明性）。

**验收**：`recall("布局")` 命中"力导向布局"（同义词）；expand 权重排序符合人眼判断；全库重嵌 < 1 分钟/千节点。
**启动条件**：M-B 完成（rel_desc 语料）+ M-C 的 C1 统计可用。

**架构红线（本模块绝对不变式）**：
1. 纯文本 `.md` 仍是唯一事实源；QKV 全部是派生缓存，可删除重建，嵌入模型升级=全库重嵌而非数据迁移。
2. 不训练、先冻结：权重全部可解释（相似度×边类型×生命周期）。
3. 图元不携带可训练矩阵；"transform"由嵌入模型完成。

## 3 · 里程碑排期（人天为单人全职估算）

| 里程碑 | 内容 | 估算 | 依赖 |
|---|---|---|---|
| M-A | P1 收尾（实机验收+打包+文档） | 2–4 人天 | 无 |
| M-B | 指南 v8 + rel_desc +（可选）向量 | 3–5（+3–5）人天 | M-A |

**关键路径**：M-A → M-B → M-D1 → M-D2 → M-D3（M-C 可与 M-B 并行，但其 C1 是 M-D2 的前置）。

## 4 · 风险登记（含新增）

| 风险 | 模块 | 应对 |
|---|---|---|
| rmcp/dsh 协议变动 | M-A/M-E | 薄封装适配层；锁版本；dsh 原生插件等 API 稳定 |
| AI 乱写致图谱膨胀 | M-A/M-B | 两阶段守门 + 指南 v8 + 返回体提示 + M-C 消退兜底 |
| GUI/server 并发写 | M-A/M-C | P1 乐观锁 + 原子写 + 串行队列；C4 文件锁升级 |
| watcher 不覆盖外部写 | M-A | 固化为 ignored 集成测试（已验证通过） |
| 嵌入模型升级 | M-D | 全库重嵌脚本；索引与数据分离（.engram 可重建） |
| 双语嵌入质量 | M-D | 选型时实测中英混合检索；必要时双模型或拼接嵌入 |
| 双索引不一致 | M-D | 文件为真理；索引带内容哈希，不一致即重嵌 |
| 注意力检索不可解释 | M-D | 权重三因子（相似度/边类型/生命周期）全部显式输出，GUI 可视化 |
| 过早引入训练 | M-D3 | 门槛：4.2 可解释权重实测不够用才启动微调 |

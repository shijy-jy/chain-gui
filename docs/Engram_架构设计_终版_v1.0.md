> **版本**：v1.0（终版）· **日期**：2026-09-07 · **基线**：Engram v2.7.0

## 0 · 总判断

**当前最值得做的架构动作只有一个：cargo workspace 化、领域核心下沉为 `engram-core` 纯库。**

公司级 ≠ 复杂。公司级 = **变化发生时有迹可循、有网兜底**。单仓 + workspace + 嵌入式纯库，就是 1–2 人项目的终态架构。它同时解决：写路径未统一（GUI 无 D3 保护的结构性根源）、watcher 无法脱离 Tauri 测试、双模式规则散落、依赖治理无边界——**一次重构消灭一个 bug 类别，而非一个 bug。**

## 1 · 目标架构

### 1.1 crate 布局（六边形架构的 Rust 版）

```
crates/
├── engram-core    ← 唯一知道「规则」的地方（零 Tauri、零 MCP 依赖，纯库可单测）：
│    节点模型 / YAML 解析 / 读写守门（D2/D3/D4）/ 乐观锁 / 原子写 / 串行队列 /
│    watcher / 检索阶梯 L1-L5 / stats 双时钟 / code_map 提取与校验
├── engram-mcp     ← 薄壳适配器：stdio/HTTP 协议翻译，调 core
├── engram-gui     ← 薄壳适配器：Tauri commands，调 core
└── engram-cli     ← 未来：sync_code_map / 数据迁移脚本 / 工作区体检 / 全库重嵌
```

依赖方向唯一：**入口 → core**；core 不得反向依赖任何入口 crate（宪法第 1 条）。

### 1.2 进程拓扑（单写域，不拆进程）

采纳《架构建议》立场：**不做守护进程、不做进程拆分**——每客户端 spawn 自己的 engram-mcp 进程（stdio），单写域由**文件级锁 + core 内的串行队列**保证，而非进程拓扑：

- 写：`LockFileEx`（跨进程）→ 重读校验 `updated`（乐观锁）→ tmp/rename 原子写 → 审计追加；
- 统计/索引：append-only 派生文件，读时现算，不共享内存态；
- **后备**：当且仅当统计争用/索引重复加载在实测中出现，才评估"stdio shim → 本地 daemon"的集中形态——正确性不依赖它，性能才可能依赖它。

### 1.3 数据布局（四区 + schema 版本）

```
工作区/
├── .chain/
│   ├── .mode            ← 模式标签（事实源元数据）
│   ├── .schema          ← 数据格式版本（新增，见 §3）
│   ├── nodes/*.md       ← 唯一事实源（人可读）
│   ├── archive/         ← 归档（archived 节点原位移入）
│   ├── index/           ← 派生物：嵌入索引（可重建）
│   ├── code_map/        ← 派生物：代码骨架（可重建）
│   ├── stats.json       ← 派生物：双时钟强度统计（不进 YAML）
│   ├── audit.jsonl      ← 派生物：append-only 审计（不可被任何工具修改）
│   └── logs/            ← 运行时滚动日志
└── …工程文件（代码、文档）
```

### 1.4 双模式 profile（不分叉代码）

开发模式与链协议模式的差异收为 core 的**两个 profile 配置包**（schema 字段集 + rel 词表 + 指南指针 + 校验规则），入口只传 profile 名。**模式是配置，不是分支。**

## 2 · 分层宪法（不可逾越条款）

| # | 条款 |
|---|---|
| 1 | `engram-core` 不得依赖任何入口 crate（GUI/MCP/CLI） |
| 2 | 节点文件为唯一事实源；一切派生物可重建、可删除 |
| 3 | 统计、索引、审计不进 YAML 事实源 |
| 4 | rel 三类型（contains/solves/alternative）不扩张；语义细节走 rel_desc |
| 5 | 一切写入必经 core 守门（D2 词表/D3 乐观锁/D4 提示），入口不得直写文件 |
| 6 | GUI「零破坏」：加性改动允许，破坏性改动（改默认交互/删减工具）禁止 |
| 7 | 检索降级链：任何增强失效退化为关键词并显式声明 |
| 8 | 错误码契约：稳定码 + 文案分离（`CONFLICT:` / `DUPLICATE_TITLE:` / `INVALID_REL:`），i18n 由此预留 |

## 3 · 数据 schema 版本与迁移（新增，P0）

- `.chain/.schema` 记录格式版本（frontmatter 字段集、目录结构、索引格式三位一体）；
- 版本升级走**幂等迁移工具**（engram-cli `migrate`），绝不靠扫描器堆 if 兼容分支；
- 安装包升级流程：检测旧 schema → 提示备份 → 迁移 → 校验 → 完成；GUI 显示"工作区已迁移 v2→v3"。

## 5 · 契约与质量体系

| 层 | 手段 | 卡什么 |
|---|---|---|
| MCP 契约 | **golden 契约测试**：9→13 工具的请求/响应固化 JSON 入 CI，变更必须显式更新 golden | 下游 AI 客户端因契约漂移全挂 |
| 故障史 | 每个线上事故固化一个回归用例（写路径分叉、watcher 漏刷新……） | 同类事故复发 |
| 集成补盲 | core 纯库化后：watcher 事件循环、并发双写、写中途 kill（tmp 残留不污染扫描）——tempfile 真实工作区跑 | 事件循环零覆盖、故障注入空白 |
| 解析器 | **fuzz**（cargo-fuzz 跑 frontmatter 解析器） | 输入边界崩溃 |
| GUI | tauri-driver/WebDriver 冒烟脚本，把「零破坏回归清单」自动化 | 全手测不可持续 |
| 性能 | 基准套件：布局收敛 / 千节点扫描 / 全库重嵌 | 性能回归 |

## 6 · 可观测性

- **tracing 单点接入，三出口**：GUI 状态栏 / MCP stderr / 工作区 `.chain/logs/` 滚动文件；
- **指标采集**（反哺记忆层）：工具调用延迟、检索命中率（→ ACT-R 衰减指数 d 的校准数据）、CONFLICT 计数、线索缺口清单——"数据回归再调参"由此落地，否则是空话；
- **排障路径**：先要日志文件，再要截图。

---

## 7 · 安全模型（HTTP 接入前强制）

- 威胁模型文档：数据属地、信任边界（本机可信 / 经转发半可信 / 云端不可信）、攻击面清单；
- token 生命周期：生成（本机随机）、存储（OS 凭据库，不落明文）、轮换、吊销；
- 默认只绑 localhost；路径穿越回归清单进 CI；
- 供应链：`cargo-audit` + `cargo-deny`（许可证白名单 MIT/Apache-2.0/BSD）+ 新依赖"为什么不自己写"清单。

## 9 · 明确不做什么

| 诱惑 | 判定 |
|---|---|
| 微服务 / 进程拆分 / 守护进程 | 不碰——单写域由文件锁保证；统计争用实测出现才重议 |
| 插件系统 | 不碰——双模式用 profile 配置解决 |
| 事件溯源 | 不碰——git 历史 + stats.json 已够 |
| 自建向量数据库 | 不碰——嵌入式库或暴力余弦（节点 ≤ 数千量级） |
| 神经网络训练 | 不需要——embedding 用预训练模型推理；4.3 微调有门槛且大概率永远用不上 |

> 触发：曲线调色；调色工具初版；直方图提取；亮度曲线；RGB 颜色曲线；抓帧预览

## 目的

把《曲线调色·一页读懂》笔记里的调色流程落到一个可操作的工具上：**抓一帧游戏画面 → 看它的直方图 → 用亮度/RGB 曲线调它 → 实时看到调节效果**。

这是风格化后处理器的**前置阶段**：先把「什么样的参数能调出什么效果」验证清楚，再谈怎么实时化（实时化见后续设计，需要 LUT + 渲染管线接入）。

## 原则清单

| 类型 | 内容 |
|---|---|
| **目标原则** | 能抓到帧并预览；能提取亮度 + R/G/B 直方图；能调曲线并实时预览 |
| **约束原则** | 纯编辑器工具，不进构建产物；不接入渲染管线；不改动项目现有资产 |
| **边界原则** | 不做局部调整（选区/蒙版）；不做色相饱和度曲线；不做自动参数推导；不做 URP 接入 |

## 关键设计决策

### 1. 曲线作用于「显示域（sRGB）」，不是线性空间

**这是本设计最重要的判断。** 笔记的语义是照片编辑器语义：

- 「把一张照片最暗到最亮排序」= 感知亮度排序
- 「左边暗部、中间不暗不亮、右侧亮部」= sRGB/显示域的影调区间
- 「S 曲线去灰」= Photoshop 的那条 S 曲线

若在线性空间做曲线，同样形状的 S 曲线会得到完全不同结果，**笔记里的全部经验法则失效**。

### 2. 亮度曲线用「增益」而非直接映射

直接映射会把像素感知亮度强行改成曲线值，造成**色相漂移**。改为：

```
查表得目标亮度 y1 = curve(y0)，增益 g = y1 / y0，RGB 同乘 g
```

既让 S 曲线的去灰效果成立，又不让画面整体偏色。

### 3. 颜色曲线用显示域直接映射

等价于 Photoshop 的通道曲线。「皮肤黄加蓝」「水往青」「夕阳氛围」这类操作都是通道曲线的直接应用。

### 4. CPU 逐像素，不上 GPU

抓的是静态帧，没有帧率压力。CPU 版本能直接打印数值调试，GPU 做不到。**换 GPU 的时机是将来接入实时渲染时**，届时调色数学不变，只换执行层。

### 5. 直方图必须显示「调节前 / 调节后」两条

只有前后对比，才能验证笔记的法则：加暗部后右侧峰值应**向左移动**；S 曲线去灰后中间应**向两侧分开成双峰**。看不出这个位移，就无法判断调节是否真的起了作用。

### 6. 性能：预计算 256 项查表，杜绝逐像素 Pow

200 万像素 × 3 通道做 sRGB→线性 Pow 会明显卡顿。改为整条链路只用 256 项查找表。

## 交付位置（TA_show 项目）

```
Assets/Project/Editor/CurveGrading/
├── CurveGradeHistogram.cs   直方图计算 + 绘制
├── CurveGradeProcessor.cs   调色数学（CPU 逐像素）
└── CurveGradeWindow.cs      主窗口（抓帧 / 预览 / 曲线 / 预设）
```

打开方式：菜单 `TA_Show → 曲线调色工具`（快捷键 Ctrl+Shift+G）。

## 明确排除

| 排除项 | 理由 |
|---|---|
| 局部调整（只调沙滩） | 需要选区/蒙版机制，独立课题 |
| 色相/饱和度曲线 | 笔记只提亮度 + RGB 三通道，先严格对齐 |
| 参数自动推导 | 属于自动调色，初版要的是手动闭环 |
| URP 接入 / LUT 烘焙 / 多参考帧 | 属下一阶段 |

> 触发：用工具链建个模型试试；天空之柱；宝可梦建模；实战验证工具链

**类型：设计　状态：已落地**

## 为什么用"天空之柱"

工具链做完了需要**真实压力测试**——不是再跑一遍自测脚本，而是拿一个真有要求的建模任务去用。宝可梦《欧米伽红宝石/阿尔法蓝宝石》的**天空之柱**是个好题目：

- 有明确的**设定约束**（可判断对错）：柱状高塔、内部多层迷宫、贯穿塔高的壁画、顶层是烈空坐栖息地。
- 有**足够的复杂度**：塔身收分、装饰带、入口拱门、顶部开口、内部结构。
- 能同时压到**几乎所有工具**：创建、变换、修改器、布尔、材质、渲染、导出。

## 设定拆解为几何

| 设定 | 几何对应 |
|---|---|
| 高耸入云的柱状高塔 | 高 80、底半径 9.1（细长比 8.8）的 24 边形锥筒 |
| 内部多层迷宫（50 层） | 楼板间距 1.561，共 50 层 |
| 贯穿塔高的巨型壁画 | 贴 -X 侧内壁的弧形衬板 + 蜿蜒浮雕 + 两颗宝珠 |
| 顶层是烈空坐栖息地 | 顶部 6 个拱形开口构成的柱廊 |
| 入口藏于黑色缺口 | 底部拱形门洞，切穿 1.2 壁厚 |
| 50 层的外部表达 | 9 道装饰带（每 5 层一道） |

## 交付形态

一式两件：**完整塔**（看外形）+ **剖面塔**（看内部），并排摆放便于对照。

## 这场实战的最大价值

它抓到的 5 个工具缺陷里，有 3 个是自测脚本永远不会碰到的——**真实使用才能暴露"我以为的 API 行为"与"实际行为"的差异**。详见「设计 · 实战暴露的工具链缺陷必须收敛」。

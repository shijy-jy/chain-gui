> 触发：工具用着出问题了怎么办；插件 bug；修根因还是绕过；工具链可靠性

**类型：设计　状态：已落地**

## 原则

自由建模的前提是**工具可信**。建模过程中一旦发现工具行为与文档/直觉不符，必须停下来查根因：

- **不接受"绕过就行"**：绕过一次，下次还会踩；绕过的代价会累积进每一次建模。
- **失败要定格**：出错的现场（错误信息、实测数据、错误假设）必须记录，不能悄悄改掉当没发生。
- **修完必须复验**：不是"改完看起来对了"，而是用当初失败的那个操作重新跑一遍。

## 本次实战暴露的缺陷清单

| # | 缺陷 | 根因类别 |
|---|---|---|
| 1 | `create_object` 忽略基础体的 `name` 参数 | 代码遗漏，且 e2e 测试覆盖不足 |
| 2 | `top` 视图渲染结果旋转 180° | 用了有歧义的 `to_track_quat` |
| 3 | `SMOOTH_BY_ANGLE` 修改器类型在 Blender 5.2 不存在 | 基于过时 API 假设 |
| 4 | `create_object` 回报的 `dimensions` 是过期缓存 | 缺 depsgraph 更新 |
| 5 | 带 .blend 参数启动时桥不自动监听 | 非持久定时器被文件加载清除 |

**#5 最危险**：表现是"Blender 开着、插件也启用了，但端口就是不监听"——看起来像环境问题，实际是代码缺陷。我最初误判成端口 TIME_WAIT，加了重试也没用才找到真因。

## 教训

缺陷 #1、#3、#4 都是**"我以为的 API 行为"与"实际行为"不符**。这类缺陷靠读代码发现不了，只能靠**真实使用**暴露。

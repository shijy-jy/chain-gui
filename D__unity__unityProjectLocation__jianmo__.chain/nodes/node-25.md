> 触发：VMD；MMD 动作；骨骼重映射；retarget；骨骼名翻译；MMD Tools 字典；dictionary_folder

**类型：方法（可复用流程）**

把别人做的 MMD 动作（VMD）套到这个模型上的完整方案。**已经跑通并逐项验证。**

## 一、核心发现：这个骨架本来就按 MMD Tools 的译名体系命名

MMD Tools 有一个**骨骼名字典系统**（`translations.py` 的 `MMDTranslator` + `DictionaryEnum`），VMD 导入时可选一份 CSV 做翻译。

翻译流程（`core/vmd/importer.py:52-60`）：
```
VMD 日文名 → convertNameToLR() 转左右 → 查字典做子串替换 → 在 pose.bones 里找同名
```
而字典是**按串长降序做子串替换**（`translations.py:295-298, 373`），不是整名映射。

于是：`左腕` → `腕_L` → `腕`替换成`Arm` → `Arm_L`。
**这恰好就是 UmaViewer 给这个模型的命名方式**（`Arm_L` / `Elbow_L` / `Knee_L` / `Ankle_L` / `Head` / `Neck` / `Waist`）。

**实测：26 条标准轨道里 15 条开箱即用，不需要任何配置。**

## 二、缺的 11 条 + 自定义字典

缺的：`全ての親` `センター` `グルーブ` `上半身` `上半身2` `下半身` `腰` `左足/右足` `左足ＩＫ/右足ＩＫ` `左目/右目/両目` `あご`

补法：写一份自定义 CSV，放进 MMD Tools 的 `Preferences → dictionary_folder`，导入时 `dictionary` 选它。
**注意：自定义字典会整体替换内建字典，必须写全。**

**坑：字典不能一对多。** `importer.py:470` 有
```python
assert bone_name_table.get(bone.name, name) == name
```
两个 VMD 名映射到同一根骨 → **AssertionError 直接崩溃**。所以 `腰` 和 `下半身` 只能留一个（选 `下半身`→`Hip`）。

**坑：替换顺序。** `足ＩＫ_L` 必须排在 `足_L` 前面，`足首_L`/`手首_L` 必须排在 `首` 前面，否则会被吃坏。CSV 已按串长降序排好。

产出的字典：`blender-mcp/mmd_dict/shikageki.csv`，实测 **25/26 命中**。

## 三、骨架改造（必须做）

### 1. 加 MMD 兼容层
- 新增 `Center`（挂在 `Position` 下）承接 `センター`
- `Hip` 改挂到 `Center` 下
- 新增 `LegIK_L/R`（挂在 **`Position`** 下，不是 `Center`）承接 `足ＩＫ`
- IK 约束的 target 从空物体改为骨骼 `LegIK_L/R`

**为什么腿 IK 靶要挂在 Position 而不是 Center**：MMD 里 `足ＩＫ` 是 `全ての親` 的子级，所以 `センター` 移动身体时脚不动、腿自动弯曲。挂在 `Center` 下就会跟着走，脚就锁不住了。

静止网格**逐位不变**（改父级/加骨不影响绑定姿势）。

### 2. 修骨骼朝向 —— 这是最关键的一步

`BoneConverter.convert_rotation` 是 `result = q @ rot @ q*`，`q` 由**目标骨骼自己的 `matrix_local`** 导出。所以**骨骼的静止朝向必须符合 MMD 约定**，否则同一个 VMD 旋转会落到错的轴上。

MMD 标准朝向：`センター/上半身/首/頭` 朝上、`下半身/足/ひざ` 朝下、`肩/腕/ひじ/手首` 朝外、`足首` 朝脚尖。

实测这个模型的偏差：
| 骨骼 | 原朝向 | 改成 |
|---|---|---|
| `Head` | **朝下**（head z0.2697 → tail z0.2223）| 朝上 |
| `Ankle_L/R` | **朝上** | 朝脚部权重质心（前下） |
| `Hip` | 朝后上 (0,0.824,0.567) | 朝下 (0,0,-1) |

改朝向**不影响绑定姿势**（静止时形变恒等），但会改变局部轴 → **已有的手工 K 帧和头发烘焙都要重做**。
`Head` 翻向后其局部轴与 `Neck` 完全一致，正是 MMD 约定。

### 3. 脚掌水平锁定会打架
为手工 K 帧加的 `Ankle_L/R` 世界空间 `COPY_ROTATION`（target 是 `Foot_Rot_L/R` 空物体，influence=1）**会完全覆盖 MMD 的「足首」轨道**。
→ 套 VMD 前必须把 influence 设为 0，见 `import_vmd.py` 的 `set_foot_leveling(False)`。
（不能用 `mix_mode='ADD'` 代替：ADD 会把小腿的旋转也加进去，脚就不水平了。）

## 四、方向验证（容易搞错的地方）

**MMD 是左手坐标系。** 实测：VMD 里 `頭` 绕 **+X** 旋转 20°，在这个模型上表现为**绕世界 X 的 −20°**，即**抬头（后仰）**。
**`+X` 是抬头，`−X` 才是低头。** 我第一次写的测试动作把这个标反了，白追了一轮。

验证数据（低头 −20°）：眉毛质心位移 `(0, −0.0626, −0.0679)` = 前倾 + 下移 ✓，与手算的 −20° 世界X 旋转完全吻合。

## 五、端到端验证结果

| 轨道 | 实测 | 理论值 |
|---|---|---|
| `センター` | Center 位移 (0, **−0.32**, 0) | 4.0 × scale0.08 = 0.32 ✓ |
| `左足ＩＫ` | 踝L 位移 (0, 0, **0.24**)，膝盖正确弯曲 | 3.0 × 0.08 = 0.24 ✓ |
| `左腕` | 腕 (+0.051, 0, +0.262) | ✓ |
| `頭` | 眉位移量 = 半径 × sin20° | ✓ 精确 |
| `上半身` | Chest 位置随扭腰变化 | ✓ |

**`scale` 必须与模型导入时一致（本仓库是 0.08），否则位移整体缩放错。** 旋转不受影响。

- 字典不能一对多（`importer.py:470` 的 assert）
- `下半身`→`Hip` 已经占了骨盆

要完整支持需要再加 `Groove` 和 `Waist_Ctrl` 两层骨，并把 `Hip` 重新挂到 `Waist_Ctrl` 下。本仓库目前没做。

## 补充二：真实动作「看起来不对」的根因诊断

用户反馈：**骨骼没乱飞，但动作奇怪、和原 VMD 差得多。** 逐项排查后的结论 —— **不是映射错了，是模型体型撑不起这个动作。**

### 排查过程（可复用的方法）

**第一步：量每条轨道的旋转量**，找出动作主要在动什么。
结果：`左腕` 140°、`頭` 135°、`左ひじ` 135°、`下半身`/`上半身` 各 117°、`足ＩＫ` 位移 32 单位。

**第二步：查被丢弃的轨道到底有没有内容。**
`腰` 和 `グルーブ` 的**旋转全部是 0.0°**（最大也是 0）——它们只是恒等占位轨道。**丢弃它们零损失。**
> 教训：先量再下结论。按名字猜"丢了骨盆动作"是错的。

**第三步：查层级结构冲突。**
`上半身` 与 `下半身` 在 **全部 739 帧里逐位完全相同**（夹角 0.00°）。这是 MMD 的标准手法：两根骨的局部坐标系上下相反，同一个四元数产生"上半身前倾、骨盆反向"的铰链效果。
**前提是它们在 MMD 里是兄弟关系**；而本模型 `Hip`(下半身) 是 `Waist`(上半身) 的**父级** → 同一旋转被叠了两层。
- 修正：把 `Waist` 改挂到 `Center` 下，与 `Hip` 平级
- 实测影响：躯干相对竖直的倾角 中位 20.0°→16.5°、最大 48.9°→37.8°（**都不是致命量级**）
- 注意：`上半身` 世界转角曾测到 172.7°，一度误判「躯干翻过去了」——实际那是**绕竖直轴的扭转**，倾角中位只有 20°。**角度大 ≠ 姿态错，要分解成倾角/扭转分别看。**

**第四步（真正的病根）：量 IK 是否够得着。**

```
IK目标需要伸展比 = |IK目标 − 大腿根| / 腿全长
```
`>1.0` 就意味着腿够不着，只能笔直伸向目标，脚**不在动画指定的位置**。

| | 修正前 | 修正后 |
|---|---|---|
| 够不着的帧占比 | **64.5%** | **8.1%** |
| 伸展比 中位 / 最大 | 1.23 / **4.28** | 0.94 / 1.08 |
| 膝关节夹角 中位（0=伸直） | **0.3°** | **39.9°** |
| IK 误差 中位 | 0.043 | **0.000** |
| 身体行程 | 2.00 | 0.40 |

**根因算术**：这个模型腿长 **0.189**（占身高 16%，是个头大短腿的比例）；动作是为 TDA 风格正常比例模型（腿约占身高 50%）做的。腿相对这个动作**短了约 4 倍**，所以 64% 的时间里腿被拉直去够一个够不到的目标。

### 修复：缩放位移轨道

**`import_vmd` 的 `scale` 参数行为不可靠** —— 传 0.02 时位移轨道数值全变 0（轨道存在但值为零），且连续多次导入到同一 action 会**叠加关键帧**而不是替换。不要依赖它。

**可靠做法**：按 0.08 正常导入，然后**把全部 `*.location` 的 fcurve 关键帧值乘以系数 k**（旋转轨道不动，所以手臂/头/躯干动作完整保留）。

扫描结果（腿够不着占比 / 膝角中位）：

| k | 够不着% | 伸展比最大 | 膝角中位 | 身体行程 |
|---|---|---|---|---|
| 1.00 | 64.5 | 4.28 | 0.3° | 2.00 |
| 0.50 | 42.7 | 2.08 | 33.5° | 1.00 |
| 0.30 | 27.4 | 1.33 | 40.6° | 0.60 |
| **0.20** | **8.1** | **1.08** | **39.9°** | 0.40 |
| 0.10 | 12.9 | 1.05 | 35.9° | 0.20 |

**k=0.20 是最优点**：够不着降到 8.1%、IK 误差归零、膝盖真正开始弯曲。代价是身体行程从 2.00 缩到 0.40（约占身高 1/3），舞蹈变成偏原地。

**必须整体缩放所有位移**（`センター` 和 `足ＩＫ` 一起），只缩放其中一个会让腿的负担更重。

### 教训汇总

1. **「动作看起来不对」要从 IK 够不够得着入手量**，不要先怀疑映射。伸展比是最灵敏的指标。
2. **`scale` 参数别信**，直接对 fcurve 动手，结果可控可验证。
3. **连续导入同一个 action 会叠加关键帧**，测试时必须先 `animation_data_clear()`；否则会得出"参数没生效"的错误结论（我在这上面绕了两轮）。
4. **旋转角大不等于姿态错**；要分解成相对竖直的倾角去看。
5. 骨头名字对得上 ≠ 动作就对。**关节的物理可达性才是硬约束。**

## 补充三：用「真 MMD 模型」当基准做 A/B 对照

用户导入了一个**原生 MMD 模型 `猫耳永雏塔菲`**（437 骨 / 45674 顶点 / 222 刚体 / 335 关节）并套同一个 VMD，效果几乎无错。**它直接成了 ground truth** —— 之前靠推理没法定论的问题全都有答案了。

### 拿到了真实的 MMD 层级（一次定论）

```
全ての親 → センター → センター+ → センター++ → グルーブ → グルーブ+ → グルーブ++ → 腰
                                                                          ├ 上半身 → 上半身2 → 首 → 頭
                                                                          └ 下半身
```

**`上半身` 与 `下半身` 都是 `腰` 的子级 —— 是兄弟，不是父子。**
本模型原本把 `Hip`(下半身) 当作 `Waist`(上半身) 的父级 → 同一旋转被叠两层。**改挂 `Waist` 到 `Center` 是对的。**

真实朝向：`センター` **朝下**、`下半身` 朝下、`上半身/上半身2/首/頭` 朝上、`両目` 朝前。

### 揭示了塔菲为什么开箱即用

它的四肢骨叫 **`腕.R` / `足.L` / `ひざ.L` / `足首.L` / `親指０.R`**（**点号**后缀）。而 MMD Tools 的 `convertNameToLR("左腕")` 产出的正是 `腕.L` —— **精确命中，连字典都不需要**，`dictionary=DISABLED` 就能跑。

**结论：给模型补骨骼时，命名只要能被 `convertNameToLR` 命中即可，不必真叫日文。**

### 对照方法论（可复用）

**同一个 VMD 同时套在两个模型上，逐帧比较与缩放无关的内在量**：关节夹角、骨骼朝上轴相对竖直的倾角、方位角。

协调结果（各 38 个采样帧）：

| 指标 | 塔菲 | 诗歌剧 | 相关系数 |
|---|---|---|---|
| 胸腔倾角振幅 | 28.4° | 28.4° | **0.979** |
| 胸腔扭转振幅 | 200.7° | 199.7° | **1.000** |
| 头部倾角振幅 | 44.2° | 45.7° | **0.966** |
| 肘角 均值/标准差 | 52.4 / 23.6 | 50.9 / 23.2 | — |
| 膝角 均值/标准差 | 43.0 / 22.9 | 44.1 / 18.2 | — |

**手臂与躯干已经复现到几乎一致。**

### 两个害我绕路的度量陷阱

1. **「头到骨盆的向量」在大头短腿模型上不可比**。本模型头占身高 48%、腿占 16%，这个向量又短又偏，算出的倾角只有参照的一半，我一度误判「躯干幅度差一倍」。换成**骨骼自身朝向轴**（与骨骼位置无关）后完全吻合。
   → **跨模型比较必须用与体型无关的量。**

2. **MMD Tools 按 `帧号 + 场景当前帧` 写入动画**。塔菲那次导入时场景停在第 739 帧，所以动作落在 **739~1477**；我按 1~739 采样，看到的全是静止姿势（标准差 0.0），差点得出「新模型根本没动画」的错误结论。
   → **比较前先读 `action.frame_range`，按各自偏移对齐。**

## 补充四：把模型补成「和真 MMD 模型吃同一份 VMD」的完整结构

目标：让本模型和 `猫耳永雏塔菲` 对同一份 VMD 都能正确出动作。

### 已补的骨骼（静止网格逐位未变）

| 新增 | 作用 | 层级 |
|---|---|---|
| `Groove` | 承接 `グルーブ` | Center → Groove |

`全ての親 → センター → グルーブ → 腰 → { 上半身, 下半身 }` **逐级对应**。

眼球顶点迁移很干净：`M_Eye` 组 154 个顶点**精确按 x 正负各 77 个**分成左右，硬切即可，无需过渡带。

覆盖率 **22/54 → 28/54**。

### ❌ 手指补不了 —— 网格根本没有手指几何

下结论前做了四道检验，全部指向同一结论：

1. **尺寸**：手部包围盒 0.077(长) × 0.096(宽) × 0.080(高)。**宽 > 长**，是拳套形状不是手掌。
2. **薄带扫描**（带宽 0.010，沿手臂轴）：合理阈值（间隙 0.012 / 最少 3 点）下**簇数最多 3，从未到 4**。
   之前显示 4 簇是因为用了更松的阈值（间隙 0.008 / 最少 2 点），把噪声算成了簇。
3. **直方图**：指尖区 y 从 −0.036 到 +0.051 **连续分布，没有干净间隙**。
4. **反证**：我们的「指尖跨度」0.087 **比参照模型四指的跨度 0.055 还宽**，而我们的模型还更小
   （参照骨骼间距：人指 −0.024 / 中指 −0.005 / 薬指 +0.013 / 小指 +0.031）。

**硬加手指骨只会把一整块网格揉成软塌塌的形状，比保持刚性更糟。** 所以四指 24 条轨道故意不映射。
拇指有真实几何（`Thumb_01_L` 312 顶点、`Thumb_03_L` 62 顶点），所以 `親指０/１` 接上了。

> **教训：补骨骼前必须先验证网格里有没有对应的几何。** 只看骨骼名缺失就动手，会做出比原来更差的结果。

### 最终 A/B 对照（38 采样帧，与 塔菲 逐帧比）

| 指标 | 塔菲 | 诗歌剧 | 相关系数 |
|---|---|---|---|
| 胸腔倾角振幅 | 28.4° | 28.4° | **0.976** |
| 胸腔扭转振幅 | 227.3° | 226.3° | **1.000** |
| 肘角振幅 | 90.8° | 85.1° | **0.999** |
| 头部倾角振幅 | 51.4° | 47.6° | **0.963** |
| 膝角振幅 | 101.6° | 88.3° | **0.845** |

**躯干和手臂已经一致到 0.98~1.00。** 膝盖 0.845 偏低，是因为 k=0.2 仍有约 8% 的帧腿够不着
（k 越小频率越准但身体行程越短，这是取舍）。

### 一个必须知道的取舍

**两个模型需要不同的位移缩放 k**：
- **塔菲（原生 MMD 模型）**：k = 1.0 就是它作者设计的动作
- **诗歌剧（大头短腿）**：必须 k = 0.2，否则腿够不着脚 IK 目标（64% 的帧腿被拉直）

两个 k 都是各自「正确」的，但同一份 VMD 在两者身上产生的**位移距离不同**。
要同场景并排播放，必须统一 k（本次并排视频两边都用了 0.2，塔菲那侧是被缩小的）。

根因是**体型比例**：本模型腿占身高 16%，动作是按腿占 50% 的模型设计的。这不是映射能修的。

## 补充五：腿「向左侧扭转」的根因与修复

**用户反馈**：腿一直朝角色左侧扭，整个膝盖方向不对。

### 诊断（量出来的，不是猜的）

| 膝盖偏移方向（世界） | 塔菲（基准） | 诗歌剧（修复前） |
|---|---|---|
| X（左右） | 0.074 | **0.875** ← 强烈偏左 |
| Y（前后） | **−0.868** | −0.171 |

塔菲的膝盖主要**朝前**，本模型主要**朝左** ✓ 用户观察准确。
同时极向点相对骨盆固定在 X=+0.78 从不移动。

### 根因：极向目标不跟随角色

`IK_Pole_L/R` 是**世界空间**的空物体，位置在 `膝盖 + (0, −0.45, 0)`，是静止姿势时算的。
角色一移动（舞蹈行进 0.4~2.0 单位）、一转身，极向点就落到身体侧后方，**膝盖弯曲平面被整个拽歪**。

> 另外：上一版并排视频里我把诗歌剧的根节点移到 x=−0.72，**却没移动世界空间的极向点**，
> 直接把它甩到身体左侧 0.78 —— 那一版的问题有相当一部分是我自己造成的。
> 但即使不移位，角色本身的位移也会让极向点失效，**这是真实的脆弱点。**

### 修复：给极向空物体加 `Child Of` 约束跟随骨盆

```python
c = empty.constraints.new('CHILD_OF')
c.target = arm; c.subtarget = "Hip"          # 骨盆骨
c.inverse_matrix = (arm.matrix_world @ arm.data.bones["Hip"].matrix_local).inverted()
```
`inverse_matrix` 必须用**静止姿势**的骨盆矩阵，这样静止时极向点位置不变、之后随骨盆一起动。
**挂在 `Hip`（下半身）而不是 `Center`**：膝盖的弯曲平面由骨盆决定，不由センター决定。

### 结果

| 膝偏移方向 | 塔菲 | 修复前 | 修复后 |
|---|---|---|---|
| X（左右） | 0.074 | 0.875 | **−0.205** |
| Y（前后） | −0.868 | −0.171 | **−0.734** |

从「侧扭」回到「基本朝前」（偏离正前约 16°，塔菲约 5°）。

## 补充六：验证渲染必须带贴图

**Workbench 的 `color_type='MATERIAL'` 对本模型毫无用处** —— 本模型的 MMD 材质参数层全是默认值
（`diffuse_color` = 白），所以显示出来一片灰白。实测三种模式：

| color_type | 结果 |
|---|---|
| `MATERIAL` | 全灰（156/132/108/84），等于没材质 |
| `OBJECT` | 全灰，同上 |
| **`TEXTURE`** | **正常显示贴图**（暖棕 60,36,36 / 84,60,60 / 108,84,84）|

**结论：快速验证渲染一律用 `scene.display.shading.color_type = 'TEXTURE'`**，配合
`engine='BLENDER_WORKBENCH'` + `bpy.ops.render.opengl(animation=True)`，既带贴图又有 0.02 秒/帧的速度。

（EEVEE 单帧 3.4 秒，739 帧要 42 分钟；Workbench+TEXTURE 是 739 帧 40 秒。）

## ✅ 结案：用户确认效果「几乎一模一样」

**这套重映射方案已验证可用。** 给本仓库任何「非标准 MMD 骨架」的模型套 VMD，照这条流程走：

1. `pmx_probe.py` 先读源文件，搞清它到底有什么（IK/morph/物理）
2. 查 MMD Tools 内建译名能否命中（`convertNameToLR` 产出什么，模型骨骼就叫什么最省事）
3. 补层级层：`Position → Center → Groove → Waist_Ctrl → { Waist, Hip }`
4. **核对骨骼静止朝向**是否符合 MMD 约定 —— 这是最容易漏、后果最大的一步
5. 腿 IK 的极向目标**必须跟随骨盆**（`Child Of` → `Hip`），否则角色一移动膝盖就侧扭
6. 量「IK 目标伸展比」判断腿够不够得着；够不着就按比例缩放全部位移轨道
7. 用真 MMD 模型做 A/B 对照（关节角 + 骨骼朝向轴，**不要用头到骨盆的向量**）
8. 验证渲染用 `Workbench + color_type='TEXTURE'`

> 触发：诗歌剧；マチカネタンホイザ；赛马娘模型分析；MMD 模型拆解；骨骼权重

**类型：参考（资产分析）**

对 `models/character.blend` 场景里的 MMD 模型 `诗歌剧.1` 做的全面拆解。所有数字都是实测。

## 结构

```
诗歌剧.1        EMPTY（根）
└─ 诗歌剧.1_arm   ARMATURE（178 骨）
   └─ 诗歌剧.1_mesh  MESH（19951 顶点）
```
三层变换全为单位矩阵——导入很干净。

| 松散顶点 | 0 |

**高度分区**：z −0.256~+0.238 是**身体**（`mbdy` 占 83~96%）；z +0.238~+0.928 全是**头发**（`hair` 占 57~100%）。即身体高 0.494、头发高 0.690——**头发占了模型总高的 58%**。

## 材质

8 个材质，面分布高度不均：**身体占 68.7%、头发 22.3%**，两者合计 91%；脸 4.9%、尾巴 2.0%、眼 1.1%、嘴 0.4%、眉毛各 0.3%。

**节点结构统一**（每个材质都是）：
```
Material Output.Surface ← mmd_shader.Shader        （节点组 MMDShaderDev）
                          ├─ Base Tex  ← mmd_base_tex.Color
                          ├─ Base Alpha ← mmd_base_tex.Alpha
                          └─ mmd_base_tex.Vector ← mmd_tex_uv.Base UV  （节点组 MMDTexUV）
```

**没有 Principled BSDF**——`MMDShaderDev` 内部是手工搭的 diffuse + glossy + transparent 混合（6 MIX_RGB / 7 MATH / 1 Geometry），这是 MMD 的经典外观。

`MMDShaderDev` 有 **16 个输入，只接了 2 个**（Base Tex / Base Alpha）。Toon Tex、Sphere Tex、Diffuse Color、Specular Color 全未接线，走默认值。

**贴图**：7 张漫反射贴图，全部存在于磁盘、**全部未打包进 .blend**（依赖桌面绝对路径）。材质没有任何 toon / sphere 贴图。

## 骨骼

| 指标 | 值 |
|---|---|
| 骨骼数 | **178**，**全部 use_deform**（0 非形变） |
| 根 | **只有 1 根**：`Position` |
| 最大深度 / 叶骨 | 10 / 81 |
| **约束** | **0 条——没有任何 IK** |
| 命名 | 游戏内部体系（`Hip` / `Thigh_L` / `Sp_Hi_MSkirt13` / `M_Eye`），非 MMD 日文标准 |

**权重是干净的**：全部 19951 个顶点的蒙皮权重和恰好 = 1.0，每顶点 3~4 根骨骼，0 个未蒙皮顶点。

## 五个必须知道的坑

1. **`is_built: false` + 0 约束**：模型有 27 根名字带 `_IK_` / `_Handle` 的骨骼（`Ankle_L_Handle`、`Knee_L_Handle`…），但**一根 IK 约束都没有**。腿部目前只能用 `Thigh/Knee/Ankle` 手动旋转，IK 待 MMD Tools 的 Build 步骤生成。

2. **两个 MMD 数据通道伪装成顶点组**：`mmd_edge_scale`（19951 顶点权重全是 1.0）和 `mmd_vertex_order`（编码 0~0.9999 的顶点序号）。
   - **任何"最大权重所在组"的分析都会被它们带偏**——我第一轮就误判了
   - **导出到 Unity/UE 时它们是额外权重**，会挤爆 4 骨骼上限或产生垃圾蒙皮

3. **`M_*` 面部骨骼全部堆在同一点**：`M_Cheek` / `M_Eye` / `M_Mayu_L` / `M_Mayu_R` / `M_Mouth` 的 head **完全相同**（0, 0.0129, 0.2223，即颈根）。眼睛、眉毛、嘴的顶点离自己的骨骼 0.19~0.33——**旋转它们会让五官绕颈根划大弧**。设计上更像 morph 驱动骨，但本模型 morph 数为 0。

4. **`Head` 骨骼朝下**：head (0,0.0091,0.2697) → tail (0,0.0129,0.2223)，与 `Neck` 正好反向且等长。欧拉旋转的轴向会与直觉相反。

5. **2217 个连通块**：高度碎片化（平均每块 7.6 个三角面），是 MMD Tools 按法线/UV 拆分顶点的结果。好处是硬边锐利；代价是**顶点复用率低**（1.18 顶点/面，理想闭合网格约 0.5），影响蒙皮平滑度与文件体积。

## 其他

- 贴图目录里有 8 张图，但材质只引用 7 张——`tex_mchr0001_00_face0_1_cheek0.png`（脸红贴图，10KB）**未被使用**，对应缺失的脸红 morph

## 补充实测：碎片化程度（连通块深挖）

第一轮只报了"2217 个连通块"，深挖后数字比预想严重：

| 指标 | 值 |
|---|---|
| 连通块总数 | **2217** |
| **最大连通块** | **仅 357 顶点 = 全模型的 1.8%** |
| 前 10 大块 | 357 / 299 / 218 / 209 / 209 / 158 / 156 / 155 / 155 / 118 |
| 小于 10 顶点的块 | **1751 个**（占 79%） |
| 单顶点孤块 | 0 |
| **边界边**（只属于 1 个面） | **18668 / 34663 = 53.9%** |
| 非流形边（>2 面） | **0** |

**欧拉示性数交叉验证**：V − E + F = 19951 − 34663 + 16886 = **2174**，与"2217 个盘状拓扑壳"的理论值 2217 只差 43。两种独立算法互相印证，碎片化是真实的，不是统计错误。

**结论：这个模型没有任何"主体外壳"**——身体、脸、头发全都是由几千个小补丁拼起来的。平均每块 9 个顶点 / 7.6 个三角面。

**成因**：MMD Tools 在法线或 UV 不连续处拆分顶点（PMX 按顶点存法线/UV，没有索引共享）。对于动漫风格的硬边模型，几乎每条硬边都会产生拆分。

**后果**（建模层面最需要知道的一条）：
- 网格**不封闭**，没有内外之分 → 布尔、solidify、ray_cast 内外判定全部不可靠
- 平滑着色**不能跨块生效**，着色完全依赖已有的自定义法线
- 权重必须逐个副本刷，且导入引擎后若引擎重算法线会出现裂缝
- 顶点复用率 1.18 顶点/面（理想闭合网格约 0.5），文件体积偏大

**这不是缺陷，是 MMD 资产的标准形态**——但如果要拿它去做雕刻、重拓扑或物理碰撞，必须先 merge by distance。

## ⚠️ 更正：蒙皮影响数（原报告写错了）

原报告写"每顶点 3~4 根骨骼影响"——**这是错的**。那个数字把 `mmd_edge_scale` 和 `mmd_vertex_order` 两个数据顶点组一起算进去了。

PMX 二进制 + Blender 双向核实的真值：

| 影响骨骼数 | 顶点数 | 占比 |
|---|---|---|
| **1**（PMX 权重类型 BDEF1） | 7873 | **39.5%** |
| **2**（PMX 权重类型 BDEF2） | 12078 | **60.5%** |
| ≥3 | **0** | **0%** |

两个独立来源完全吻合：`pmx_probe.py` 读出的权重类型分布是 `{0: 7873, 1: 12078}`；Blender 里排除两个数据组后的直方图同样是 `{1: 7873, 2: 12078}`。

**没有 BDEF4，也没有 SDEF。**

意义（对动画是硬约束，不是调参能解决的）：
- 这是**游戏模型的刚性蒙皮**，不是 MMD 常见的 4 权重平滑蒙皮
- 关节弯折会出现硬转折
- **没有 SDEF** —— 膝关节/肘关节缺少球面补偿，弯曲到一定角度会塌陷、穿插
- 这也解释了为什么模型碎片化严重（2217 块）：游戏引擎按材质和法线硬切，靠骨骼少、贴图补

其余原报告结论不变：权重和全部精确 = 1.0、0 个未蒙皮顶点、0 条约束、0 条 IK。

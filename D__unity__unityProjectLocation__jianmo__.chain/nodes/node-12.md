> 触发：启动器验收；幂等测试；停止流程；MCP 重连

**类型：验收　状态：通过**

## 验了什么

| 场景 | 操作 | 结果 |
|---|---|---|
| 全停冷启动 | 双击 `start.bat` | 视觉引擎 + Blender 全部就绪，**24.4s** |
| 幂等 | 已就绪时再次 `start` | 两个组件都报"已在运行"，不起第二份 ✅ |
| 定向启动 | `start -Target vision` | 只起视觉引擎；**汇总如实报告 Blender 的状态**，不再谎报"全部就绪" ✅ |
| 全停 | `stop` | Blender **正常退出**（会弹保存确认框，不硬杀），视觉引擎停止 ✅ |
| 停机后状态 | `status` | 两项都报"未就绪" ✅ |
| 重启 | `restart -Target blender -BlendFile ...` | 带模型重启并重新就绪 ✅ |

## 韧性验收（顺带做的，很重要）

Blender 重启后，DSH 侧那个 MCP 服务端手里**还攥着旧 socket**。实测 `mcp__blender__status` **自动重连成功并返回新 pid**——`BlenderBridge` 的断线丢弃 + 重试逻辑是对的。

**结论：重启 Blender 后工具照常用，用户不需要重启 DSH。**

## 抓到的缺陷

调试过程中发现 4 个（见「任务 · 封装一键启停与状态体检」试错记录）：漏声明参数、取错 JSON 层级、`ReadKey` 挂死、汇总逻辑谎报。

## 剩余问题

当时"带文件启动"这条路径**看似通过**（重启验证时 Blender 正好没带文件参数），实际藏着缺陷 5。是后来建模时用 `-BlendFile` 才暴露的——**测试矩阵没覆盖"带文件启动"这个组合**。

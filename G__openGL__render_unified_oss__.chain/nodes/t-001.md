> 触发：VS2026 Release 调试配置

# 要做什么

在 VS2026（CMake 工程）里用 **Release 优化级别调试**：

1. `CMakeSettings.json` 增加 `x64-Release` 配置（当前只有 x64-Debug）
2. Release 构建保留调试符号：MSVC `/Zi` + `/DEBUG:FULL`，nvcc `-g -lineinfo`
3. 可选核函数内断点：新增 CMake 选项 `RENDER_UNIFIED_CUDA_DEVICE_DEBUG`（相当于 nvcc `-G`，默认 OFF，避免拖慢正常 Release）

# 验收标准

- VS2026 配置下拉框出现 x64-Release，能构建、能命中主机代码断点、变量可查看
- 勾选 `RENDER_UNIFIED_CUDA_DEVICE_DEBUG` 后能在 .cu 核函数内断点（需装 Nsight VSE）
- CLI 的 `cmake -S . -B build && --build --config Release` 默认行为不变（不带 -G）

# 参考依据

- Nsight Visual Studio Edition 2026.2 发行说明：https://developer.nvidia.com/nsight-visual-studio-edition-2026_2-new-features
- FLAMEGPU2#798：CMake CUDA 各构建类型缺省 flag（-G 只对设备代码，-lineinfo 轻量行号）

# 实际做了什么

1. `CMakeLists.txt`：新增 `RENDER_UNIFIED_CUDA_DEVICE_DEBUG` 选项（默认 OFF）；MSVC 下对 Release/RelWithDebInfo 注入 `/Zi`（CXX）+ `-g`（CUDA 主机侧）+ 链接器 `/DEBUG:FULL`；DEVICE_DEBUG 关时对 CUDA 追加 `-lineinfo`，开时改追加 `-G`（两者不叠加）
2. `CMakeSettings.json`：新增 `x64-Release` 配置（Ninja + msvc_x64_x64），默认勾选 `RENDER_UNIFIED_CUDA_DEVICE_DEBUG=ON`，VS 的 CMake 设置界面里可直接切换
3. `README.md`：Build 节补充 VS2026 用法说明

# 验证结果（VS2026 Community 18 + MSVC 19.51 + CUDA 13.3.73 + Ninja，真实构建）

- **默认配置**（DEVICE_DEBUG=OFF，`build/verify-default`）：configure 成功；build.ninja 注入 `-lineinfo`×7、`/Zi`×21、`/DEBUG:FULL`×1，无 `-G` ✓
- **设备调试配置**（DEVICE_DEBUG=ON，`build/verify-g`）：29/29 全量编译+链接成功（exit 0）；产物 `render_unified.exe` + `render_unified.pdb`（15.9MB）+ `glew32.dll` + `models/` 齐备；build.ninja 注入 `-G`×7、`-lineinfo`×0（正确不叠加）✓
- CLI 发布构建默认行为不变（选项默认 OFF）✓

## 试错记录

- ⚠️ `CMakeLists.txt` 里 `set(CMAKE_CUDA_ARCHITECTURES 75 80 86 89)` 是普通 set，会覆盖命令行 `-DCMAKE_CUDA_ARCHITECTURES=89`（本想省验证时间失败，按真实四架构构建反而验证更充分）
- ⚠️ DEVICE_DEBUG=ON 构建时 `path_trace_gpu_backend.cu(1594)` 出现 warning #546-D（goto 跨过变量初始化），为既有代码问题，设备调试编译下才暴露；不影响产物，后续可修
- 🔑 关键点：`-G` 与 `-lineinfo` 不叠加（`-G` 已隐含设备行号），CMake 侧用 if 分支切换，避免 nvcc 冲突
- 📌 验证构建产物在 `build/verify-default/`、`build/verify-g/`（被 .gitignore 覆盖，可随时删除）

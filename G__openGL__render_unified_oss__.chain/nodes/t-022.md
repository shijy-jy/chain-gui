> 触发：评判链落盘；eval 核心 dump 协议

# 要做什么

d-012 最小闭环第一环：让"图像落盘"成为可执行能力，且核心可移植（零依赖 eval/ 目录）。

1. **eval/ 便携核心库**：`frame_dump.h/.cpp`（namespace evalcore，纯 C++17 标准库：
   writePFM/readPFM/writePPM/readPPM）+ `README.md` 集成契约（3 步接入、格式定义、
   submodule 用法、基线约定）。
2. **协议**：`--autotest <m> --passes N --dump <dir>`（lpCmdLine 子串解析；无新参数时
   行为与旧版完全一致）；passes 模式**独占**终止条件（不参与 10s 墙钟竞态）。
3. **IRenderBackend::dumpFrame(path)** 默认虚函数 + 四后端实现：
   PT CPU（accumBuffer_/currentPass_ 均值→PFM）、PT GPU（accum 模式 d_accum_ 同步回读→PFM，
   非 accum 回退本帧 radiance）、Raster CPU/GPU（RGBA8→PPM）。autotest --dump 在 arm 时
   强制 accum 模式；dump 完成后再 PostQuitMessage（顺序保证）。
4. CMakeLists：eval/frame_dump.cpp 入源、eval/ 入 include、frame_dump.h 挂 OBJECT_DEPENDS。

# 验收

- 四模式 `--passes 8 --dump` 各产出 1280×720 图（PPM 2764816B / PFM 11059217B，尺寸核对 ✓）
- 双跑位级验证：Raster CPU/GPU max_abs_diff=0 ✓；**PT CPU 实测不可位级复现**（见下）
- 全量编译 ✓（verify-nodebug）

# 重要发现（修正 d-012/review 文档）

**PT CPU 端到端不可位级复现**：同机同配置 --passes 1 双跑 max_abs_diff≈15~17、
PSNR 57.7~72.6dB、mean_rel_err≈1e-3、差异像素 ~0.4% 且集中于物体边缘区域；第三轮与
前两轮都不同（真随机，非双模态）。RNG 层（PCG32::setState 逐像素逐 pass）确定 →
根因候选：无序容器/目录遍历顺序、边缘 tie-breaking、未初始化 padding。**另立调查项**。
判定口径修正：Raster max_abs_diff=0（实测位级一致）；PT 双后端 PSNR≥50dB（余量 7.7dB）。

# 目标

采纳 d-008 评审的 8 条建议与规划书 v2 的三层同心圆框架，落地为**最小风险、可逐步验证**的迁移：
不动旧文件的功能语义，以"新增文件 + 新增接口 + 一次机械拆分"完成组织架构升级。

# 目标架构（目录不变，规则成文）

```
core/        稳定层：math/camera/timer
assets/      场景契约 scene.h + 加载器 + 材质定义（宿主侧平行数组扩展模式，t-008 先例）
shading/     BSDF 抽象 bsdf.h + 共享数学 microfacet + 预计算 LUT（每模型一文件）
backends/    积分器/光栅化器（新后端=新类）+ POD 镜像与转换单点
denoising/   每算法一文件（单向依赖：不 include backends/assets/app）
raster/      显示层落位（d-008 建议 1）：CUDA-GL interop，只被 app 装配调用
app/         装配 + UI 面板（拆分出 ui_panel）+ 崩溃诊断
契约清单     scene.h / render_backend.h / pt_gpu_scene_layout.h / raster_*_layout
            / bsdf_device.h —— 不搬家，用"清单 + static_assert 防线"管控（d-008 建议 4）
```

铁律：`core ← assets ← shading/backends ← denoising ← app`，仅允许上层 include 下层。

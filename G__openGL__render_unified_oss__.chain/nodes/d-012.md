> 回溯修改：按 v12 指南 v11 节散布代码骨架——评判体系概念的证据挂本节点（code_map: eval/frame_dump.cpp，可插拔核心的 C++ 侧）；不改变状态与结论（原 revision 3）。

# 背景

评审文档 `docx/render_unified_oss_eval_review_20260903.md` 判定：§7 回归口径目前只有
"文档政策"没有执行层——regress.ps1 只断言 exit 0 + 无 crash log（纯黑也能 PASS），
全工程无 dump/无指标/无基线。本设计把口径变成可执行的判定链，并满足用户的
**可插拔可移植**要求（其它渲染工程复用同一套评判）。

# 决策

1. **评判核心自包含**：零依赖目录 `eval/`（C++17 标准库 frame_dump 读写 PFM/PPM +
   Python3 标准库 compare.py + selftest.py + README 集成契约）。不 include 工程头、
   不依赖 CUDA/ImGui/平台 API。其它工程复制目录或 git submodule，3 步接入。
2. **胶水留工程内**：render_unified_oss 只加 `IRenderBackend::dumpFrame(path)` 默认
   虚函数 + 四后端小实现；判定逻辑全部在 eval/，换工程不换裁判。
3. **协议三钉子**（经代码复核修正）：
   - 分辨率：四后端已固定 1280×720 离屏渲染（RENDER_WIDTH/HEIGHT 常量、无 resize），
     跨机器基线可比性天然成立；640×640 降为远期可选提速项（t-027 --res）。
   - 终止条件：--passes N 替代墙钟秒数；语义分模式记录进 meta.json
     （CPU pass=独立样本，GPU 帧=ReSTIR 复用帧，样本相关）。
   - 取数点：线性 HDR、tone map 之前；PT CPU 取 accumBuffer_ 均值，PT GPU 取 accum
     模式 d_accum_（同步后回读），Raster 取 LDR 帧走像素级对比。
4. **阈值默认（t-022 实测修正）**：Raster CPU/GPU max_abs_diff=0（双跑位级一致 ✓）；
   PT CPU PSNR≥50dB（端到端不可位级复现：~0.4% 像素、边缘聚集、run-to-run
   57.7~72.6dB——RNG 层确定、像素层不确定，根因另立调查项）；PT GPU PSNR≥50dB
   （峰值钉死 max(reference)）。
5. **任务切片**：t-022（eval 核心+dump+协议）→ t-023（compare+selftest）→ t-024
   （基线+regress 接线）最小闭环；t-025 收敛曲线；t-026 场景（procedural OBJ 生成器，
   已拍板）；t-027 远期（FLIP/EXR 转换/HUD 落盘/Rec.709 统一/--res）。

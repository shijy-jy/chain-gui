> 触发：PBR 材质面板热更新

# 要做什么（路线 A 第一步，按 d-003 〇·三 决策）

1. **UI**：面板新增 Material 材质 分区——列出当前场景所有材质（名称/三角形使用数），选中后可编辑：
   baseColor 色板、roughness、metallic、emission（发光材质）、ior、isGlass/isMetal 开关，
   以及材质预设按钮（漫反射/金属/玻璃）；中文字形白名单同步补齐
2. **热更新通道**：改参 → 更新 `Application::scene_` → 四个后端轻量重传（不重建 BVH/后端）：
   - `IRenderBackend` 增加虚接口 `updateMaterial(index, Material)`
   - RasterGPU/PathTraceGPU：单个材质 cudaMemcpy 进 d_materials_
   - RasterCPU/PathTraceCPU：更新各自持有的场景副本
3. **v1 边界**：isEmissive 切换不做（需重建光源三角形列表）；只编辑"已经是发光材质"的 emission 值

# 实际做了什么

1. `IRenderBackend::updateMaterial` 虚接口 + 四后端实现（GPU 双后端单个 cudaMemcpy；
   CPU 双后端更新场景副本；PT 双后端顺带 resetAccumulation/firstFrame_ 使历史累积失效）
2. `Application`：`applyMaterialEdit`（场景 + 三指针别名安全分发）、Material 分区 UI
   （材质下拉 + 三角形使用数 + ColorEdit3(sRGB 面板→线性存储) + 粗糙度/金属度/发光/玻璃/金属开关/折射率 + 三个预设按钮）
3. 字形白名单追加"材质金属度粗糙度自发光颜色玻璃折射率漫反射预设基础三角形"
4. **陈旧编译产物守卫**：main.cpp 与 application.cpp 各记一份 sizeof(Application)，
   WinMain 启动比对，不一致弹明确错误——本环境 ninja depfile 会静默失效，
   t-003 的根因在 t-005 期间又复现了一次（见试错记录）

## 试错记录

- ⚠️ **t-003 的陈旧 TU 病在 t-005 期间复发**：加成员后我的构建目录 main.cpp.obj 未重编
  （8/31 15:31 vs 头文件 9/2 10:26），关窗 /GS 崩溃复现——根因实锤为
  **CMake/Ninja+MSVC 的 depfile 缺失**（main.cpp.obj.d 不存在），依赖 TU 静默跳过。
  修复：全量重建 + sizeof 守卫。教训：此环境下**头文件改动后必须确认依赖 TU 真的重编**
- ⚠️ 守卫实现踩坑：命名空间作用域的 `const int` 默认**内部链接**，跨 TU 引用必须
  `extern const int x = ...;` 定义（extern+初始化器 = 外部链接定义）
- 🔑 热更新语义：PT 后端参数变了要重置累积器（CPU: resetAccumulation, GPU: firstFrame_=true），
  否则新旧参数帧混平均

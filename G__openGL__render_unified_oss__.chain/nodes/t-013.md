# UI 缺字检测与修复

## 检测结果（ui_glyph_audit 工具，扫描全部 UI 源文件 + 按真实 initImGui 配置打包）

1. **打包无溢出**：4096² 图集在 15/22.5/30px（DPI 1.0/1.5/2.0）下均富余（30px 仅用 2048 高）——t-033 的全量 CJK 块教训不适用于当前"常用集+白名单"配置。
2. **26 个未声明字符**（源码用到但不在 Default+常用集+白名单内）：
   - 运行时真缺：帧/噪/敛（t-012 tooltip）、铝（预设按钮）、兜 等
   - 注释用字：俄(罗斯轮盘)/吻(合)/幽(灵)/徽(章)/拷(贝)/拽/曝/迭(代)/钮/馈/晰/拟/辑 等
   - 希腊/数学符号（Π α η π → ≈ ─，仅注释）

## 修复方案

1. initImGui 白名单重构为 **kUiZhTexts 单一事实源数组**（含 26 个缺口字符，注释用字保守覆盖），循环 AddText；"新增标签必须同步"的散落注释并入数组注释。
2. sanity check 升级：从 8 个关键字 → **白名单全量逐字 FindGlyph 检查**（缺字启动即报 U+XXXX）。
3. 图集尺寸兜底：查询 GL_MAX_TEXTURE_SIZE，≥8192 则 TexDesiredWidth=8192（更高 DPI 预留）。
4. ui_glyph_audit.cpp 白名单解析适配新数组格式；跑通后作为永久回归工具。

## 验收标准

1. ui_glyph_audit 复跑：0 not-declared、0 pack-missing。
2. 全量重建 + 四模式 autotest exit 0；启动日志 sanity 0 missing。

## 进度与结论

### 实际做了什么

1. **审计工具** `build/verify-models/ui_glyph_audit.cpp`：扫描全部 UI 源文件的非 ASCII 字符 → 解析白名单（kUiZhTexts 数组格式）→ 两级检查（范围声明 + 按真实 initImGui 配置在 15/22.5/30px × 4096/8192² 六组合下打包）。最终 **0 未声明 / 0 打包缺失**。
2. **修复的 34 个缺失字形**（常用集外，运行时真缺的：帧/噪/敛/铝/兜/尔 等；其余为注释用字保守覆盖）全部进白名单。
3. initImGui 白名单重构为 `kUiZhTexts` 单一事实源数组 + 循环 AddText；图集宽度按 GL_MAX_TEXTURE_SIZE 兜底 8192。
4. **sanity check 升级**：8 个关键字 → 白名单全量逐字检查，且改用 `FindGlyphNoFallback`。
5. **假阴性根因修正**：ImGui 1.91 起 `FindGlyph` 对缺失字形返回 fallback（永不 null）→ 旧的 t-004 glyph_check 与 sanity check 全是假阴性；glyph_check.cpp 同步修正（42 字重验 0 缺失，且检查真实有效）。

### 验证

- ui_glyph_audit：0/0 全绿（六组合）。
- glyph_check（NoFallback 版）：42 字 0 缺失。
- 全量重建通过 + 四模式 autotest exit 0（每次启动都执行新白名单构建与全量 sanity 检查）。

### 试错记录

- ⚠️ 工具自身的两处假象：① ImGui 1.91 `FindGlyph` 永远返回 fallback → 打包检查必须用 `FindGlyphNoFallback`（非 const 成员，调用处指针去 const）；② 工具向 AddText 喂白名单时用单字节截断（`char[4]` 存 ImWchar）→ 必须正确 UTF-8 编码。
- 📌 用户模型文件名仍依赖常用简体集（~2500 字），超出其范围的文件名会缺字——审计工具已覆盖，若将来支持任意生僻文件名需换全量 CJK 集 + 大图集。

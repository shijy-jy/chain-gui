> 触发：面板可拖拽分组 UI

# 要做什么

参考 UE5 材质实例编辑器 / Unity Inspector / Blender Principled 的惯例优化右侧面板：

1. **可拖拽调宽**：面板左缘 6px 把手，拖动实时改宽（240~700 钳制，DPI 初始化），
   hover 显示 ResizeEW 光标，拖动时自动屏蔽相机输入；视口信箱自动适配新宽度
2. **内部布局**：
   - 分组折叠保持 CollapsingHeader 惯例；材质分区内部按行业分组（基础/自发光/透射/预设）
   - 所有参数行统一"标签列 + 控件"对齐
   - 每个材质参数加 hover 工具提示（物理含义，配合 d-004 教学）
3. **字形**：工具提示新增汉字同步白名单

# 实际做了什么

1. `panelWidth_` 成员（initImGui 按 DPI 初始化 320×scale）；`computeImageRect` 用动态宽度
2. 面板左缘 8px 隐形按钮把手：`IsItemActive` 时 `panelWidth_ -= MouseDelta.x`（240~700 钳制），
   hover ResizeEW 光标 + 竖线高亮；按钮捕获鼠标 → 相机输入自动屏蔽
3. 材质分区重排：Base 基础 / Transmission 透射 / Emission 自发光 / Presets 预设 四个子组，
   标签列 110×dpi 对齐，全部参数行加 `ImGui::SetTooltip` 物理含义（中英双语）
4. 字形白名单追加工具提示汉字；harness 42/42 全命中
5. **根因修复**：追踪 depfile 失效到本源——中文版 MSVC 的 /showIncludes 输出
   "注意: 包含文件:"（cmcldeps 只认英文 "Note: including file:"），且 build.ninja
   完全没有 deps 规则 → 头文件变更静默不重编。修复：CMakeLists 给所有源文件挂
   `OBJECT_DEPENDS`（application.h/scene.h/render_backend.h），关键头变更必重编

# 验证结果

- 构建通过；**main.cpp.obj 在 application.h 变更后确认重编**（OBJECT_DEPENDS 生效，rebuilt: True）
- 字形 harness 42/42、0 缺失
- 冒烟 ×2：autotest 渲染 8s 优雅退出 exit 0；纯关窗 exit 0；无崩溃日志

## 试错记录

- ⚠️ 陈旧 TU 第三次出现（t-006 期间）→ 顺藤摸瓜找到真正根因：**中文 VS 的本地化
  /showIncludes 输出让 CMake 的 depfile 转换（cmcldeps）完全失效**，build.ninja 无任何
  deps 规则。VSLANG=1033 实测无效（语言包优先）。最终 OBJECT_DEPENDS 兜底根治
- 🔑 拖拽把手用 ImGui 隐形按钮而非 WM_MOUSEMOVE 手动处理：WantCaptureMouse 自动屏蔽相机，
  不用碰消息循环

# 背景

本地视觉引擎已就绪（llama.cpp + Qwen2.5-VL-3B, http://127.0.0.1:8080, d-013 期间
验证过判图能力）。用户要求：① 集成进工程；② UI 中可见使用方式，作为调试工具；
③ 每次运行的全部结果落本地，带时间戳与对应工程状态，方便 AI 读取分析。

# 决策

1. **零依赖原则保持**：BMP 写出器进 eval/frame_dump（24-bit 无压缩，stb_image 兼容，
   视觉引擎可直读）；HTTP 客户端用系统 WinHTTP（winhttp.lib，工程已是 Windows 专属）。
2. **UI 调试卡**（面板新增 beginCard "debug"）：提示词输入框（默认英文提示）、
   "视觉判图"按钮、引擎状态行（在线/已自动拉起/离线提示）、上次结果摘要、
   "打开结果目录"按钮（ShellExecute vision_reports/）。
3. **一键流程**：captureFrame（当前帧 BMP, 四后端各 ~15 行）→ vision::ask
   （WinHTTP POST /v1/chat/completions, base64 内联）→ 落盘报告三件套。
4. **报告协议**（vision_reports/, .gitignore 忽略但留盘供 AI 读）：
   `<YYYYMMDD_HHMMSS>_<模式名>.{bmp,md,json}`。json 含：timestamp、git_commit
   （编译期注入）、build、mode、model(场景)、params 摘要（kSpp/diSamples/frameWindow/
   svgf×2/accum/exposure/shading）、prompt、answer、engine（host+model+在线状态）、
   elapsed_ms。md 为同内容人读版。**AI 分析时先读 json**。
5. **引擎离线自动拉起**：判图前探测 /health；失败且
   C:\Users\jcm20\ollama\runtime\bin\llama-server.exe 存在 → CreateProcess 静默拉起
   （同 start_vision.bat 参数）→ 轮询健康 ≤45s → 仍失败则报告并指导运行脚本。
6. **无头验证**：`--visioncli <bmp路径> [prompt]` 走同一 vision::ask 通道打印结果，
   供回归与 AI 侧调用（自动测试不依赖 UI）。
7. **工程状态**：git hash 由 CMake configure 期 execute_process 注入编译定义
   RENDER_GIT_HASH（避免运行时 spawn git）；build 时间用 __DATE__ __TIME__。

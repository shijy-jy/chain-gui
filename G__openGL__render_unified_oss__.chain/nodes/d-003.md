# 材质系统梳理（2026-08-31 现状）

## 〇、行业参考（2026-08-31 检索结论）

### 主流渲染器材质系统的共同骨架

1. **统一"万能"材质模型（Uber/Principled BSDF）是事实标准**：源头是迪士尼 Principled BRDF（Burley 2012，11 个参数：baseColor/subsurface/metallic/specular/specularTint/roughness/anisotropic/sheen/sheenTint/clearcoat/clearcoatGloss）。各大引擎各自实现：UE5 Material、Unity HDRP Lit、Blender Principled BSDF、Filament；**交换标准是 glTF 2.0 PBR Metallic-Roughness**（baseColorFactor/metallicFactor/roughnessFactor + 贴图槽），跨工具互操作都对齐它
2. **两层设计**：材质资产（节点图/主材质，决定"怎么算"）与材质实例（参数覆写，美术日常只碰这层）。UE5：Material → Material Instance；Unity：Shader → Material；Blender：Node tree → Material
3. **每个参数都是"标量+贴图槽"合一**：贴图优先于参数（glTF 语义是 factor × texture 相乘）；行业惯例纹理打包 ORM（occlusion/roughness/metallic 合一张）
4. **GPU 侧 = 紧凑 POD 参数块 + 纹理表索引**，与几何解耦、支持热更新——本项目的 64B Material POD 正是这个形态的雏形

### 开放美术参数的材质面板设计惯例

参考 [UE5 材质实例编辑器](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-material-instance-editor-ui?application_version=5.4&lang=zh-CN)、Blender Principled、[Unity Shader Graph 参数暴露](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.4//manual/Sub-Graph-Promote-Property.html)、[Substance 动态材质分层](https://experienceleague.adobe.com/en/docs/substance-3d-painter/using/features/dynamic-material-layering)：

1. **分组折叠**：基础（BaseColor/Metallic/Roughness）→ 细节（Normal/AO）→ 自发光 → 透射 → 高级（Sheen/Clearcoat/SSS）默认折叠
2. **命名与范围标准化**：与 glTF/Disney 对齐、0-1 归一化；颜色用线性空间色板；滑条+数字框组合
3. **参数行 = 贴图槽 + 滑条**：贴图存在时参数退化为乘数
4. **实时预览**：预览球/当前模型，改参即时刷新
5. **预设材质库**：铝/金/铜/玻璃/塑料一键套用
6. **渲染器集成路径**：参数改动 = 更新 POD + 重传设备常量（毫秒级、不重建加速结构）；结构开关（isGlass/isMetal）最多重建后端；贴图 = 纹理对象注册 + 材质引用 id；脏标记按需上传；序列化用 JSON/USD

## 〇·二、名词辨析（概念分层）

三个层级，避免把不同层混为"并列选项"：

```
第一层【流派】   PBR（写实物理: 参数有物理含义/能量守恒/任何光下正确）
                 NPR（风格化: 卡通描边/色阶/水墨, 故意不物理）
第二层【公式】   BSDF（光在表面的反射+透射完整响应函数）
                 ├ BRDF（只反射的那部分, Lambert 是最简 BRDF）
                 ├ BTDF（透射部分）
                 └ BSSRDF（再含次表面散射传播, 皮肤/蜡烛）
第三层【参数套餐】 Metallic-Roughness 工作流（glTF 标准, 本工程在用）
                 Specular-Glossiness 工作流（老 Unity 二选一, 高光色可指定,
                                          易违反能量守恒, 现基本被取代）
```

面板"解析方式"即参数模型选择，主流 3+1：A=PBR Metallic-Roughness（默认，本工程已就位）；
B=PBR Specular-Glossiness；C=NPR（描边宽/色阶数/渐变带等完全不同参数集）；
D=程序化节点图（非参数面板，TD 向）。A/C 可共存于同一渲染器（切渲染风格）。
NPR 支线（卡通模式: 描边+色阶化+cel 高光）是学习渲染器的经典扩展。

## 〇·三、路线决策（2026-08-31 定案）

**采用 A+C，D 为远期选修。**

- D 的难点不在节点编辑器 UI（有 imgui-node-editor），而在"图→可执行着色代码"的编译链路：
  商业引擎靠运行时 JIT（UE5 材质图→HLSL）；本工程 CUDA 四后端要么离线 nvcc 重编（改图分钟级、
  体验差）、要么 NVRTC（复杂度高）、要么节点解释器（GPU 性能差）→ 性价比最低，先不做
- C 极其便宜：NPR 大部分是着色后处理，现成缓冲全用得上——
  描边 = depth+normal 缓冲 Sobel 边缘检测；色阶 = NdotL 量化 step；cel 高光 = Blinn 阈值化；
  ramp 渐变带 = 1D 纹理按 NdotL 采样。面板加"渲染风格"开关（PBR/Toon），四后端共用材质数据、只换着色分支
- 实施顺序：① A 材质面板 + 热更新 → ② C Toon 模式（光栅先做，PT 后处理跟进）→ ③ D 远期迷你演示（可选）

# 材质系统梳理（2026-08-31 现状）

## 一、数据模型

`include/assets/scene.h` 的 `Material`（64 字节 POD，宿主/设备共用布局，static_assert 与 raster_gpu_backend.cu 同步）：

| 字段 | 语义 |
|---|---|
| baseColor (vec3) | 反照率/金属色 |
| emission (vec3) + isEmissive | 自发光（面光源） |
| roughness / metallic | PBR 金属工作流双参数 |
| conductorEta / conductorK (vec3×2) | 导体复折射率（铝参数硬编码） |
| ior + isGlass | 电介质折射（玻璃 1.5） |
| isMetal | 导体标志（Fresnel 分支用） |

## 二、数据来源（三条路）

1. **OBJ/MTL**（`obj_loader.cpp` convertMaterial）：Kd→baseColor、Ns→roughness、metallic=0；其余字段全默认。t-002 起支持同目录 mtllib 搜索（UTF-8/宽路径）
2. **Cornell 硬编码**（`cornell_materials.cpp`）：墙体按法线分类五材质 + 铝球/玻璃球 + 顶灯，名称/法线规则驱动
3. **兜底**：无材质时灰漫反射

## 三、消费方（四后端的能力落差）

- **RasterCPU / RasterGPU**：只有 Lambert+Blinn（albedo/roughness/emissive），**完全忽略 metallic/ior/isGlass**——金属球在预览里就是"白色高光球"
- **PathTraceCPU / PathTraceGPU**：完整 BSDF——漫反射 / 导体 Fresnel（GGX）/ 玻璃折射 / 自发光面光源（buildEmissiveLights 逐三角形收集），是真正 PBR 的参考实现

## 四、当前限制（= 潜力点）

1. **无纹理**：map_Kd/map_N/normal 等全部忽略（Vertex.uv 已有、Vertex.color 从未使用——管线是现成的）
2. **MTL 解析只覆盖 Kd/Ns**：Ke 自发光、d/Tr 透射、多 material 属性丢失
3. **无运行时材质编辑**：改颜色要改代码/文件后重启
4. **用户模型无材质分类**：Cornell 的名称/法线规则只服务内置场景
5. **金属/玻璃在光栅预览不可见**（预览与路径追踪表现不一致）
6. 64B 布局是硬约束（加字段必须同步 .cu 镜像）

# 发展路线图

## P0 · 实用层（性价比最高，先做）

1. **MTL 完整解析**：Ke→emission、d/Tr、map_* 引用至少识别并打日志（纹理见 P1）
2. **运行时材质编辑器**：面板选中模型 → 调 baseColor/roughness/metallic/emission → 双后端即时重建（沿用 t-002 switchModel 的重建通道，成本低）
3. **材质库与实例化**：按名称去重引用 + 用户模型自动分类（文件名含 metal/glass 即套对应材质，Cornell 规则泛化）
4. **预览一致性**：RasterGPU 加金属/玻璃近似（GGX 高光 + 简化 Fresnel），预览不再骗人

## P1 · 渲染质量层

5. **纹理贴图管线**：albedo/normal/roughness/metallic/emission 贴图；GPU 用 CUDA 纹理对象+双线性过滤，CPU 走简单采样；顶点色（Vertex.color）同步启用
6. **环境光 IBL**：金属/玻璃需要环境可反射；先用解析天空+预滤波 cubemap，Cornell 外场景立竿见影
7. **BSDF 扩展**：各向异性（GGX+Tangent）、清漆层、透射介质（体积光）

## P2 · 工程化与前沿

8. **材质描述文件**：`models/<name>.mat.json` 声明式材质，与 .obj 解耦、可版本化
9. **材质 UI 增强**：预设库（铝/金/铜/玻璃/塑料…）、多材质实例列表、Kd 色板
10. **前沿**：多层 BSDF 叠加、次表面散射（SSS）、体积渲染、与 OptiX 降噪联动后的 Neural/纹理 BRDF

## 建议的下一步

P0-1 + P0-2 组合拳：MTL 补全 + 面板材质编辑，1-2 个任务量，立刻让"任意模型导入"体验闭环。P0-4 预览一致性紧随其后（否则金属/玻璃用户在预览里看不到效果会误以为材质没生效）。

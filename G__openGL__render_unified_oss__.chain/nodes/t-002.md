3. `application`：启动扫描 → 默认内置 Cornell；面板 Model 分区下拉切换；切换时双后端重建 + 调参回灌 + 相机自动取景
4. `CMakeLists.txt` 增源文件；README 说明文件夹位置

# 验收标准

- 编译通过（Ninja Release，四架构）

# 实际做了什么

1. 新增 `include/assets/model_library.h` + `src/assets/model_library.cpp`：
   - `scanModelFolder("models")`：内置 Cornell 排第一，扫描顶层 `*.obj`（跳过 `cornell_*`），按名排序
   - `buildModelScene()`：内置 = 三文件+墙体材质+顶灯；用户模型 = 单文件+MTL 颜色+默认灰兜底+顶灯（保证路径追踪非黑）
2. `obj_loader.cpp`：`ParseFile` 改用 `MaterialLibrary::SearchPath(绝对父目录, Load::Optional)`——Cornell 无 .mtl 行为不变，用户带材质模型能读入 diffuse 颜色
3. `application.cpp/.h`：
   - 启动：扫描模型库并加载默认条目（失败→立方体兜底，与原 createDefaultScene 行为对齐；旧函数已删除）
   - 面板新增 **Model 模型** 分区（下拉选择 + Rescan 按钮 + 网格/三角形统计），切换即生效
   - `switchModel`：重建 scene → 相机按 AABB 自动取景 → 重建预览/渲染双后端（别名安全 dispose，沿用 t-028 模式）→ 暂存调参回灌（夹取范围）→ 保持预览/渲染状态
4. `CMakeLists.txt` 增 `src/assets/model_library.cpp`；`README.md` 新增 Models 节（文件夹位置 + 用法）

# 验证结果

- **完整构建**：Ninja Release（-G 配置，四架构）编译+链接通过（exit 0），产物 `render_unified.exe` 14:54 重链接
- **独立测试 harness**（`build/verify-models/`，cl 编译，16 项断言全过）：
  - 扫描：内置第一、cornell_* 不重复列出、用户文件按名排序 ✓
  - 装配：内置 Cornell 4 网格/9 材质/2 面光源 ✓；带 MTL 的用户模型读入红色 diffuse ✓；无 MTL 走灰色兜底 ✓；顶灯保证非黑 ✓

## 试错记录

- ❌ 首轮 harness：带 .mtl 的模型颜色没读进来 → 根因是 rapidobj `FindBestPath` 对**相对**搜索路径做 `basepath/path` 拼接，拼出双份目录 → 修复：搜索路径转**绝对路径**（读 vendored 源码定位，见 rapidobj.hpp FindBestPath）
- ⚠️ MTL 的 `Load::Optional` 只影响"找不到文件是否报错"，不影响搜索目录拼接规则，别被名字误导
- 🔑 用户模型复用 Cornell 顶灯（y≈8）：任意尺度的模型路径追踪都能出图；大模型遮挡顶灯时画面偏暗属已知取舍（v1 不做环境光/自动布光）

> 触发：动态 M-cap 均衡器；帧窗口制

> 回溯修改：按 v12 指南 v11 节挂载代码骨架（code_map: src/backends/path_trace_gpu_backend.cu——动态 M-cap 落地于 DI/GI 时域复用内核，t-020）；不改变状态与结论（原 revision 2）。

# 问题（承接 d-010）

d-010 主因：固定 mcap=30 是均衡器——N=32 时每帧被硬截断且 wSum×30/62 腰斩历史，
质量受限于 cap 而非 N。本节点给出让 N 真正生效的动态 cap 设计。

# 核心思路：cap 的单位从"样本数"改为"帧数"

M-cap 的本质目的 = 控制**时间偏置**（旧样本在重投影/光照变化后过期，需要遗忘机制），
而"过期"的时间尺度是**帧**，不是样本。因此：

```
dynCap = N × F       N=每帧候选数 (kSpp/diSamples)   F=期望记忆的帧窗口 (新调参, 默认 30)
```

N=1,F=30 → cap 30（与现状一致）；N=32,F=30 → cap 960。质量随 N 线性增长，不再被硬截断卡死。
代价为零：蓄水池是定长结构（wSum+M 两个数），M 是 uint32，N×F 远够。

# 合并公式（Tier 1，最小改动）

现状（两处 merge：DI .cu 1042-1067 / GI .cu 2011-2041）：
`wSumNew = r.wSum + prev.wSum; if (mSum>cap) wSumNew *= cap/mSum` —— 线性 rescale 连新样本一起稀释。

改进（**只压缩历史，不稀释新样本**）：

```c
const uint32_t dynCap = max(N * F, N + 1u);
const uint32_t mPrev  = min(prev.M, dynCap);
const float    wPrev  = prev.wSum * (float)mPrev / max(prev.M, 1u);   // 截断只吃历史
wSumNew = r.wSum + wPrev;
M_new   = r.M + mPrev;        // r.M = 本帧 N
```

稳态推导：M → N + min(N·F, …) = N(F+1) ≈ **N×F 个有效样本**。
N=32/F=30 → ~960 样本 vs N=1/F=30 → ~30 样本，方差差 ~32 倍（预期与 d-010 实验 2 一致）。

# Tier 2：帧窗口 F 自适应（内容感知）

F 仍可"硬"，按内容变化动态调：

1. **复用相机脏信号**（t-012 已有先例）：cameraDirty_/onCameraChanged 帧把 F 压到 4~8（快速遗忘），静止回 30
2. **重投影失效率驱动**（更优雅）：统计本帧 temporal reuse 被 validity gate（深度/法线/可见性门）拒绝的像素比例 ρ，`F ← clamp(F_base·(1−ρ·k), F_min, F_max)`——遮挡/移动大 → 记忆短；静止 → 记忆长。这是 history rejection 思路的连续版
3. 面板化：F 进 kTuneParams（"ReSTIR" 组），t-017 的描述符机制现成可用

# Tier 3：与 Talbot MIS 衔接（消解 cap 本身）

完整版里 cap 语义变化：`m_prev = min(M_prev, cap)` 只是 MIS 权重分母里有效样本数的偏置钳制，
配合"历史权重按当前目标重评估"（p̂_current(x_prev)）后，硬截断的偏置来源基本消失。
Tier 1 先落地，Tier 3 与 d-010 的修复路线合流（储层需补原始 pdf 字段）。

# 实现注意

- DI/GI 两处 merge 同步改（契约习惯）；wSum 是亮度标量（restirLum），rescale 因子同为标量 ✓
- RestirReservoir/RestirGiReservoir 结构无需改（M 已是 uint32）
- 与 diGReject 巨权拒绝的关系：cap 变大后历史里大权重旧样本存留更久，diGReject 的守卫价值上升，两者不冲突
- 验证：d-010 实验矩阵 + N=32/F=30 对照 N=32/mcap=30（预期大幅拉开）

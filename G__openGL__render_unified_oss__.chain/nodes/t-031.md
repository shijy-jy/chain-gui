> 触发：对比热力图；并排图分块矩阵

# 要做什么

用户确认工作流："保留一张高帧积累静态图 → 出对比结构 + 数据分析"。补齐缺失环：

1. `eval/compare.py`：+BMP 读取（24-bit BI_RGB）+ `--heatmap <out.png>`（对数刻度
   误差热力图，纯 stdlib zlib PNG）+ `--sidebyside <out.png>`（ref/test/热力图
   三联并排）+ `--blocks N`（N×N 分块 mean_rel_err 矩阵打印与落盘）；selftest 覆盖。
2. UI 调试卡 +"对比参考图 (Compare Ref)" 按钮：C++ 内联对比（dumpFrame 当前
   累积帧 PFM → readPFM 参考 → max_abs_diff/PSNR(峰值=max(ref))/rel_err +
   8×8 分块矩阵 → 误差图 BMP + 三联并排 BMP → 报告三件套落盘 vision_reports/）。
   默认参考 = benchmarks/reference/cornell_ptcpu_ref.pfm。
3. `--comparecli <test.pfm> [ref.pfm]` 无头验证入口（同 runCompareReference 通道）。

# 备注（重要排障）

- **readPFM 读头坑（修复）**：`fread(2)` 只吃掉 "PF" 两字节，"PF\n" 首行的余行
  就是 "\n"——旧 fscanf 版靠跳过空白掩盖；改用 fgets 按行读后必须先吃掉魔法行
  余行再读尺寸行，否则首行解析失败（errno=0、文件字节完全正确 → 极具迷惑性）。
  同修 readPPM。独立 console 测试 + 逐字节诊断才定位。
- 旧 fscanf("%f\n") 的尾随空白还会吞数据流首字节（首像素低字节恰为 0x0A 时
  读头错位）——两害相权取 fgets + 显式跳行。
- 三联并排图 = ref|test|heat (3840×720)，误差热力图对数刻度蓝→红→白。

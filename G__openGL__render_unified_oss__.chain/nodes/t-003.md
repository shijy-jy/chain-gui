> 触发：堆栈溢出崩溃；中文乱码修复

# 要做什么

用户加载模型后 `render_unified.exe` 崩溃（堆栈 Cookie 检测/GS 报错），且中文文件名乱码。

# 排查方向

1. 全局 grep 栈上定长缓冲 + 不安全写入
2. 文件名编码（GBK vs UTF-8）
3. 用真实模型复现

# 最终根因（外部调试器 + 硬件写监视点实证）

**崩溃与模型完全无关，是"关窗时"的确定性崩溃**，根因是**两个编译单元对 `Application` 类布局的视图不一致（ODR 违例）**：

- `main.cpp.obj` 陈旧（用旧版 application.h 编译，sizeof(Application)=0x180）
- `application.cpp` 用新版头编译（sizeof=0x190）
- Application 构造函数零初始化 `uiPending_[16]` 时按 0x190 写，越出 WinMain 为它留的 0x180 帧空间 → **写穿栈 Cookie**（Cookie 槽 = WinMain 帧 rsp+0x190，x64 存储值为 `__security_cookie ^ rsp`）
- Cookie 检查只在 WinMain 返回时执行 → 关窗时才报 /GS → 退出码 0xC0000409

实证链（全部实测）：
- minidebugger 抓到崩溃栈：`__report_gsfailure ← WinMain+0x72`
- int3 打点 WinMain 序言后 + DR0 写监视 Cookie 槽 → 命中写者 `Application::Application+0x12A`（即 `movups [rbx+16Ch],xmm0`，uiPending_ 第 13-16 个 float 的清零）
- dumpbin 反汇编 WinMain：`sub rsp,1A0h` + `lea rcx,[rsp+20h]` + Cookie 在 `[rsp+190h]` → 帧只够 0x180 的对象
- 我做的两个**全量**构建（verify-g/verify-nodebug）关窗三连测全部干净退出 → 全量重编即治愈

**修复 = 全量重建**（删除 CMake 缓存 + 重编所有 TU）。已清掉用户 VS 构建目录的缓存并重编全部 31 个目标文件；链接被 VS 里挂起的调试进程锁住，用户停止调试后重新生成即可。

# 已完成的附带修复（防同类栈越界，均已验证）

1. 中文文件名乱码：model_library 宽字符转 UTF-8 + obj_loader u8path（harness 22/22 断言全过）
2. BVH 树深上限 32→31 + 遍历栈守卫 + NaN 分桶防线 + OBJ 负索引钳制（复现程序全过）
3. 新增 `crash_diag.cpp`：自定义 `__report_gsfailure` + UEH，崩溃时写符号化 crash_gs.log/crash.log
4. 新增 `--autotest [mode] [secs]` 无头冒烟模式

# 试错记录

- ❌ 假设1（深树压栈越界，bvh）：合成深树不触发，实证证伪（SAH 对合成排列生成平衡树）
- ❌ 假设2（NaN 分桶越界，bvh）：NaN 被 min/max 静默吸收、转 size_t 恰好回绕到桶 0，不崩溃，实证证伪
- ❌ 假设3（-G 设备调试差异）：OFF/ON 全量构建都干净，证伪——差异不在设备代码
- 🔑 关键转折：崩溃栈显示 `__report_gsfailure ← WinMain` → Cookie 属于 WinMain 帧 → 反汇编 + int3/DR0 写监视点锁定写者为 Application 构造函数 → 帧大小与对象大小对不上 = 陈旧 TU
- ⚠️ 调试工具自坑：硬件执行断点（DR exec）在初始断点上下文不触发，改用 int3 软件断点；`EXCEPTION_DEBUG_INFO` 不带 ContextRecord，需自行 GetThreadContext；`ReadProcessMemory` 跨页大块读会整体失败，需逐页
- 📌 工具留档：build/verify-models/ 下 minidebugger.c、cookiewatch.c、watch3.c、probe.c、lookup.c + 复现脚本（gitignored）

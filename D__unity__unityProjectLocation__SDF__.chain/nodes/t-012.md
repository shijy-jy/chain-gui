# 任务：shader 家族命名整理 + 贴图模式普及

## 需求原文
「整理现有 shader 的命名，清晰一些」→ 追加「已有的 shader 使用噪声的逻辑变为在 inspector 面板使用我给的噪声贴图」→ 追加「正方体采样 3D 噪声贴图」

## 一、命名整理（平台-特性规则）
| 旧名 | 新名 | Shader 菜单名 |
|---|---|---|
| `L17_Dissolve.shader` | `L17_Dissolve_2D.shader` | SDF/L17_Dissolve_2D |
| `L17_Dissolve_DomainWarp.shader` | `L17_Dissolve_2D_DomainWarp.shader` | ..._2D_DomainWarp |
| `L17_Dissolve_Sparks.shader` | `L17_Dissolve_2D_Sparks.shader` | ..._2D_Sparks |
| `L17_Dissolve_AudioBeat.shader` | `L17_Dissolve_2D_AudioBeat.shader` | ..._2D_AudioBeat |
| `L17_Dissolve_Ignition.shader` | `L17_Dissolve_2D_Ignition.shader` | ..._2D_Ignition |
| `L17_Dissolve_3D.shader` | 不变 | SDF/L17_Dissolve_3D（旗舰） |
| `L18_Dissolve3D.shader` | 不变 | 用户课程版（NoiseLib） |

**规则**：`L17_*` = 功能演进线（平台 2D/3D + 特性后缀）；`L18_*` = 用户课程线。
**关键安全操作**：改名时**文件与 .meta 成对移动，GUID 原样保留** → 现有材质引用（正方体溶解.mat / 起点溶解.mat）不断链。

## 二、贴图模式普及（5 个 shader 统一改造）
统一加入两属性 + 双模式分支：
```hlsl
[Toggle] _UseNoiseTex ("使用噪声贴图 (关=程序化)", Float) = 0.0
_NoiseTex ("噪声贴图 (R 通道)", 2D)  = "white" {}      // 2D 版
_NoiseTex3D ("3D 噪声贴图 (R 通道)", 3D) = "white" {}   // 3D 版

if (_UseNoiseTex > 0.5)
    n = SAMPLE_TEXTURE2D(_NoiseTex, sampler_NoiseTex, p).r;   // 贴图模式
else
    n = 0.5 + 0.7071 * perlin2D(p);                            // 程序化兜底
```
- **双模式兜底设计**：缺资产不崩，默认关（= 行为不变）
- 3D 版在 `_UseNoiseTex` 下按用户要求改为**直接采样 Texture3D**（正方体专用，见 t-013）

## 三、参数语义变更（须告知用户）
`_NoiseScale` 从"UV 频率"变为"**倍率**"——贴图模式下 `1` = 整张贴图铺满 UV 0~1（即烘焙时设定的频率直接呈现）

## 试错记录
- ⚠️ **材质引用安全验证**：改名后必须核对材质引用的 GUID 是否仍指向正确 shader——本项目两个材质 GUID 分别为 a100...17（L17_Dissolve_2D）与 332909c1...（L17_Dissolve_2D_DomainWarp），改名后核对均正确。
- ⚠️ **UNITY 第三方会话中修改文件的时序坑**：本轮多次遇到"文件在读取后被外部改动"（Unity 重导入 / 用户手动编辑）导致 edit 失败——须重新读取再改。表现为 `file changed since it was read`。
- 🔑 **参数语义变更的连带效应**：`_EdgeWarp`（值域→空间域）、`_NoiseScale`（频率→倍率）两次语义变更都要求用户手动改材质旧值，否则"改了跟没改一样"——这是 shader 迭代中最易被忽视的环节。

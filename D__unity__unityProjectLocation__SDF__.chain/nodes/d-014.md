# 模块化重构评审与整理优化路线

自验收：评审节点（无执行改动；补档见 t-050/v-033）。

## 评审结论：质量高，架构落地符合 d-013
- Director 543 行只做"状态机+核心闭环"，5 模块独立文件、黑板单向数据流、
  solo/weight/tier 语义正确；行为对齐经静态逐段核对（见 v-033）
- 场景零改动（调参字段留 Director）——聪明的兼容取舍
- 唯一必须用户执行的动作：**Unity 资产刷新 + Game 视图 A/B 回归确认**

## 发现的问题（按优先级整理优化路线）
### P0 立即（零风险，等并行会话让出文件后做）
1. **链补档完成**: t-050/v-033（本节点执行 ✓）
2. **d-003 架构轨更新**: 挂载 Modules/*.cs 骨架 + 架构图加模块层

### P1 代码卫生（小改，等 Director 稳定后）
3. `frameSeed` → [System.NonSerialized]（面板噪声；运行时自增字段不该序列化）
4. `FXContext.phaseT` 实为已耗时秒 → 更名 phaseElapsed 或注释澄清
5. **enableX 主从语义**: Director.Init 每次用 enableX 覆写模块 enabled →
   模块面板开关只在运行期有效。建议: 模块 enabled 优先、enableX 降级为
   "首次迁移提示" 或直接移除（二者等价易误用）
6. Orb 模块 `_CrownStrength × weight` 只在 Init 计算一次 → 运行期改 weight
   不影响火焰冠（与 weight 语义不一致, 移入 UpdateFX）

### P2 架构收尾（d-013 遗留, 各自开 task）
7. **S5 暖光模块化**: warm light 抽成 L17Mod_WarmLight (持 targetRenderer
   引用), 场景值迁移 (warmLightStrength=1/Radius=2.5 ≈ 默认, 成本低)
8. **调参下沉模块**: 各层调优字段从 Director 移入对应模块 (面板=模块折叠
   内自带参数; Director 只剩 引用+时序+模块管理). 注意跨类字段移动的
   场景序列化迁移 (逐项对照, 值≈默认)
9. **可选 S6**: 调试面板抽模块 (低价值, 视需要)

### 不做的
- 不改模块执行顺序 (无顺序依赖: orbPos 由 Director 先算, 模块只读黑板)
- 不抽 Ember/Orb 的宿主参数 (粒子/球与状态机强耦合, 属核心闭环)

## 验证链
- Unity 刷新编译 → Game 视图 A/B 回归 → P1/P2 每项独立 task+v 闭环

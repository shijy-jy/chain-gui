## 需求原文

## 一、tx 素材分析（15 张原始素材）

用 `System.Drawing` 降采样成字符亮度图逐张分析（避免直接读 4096² 大图）。

| 文件 | 尺寸 | 实测特征 | 建议用途 |
|---|---|---|---|
| `vfx_fire_core` | 4096² | 圆形分布，**中心白热核(峰值 @)**，向外平滑衰减 | 火球主体（现用） |
| `vfx_fire_band` | 6240×2656 | **左端极亮(@@@@@)、向右衰减**的横向火流 | UV 单向滚动条带 / 火焰冠 / 旋臂 |
| `vfx_fire_ember` | 4096² | 很小的十字星芒（中心 `%*`，四周空白） | 火星粒子 |
| `vfx_fire_distort` | 4096² | 湍流噪声，**无明显中心、明暗斑驳** | 扰动/扭曲（**当前完全未使用**） |
| `vfx_fire_smoke_1/2/3` | 4096² | 灰度烟雾团，有内部结构 | 烟层（**当前完全未使用**） |
| `vfx_fire` | 4096² | 综合火图，中心亮核 + 火舌 | 备选主体 |
| `vfx_dark_v2` | 4096² | 低亮度暗元素图 | 其他元素 |
| `vfx_ice` / `water` / `lightning` / `poison` / `psychic` / `grass` | 4096² | 各元素主图，均为「中心亮核 + 特征纹路」 | 未来多元素扩展 |

**三条对优化有直接价值的结论**：
1. `vfx_fire_core` 中心是**纯白热核** —— 这正是过曝的物理来源（见下）
2. `vfx_fire_distort` 是**现成的湍流噪声图**，而 shader 目前用程序化 `perlin2D` 做扰动
   → 可换成贴图采样，更省且纹理更自然
3. `vfx_fire_band` 的左亮右暗特征，天生适合做单向流动（火焰冠/旋臂）

## 二、根因诊断：全白过曝（不是贴图丢失）

先排除了"贴图丢失"：材质 `L17_FireCoreMat.mat` 的 `_MainTex` GUID 指向
`T_Fire_Core.jpg`，**赋值正常**。

真因是**着色过曝**——四层叠加相乘：

| 层 | 贡献（球心处） |
|---|---|
| ① 贴图原色 `fire.rgb * edgeFade` | `T_Fire_Core` 中心本身 ≈ (1,1,1) → **1.0** |
| ② `+ _CoreColor * core * (0.5+fire.r)` | **+1.5** |
| ③ `+ _HaloColor * halo * 0.6` | **+0.6** |
| ④ `× _Boost(=3, 材质实际值)` | 合计 **≈9.3** |
| ⑤ 批次6 新加的 `_RimStrength=0.6` | 边缘黄环（**本轮引入的回归**） |

Bloom 阈值 1.0 → 9.3 被全量爆开 → 中心糊成全白，边缘只剩 `_RimStrength` 的黄环。

## 三、优化：贴图定形状 / 色带定颜色 / 只在最热处提 HDR

### 新逻辑（`L17_FireCore.shader`）
```hlsl
// 热度 = 贴图 RGB 最大值 × 边缘淡出 × 呼吸
// (不用亮度加权: 火焰的橙红通道值高, 加权会低估热度)
float heat = max(fire.r, max(fire.g, fire.b)) * edgeFade * pulse;

// 色带: 暗红 → 橙红 → 亮橙 → 白热 (黑体辐射观感, 层次全由 heat 驱动)
half3 col = _FlameDeep.rgb;
col = lerp(col, _FlameWarm.rgb,  smoothstep(0.00, 0.35, heat));
col = lerp(col, _FlameHot.rgb,   smoothstep(0.35, 0.70, heat));
col = lerp(col, _FlameWhite.rgb, smoothstep(0.70, 1.00, heat));

col += _HaloColor.rgb * halo * _HaloStrength * pulse;   // 外圈光晕(独立柔和)

// HDR 分级: 只在最热处提升 → 中心爆 Bloom, 中低亮区保持颜色层次
float hdr = lerp(1.0, _Boost, saturate(heat * 1.2));
col *= hdr * _Appear;
```

### 关键变化

| 项 | 改前 | 改后 |
|---|---|---|
| 颜色来源 | 贴图原色 + 内核实心 + 光晕（三层相加） | **色带映射**（heat 驱动，单一路径） |
| "内核实心"层 | `_CoreColor * core` 叠加 | **删除**（贴图已有核，再叠就是过曝元凶） |
| HDR | `col *= _Boost`（全局 ×3） | **分级**：`lerp(1, _Boost, heat*1.2)` |
| `_Boost` | 3（材质实际值） | **1.6**（shader 默认 + 材质文件同步改） |
| `_RimStrength` | 0.6 | **0.25** |
| `edgeFade` | `smoothstep(0.55, 0.95)` | `smoothstep(0.62, 0.98)`（边缘收得更早） |

新增属性：`_FlameDeep/_FlameWarm/_FlameHot/_FlameWhite`（4 档色带）+ `_HaloStrength`。
`_CoreColor` 保留但改作"边缘强化/火焰冠着色"用。

### 顺带修正
- **材质文件必须同步改**：`_Boost: 3 → 1.6`（shader 默认值**不会**覆盖已有材质，
  这是本轮早前 `_StretchMax` 同样的坑，这次直接改了 `.mat`）
- 材质已备份 `L17_FireCoreMat.mat.bak.20260914`

## 试错记录

- 🔑 **诊断顺序修正**：一开始怀疑"贴图丢失"，先查材质 GUID 才排除。
  正确顺序：**先确认贴图赋值 → 再算亮度量级 → 最后才怀疑别的**
- ⚠️ **`_Boost` 是材质的实际值，不是 shader 默认值**：只改 shader 默认值对已有材质无效。
  凡涉及"默认值调整"，都要检查材质文件是否需要同步改
- ⚠️ **P1-7 的 `_RimStrength=0.6` 是本次过曝的次要成因**：新加的效果层默认值偏激进，
  在原有已过曝的基础上又添了一层。**新增叠加层时默认值应保守（0 或很小）**

## 四、二次修复：方形边界暴露（用户反馈）

**现象**：过曝修复后火球有层次了，但**整个 quad 是方形**，球外围圈浅橙色"无效区域"很明显。

**两个根因**（都是本轮优化引入/遗留的）：

| 根因 | 说明 |
|---|---|
| ① 色带起点取了 `_FlameDeep`（暗红） | `heat = 0` 处（贴图透明区）输出暗红而非黑 → 方形区域被涂上暗红 |
| ② `halo = exp(-d²·2.5)` 衰减太慢 | d=1.0 时仍有 0.082，光晕铺满整个方形；且原先**未做任何范围限制** |

**修复**：
1. 色带起点改为**纯黑**，用阈值控制：`lerp(black, _FlameDeep, smoothstep(0.05, 0.25, heat))`
   → `heat < 0.05` 完全不发光
2. 光晕加 `haloMask = 1 - smoothstep(0.55, 0.95, d)`，限制在圆内
3. 新增 `_CircleFade`（默认 0.88）+ 末尾统一圆形裁剪：
   ```hlsl
   float circle = 1.0 - smoothstep(_CircleFade, _CircleFade + 0.14, d);
   col *= circle;  a *= circle;
   ```
   - 放在 `HDR` 之后、`return` 之前 → 同时裁掉火焰冠/边缘强化等所有叠加层
   - `d = 1.0` 是贴图内切圆；实测火球本体直径约 **0.7**，故从 0.88 起淡出不伤本体

**可调**：`_CircleFade` 调小 = 圆更小更紧；调大接近 1.0 = 更接近贴图内切圆。

**为什么不用圆形 mesh 代替 quad**：billboard quad 在 shader 里裁剪更灵活，
换 mesh 需要重新算 `_Scale` 与角点映射，收益不值当。

**校验**：28 个属性全部声明；`core` 残留检测为脚本正则大小写不敏感误匹配 `_CoreColor`，
人工复查 frag 确认无残留。

# 根目标：完成系列 shader 特效开发与实现过程记录

## 为什么存在
SDF（Unity 2022.3.62f1c1）工程需要开发若干个 shader 特效，具体效果由用户在对话中**逐一指定**。每个效果的实现过程（设计 → 实现 → 验证 → 试错）按 chain 协议在本图谱中记录。工作区模式：analysis。

## 原则清单（刚性 / 弹性 / 边界）
- **刚性**：
  - 效果范围由用户指定，不擅自扩大
  - 每个 task 完成必须验收闭环（挂 v-* 验收节点，或正文注明自验收）
  - 实现过程真实记录：不伪造结果、失败留痕、试错记录（§4.7）
  - 遵守用户 GPU 编程安全守则：访问前边界检查、避免死循环、避免长时间计算引发 TDR
- **弹性**：渲染管线（Built-in/URP）、ShaderLab/HLSL 写法、实现路径与参考来源，在原则内按工程现状与效果需求择优
- **边界**：不越界改动与当前效果无关的代码；不做用户未要求的功能扩展

## 约束与环境
- Unity 2022.3.62f1c1，工程根：D:\unity\unityProjectLocation\SDF
- 本机网络：GitHub/Gitee 不可达——查资料优先用本地已有代码、Unity 内置 shader 源码（内置 CGIncludes）与 pip 可达渠道
- 每个效果指定后：视复杂度决定是否先建 design 节点，再建 task 节点执行

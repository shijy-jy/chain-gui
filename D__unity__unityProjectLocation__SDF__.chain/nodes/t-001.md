# 任务：实现平面溶解效果（简陋版）

## 需求原文
「尝试制作一个溶解效果，挂载在一个平面上，使用数值和一阶导数都连续的噪声函数，先做一个简陋版」

## 技术决策（噪声选型）
候选方案对比：
- **A. 复用 SDFLib.cginc 的 noise21**（smoothstep 插值值噪声）：$w(t)=3t^2-2t^3$ 端点 $w'=0$，格点处一阶导连续，**恰好满足 C¹**。缺点：二阶导不连续，值噪声格点取值随机，有轻微块状感。
- **B. Perlin 梯度噪声（选定）**：quintic fade $w(t)=6t^5-15t^4+10t^3$，满足 $w(0)=0,\ w(1)=1,\ w'(0)=w'(1)=0,\ w''(0)=w''(1)=0$，格点处噪声值、一阶导、二阶导均连续（**C²，超额满足 C¹**）；梯度噪声无块状伪影，视觉更平滑。
- 依据：Perlin, K. "Improving Noise" (SIGGRAPH 2002) —— quintic fade 就是为修复老版 smoothstep Perlin 的二阶导断裂而提出。Ken Perlin 原始实现为参考实现。

## 实现要点
- URP 14 物体表面材质 shader（区别于 L01-L16 的全屏 raymarching 路径）：`RenderPipeline=UniversalPipeline`，`Queue=Geometry`，正常 ZWrite
- 2D Perlin：`hash21`（复用 SDFLib.cginc 的 iq 风格 hash）生成格点梯度角 → 四格点梯度点积 → quintic fade 双线性插值；值域 ≈ ±0.707，归一到 [0,1]
- 溶解：`n - progress` 作 dissolveMask，`clip()` 丢弃已溶解区；`1-smoothstep(0, edgeWidth, d)` 提取阈值窄带边缘 → 边缘灼烧色
- 极简 lambert + ambient 让平面有体积感（unlit 会让平面死板）
- Properties 包 `CBUFFER_START(UnityPerMaterial)` 保 SRP Batcher 兼容
- 采样域：UV × _NoiseScale（平面 UV [0,1]）

## GPU 安全守则自查（用户既定规范）
1. 无循环（perlin 无迭代）✅ 2. 无 while(true) ✅ 3. 无显存管理问题 ✅ 4. 单片元单次噪声评估，无 TDR 风险 ✅ 5. 无数组越界（无数组访问）✅

1. shader 导入编译无错误（Editor.log 验证）
2. 材质挂 Plane，_DissolveProgress 0→1 时平面按噪声图样逐渐溶解至全消

4. 简陋版边界：单频噪声（无 FBM）、无贴图、无粒子、无 mask texture

## 试错记录
- ❌ **quintic 初版公式错误**：写成 `t*t*t*t*(t*(t*6-15)+10)` = $6t^6-15t^5+10t^4$（多乘一个 $t$），导致 $w'(1)=1\neq0$，恰恰破坏 C¹ 连续性——静态自查时发现（对照 $w(t)=t^3(6t^2-15t+10)$ 标准因子化），已修复。教训：数学公式转代码后必须逐因子复核端点导数。
- ⚠️ **GUID 覆盖事件**：shader 先被 Unity 自动导入（自动 GUID 2984b07b...），随后按工程惯例覆盖 .meta 为 a100...17。Unity 下次刷新以新 GUID 重映射；旧 GUID 无任何资产引用，.mat 正确引用新 GUID，安全（v-001 验证材质关联成功，重映射生效）。
- ⚠️ **Unity Tools 接入时序坑（最终成功）**：Unity Tools 为 CLI 内置 TCP 直连（非 MCP），注册条件 = CLI 后端（codely-binary）启动时 bridge 可用。实测踩坑链：① 仅重启 TUI 前端无效（工具集固化在 binary）——须 `taskkill /IM codely-binary.exe /F` 后 `codely --continue`；② bridge 包 1.0.80→1.0.81 自动更新期间 `.com-unity-codely.json` 卡死（unity_port=-1, reason=package_updating，心跳停滞），CLI 重启恰好撞上该窗口 → Unity Tools 未注册而其他工具（TJGenerators/engram MCP）正常注入；③ 解法：`Get-NetTCPConnection -OwningProcess <UnityPID> -State Listen` 找回实际新端口 61247，手工修复配置文件（unity_port/ready），再 taskkill+重启 → **77 工具注入成功**。
- 🔑 **关键转折**：放弃"用户手动挂载"路线的前提是工具注入成功——这次配置修复后的重启一次到位。

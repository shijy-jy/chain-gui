# 模块化状态机重构 — 详细执行文档

自验收：设计/规划文档（无执行改动）。执行由 S1~S6 各开 task 落实。

## 1. 目标与原则
- **目标**: 六阶段状态机独立成可观察核心; 表现模块拆成独立组件, 各自优化/开关/管理;
  降低双会话同文件冲突; 面板按模块分组。
- **原则**:
  1. 核心闭环不可拆: 状态机 + GPU 粒子管线 + 元素球 (吸收数驱动增长、位置=场心, 互为因果)
  2. 单向数据流: 模块只读核心状态, 不写回
  3. 每步独立验收可回退 (编译零错误 + A/B 观感一致)
  4. 场景序列化值迁移保护 (备份 + 对照表)
  5. 与并行会话批次协调 (其批次 settle 前只做 S1)

## 4. 状态机详细设计
### 4.1 枚举与数据
```csharp
public enum L17Phase { Cube = 0, Burn, Collect, Coalesce, Hold, Respawn }
public L17Phase Phase;        public float PhaseT;      // 阶段内进度 0..1
public float PhaseElapsed;    public event Action<L17Phase> PhaseEntered;
```
### 4.2 转换表 (条件 → 动作)
| 转换 | 条件 | Enter 动作 |
|---|---|---|
| Cube→Burn | elapsed ≥ idleDuration | — |
| Burn→Collect | progress ≥ 1 | — |
| Collect→Coalesce | elapsed ≥ vortexDuration | 快照 m_OrbLandY=m_OrbY; m_CoalesceStartCount=max(1,存活数) |
| Coalesce→Hold | 存活==0 或 elapsed≥3×coalesceDuration | — |
| Hold→Respawn | enableBurst && elapsed ≥ holdDuration | — |
| Respawn→Cube | elapsed ≥ respawnDuration | ClearParticles + 立方体恢复 scale |
### 4.3 每帧 Tick
- 状态机: 推进 elapsed → 按表转换 (fire PhaseEntered) → 更新 PhaseT
- 派生值 (每帧算, 模块只读): BurnProgress / CoalesceStrength / OrbWorldPos /
  OrbScale / OrbAppear / AbsorbedFrac / AliveParticles
- 阶段内职责不变 (case 1 发射量, case 2 动线, case 3 增长, case 4 发亮…)

## 5. 模块接口契约
核心只读属性 (全部 private set):
```csharp
L17Phase Phase; float PhaseT, PhaseElapsed, BurnProgress, CoalesceStrength,
          OrbScale, OrbAppear, AbsorbedFrac;
Vector3 OrbWorldPos;  uint AliveParticles;
event Action<L17Phase> PhaseEntered;
```
模块规范模板:
```csharp
[RequireComponent(typeof(L17_EmberVortexFX))]
public class L17_XxxModule : MonoBehaviour {
    [Header("...")] /* 本模块全部参数 */ ...
    L17_EmberVortexFX m_Core; GameObject m_GO; Material m_Mat;
    void OnEnable()  { m_Core = GetComponent<...>(); m_Core.PhaseEntered += OnPhase; Create(); }
    void OnDisable() { m_Core.PhaseEntered -= OnPhase; Release(); }
    void LateUpdate() { if (!m_Core) return; /* 读核心状态驱动 */ }
}
```
- LateUpdate 读核心 (核心 Update 同帧先算完) → 无需 DefaultExecutionOrder
- 禁止写核心状态; 空引用全程防护 (核心可被禁用)

## 7. 场景序列化迁移方案
- 新组件字段名与旧一致 (便于对照), Unity 不自动跨组件迁移 → 人工/默认值填
- 流程: 备份场景 → 加新组件 → 按旧组件面板值逐项填 → 删除核心旧字段 (旧序列化自动丢弃)
- 当前值 ≈ 默认值 (如 smokeStrength=1, groundGlowRadius=3.5, warmLightStrength=1),
  提供默认值对照表; 用户调过的参数以 Inspector 旧值为准

## 9. 风险与缓解
| 风险 | 概率 | 缓解 |
|---|---|---|
| 并行会话执行期改核心 | 高 | S0 协调 + 每步前重读 + 分文件 |
| 场景参数值丢失 | 中 | 备份 + 对照表 + 每步 task 记录迁移值 |
| 模块初始化顺序 | 低 | 模块 OnEnable 空引用防护 + LateUpdate 延迟读 |
| 事件订阅泄漏 | 低 | OnEnable/OnDisable 严格配对 |
